## 2. 性能

| 指标 | 实测 | 手册要求 | 结果 |
|---|---|---|---|
| 整步 `LayoutCount` 差值 | **2** | ≤1 | **未达** |
| 动画阶段（80ms → 680ms）`LayoutCount` 差值 | 1 | — | 含动画结束与 500ms 清理 |
| >20ms 长帧 | **0** | 无 | 通过 |
| 合成层数 | **4** | ≤4 | 通过 |
| Canvas 层 | 0 | — | 通过 |

拆分布局来源（独立探针）：

| 场景 | `LayoutCount` 差值 |
|---|---|
| 正常 SubBytes（值 + 动画） | 2 |
| 注入 `animation: none`（只更新值） | 1 |
| 只加动画、不写值 | 1 |
| 先加动画、再写值 | 2 |

结论：整步 2 次 = **值写入 1 次 + 动画对象创建 1 次**。动画运行期间没有 >20ms 长帧，合成层 4；但手册验收 2 的“整步 Layout ≤1”未满足。

尝试过的方案与结果：

| 方案 | `LayoutDelta` |
|---|---|
| CSS `@keyframes` + class | 2 |
| CSS 交替动画名（a/b） | 2 |
| CSS + 强制 `offsetWidth` 重启 | 2 |
| WAAPI + 单次创建 | 2 |
| WAAPI + 双 rAF + will-change | 2 |
| WAAPI 预创建暂停动画 | 6（更差，已回退） |

当前采用：**WAAPI 单次创建 16 个 transform 动画**，时长 60ms，列优先 20ms/列 delay，`fill: both`，500ms 后取消。

## 3. 关闭 SubBytes 动效后其他操作

设置 `document.documentElement.dataset.motion = 'reduced'`：

| 步骤 | `op` | running animations | 值更新 |
|---|---|---|---|
| 第 1 轮 SubBytes | `sub_bytes` | 0 | 正常（63 CA B7 04…） |
| 第 1 轮 ShiftRows | `shift_rows` | 0 | 正常（63 53 E0 8C…） |
| 第 1 轮 MixColumns | `mix_columns` | 0 | 正常 |
| 第 1 轮 AddRoundKey | `add_round_key` | 0 | 正常 |

关闭 SubBytes 后，其他三种操作仍按静态换值正常工作，说明四条通道互不依赖。

## 4. 通道特征

SubBytes 采用“点状、逐格、吸收”：

| 参数 | 实现 |
|---|---|
| 每格动画 | `scaleY(0.94 → 1)` |
| 单格时长 | 60ms |
| 缓动 | `cubic-bezier(0.16, 1, 0.30, 1)`（`--e-out-quart`） |
| stagger | 列优先 20ms/列：c0 0ms、c1 20ms、c2 40ms、c3 60ms |
| 动画属性 | 只改 `transform` |
| 触发 | `op === 'sub_bytes'` |

> 手册 F8 写“scaleY 0→1”，视觉规范 §5.3 与前端规格 M6 写 `0.94→1`。按 M6 实现 0.94→1，避免格子整块消失。
> 手册 F8 的“列优先 20ms stagger”与视觉 §5.3“20ms/格”不一致；按前端规格 M6 的“20ms/列”实现。

其他三种操作本轮没有动效；四种通道并列对比留到 F11。
