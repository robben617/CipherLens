## 2. 时间线实测

| 时刻 | `is-add-round` 格数 | 密钥层 opacity | 格子底色 | 第 1 格值 |
|---|---|---|---|---|
| 点击前 | 0 | 0 | 透明 | `00` |
| 30ms | 16 | 0.166 | 透明 | `00` |
| 150ms | 16 | **0.6** | 石墨 3.1% 过渡中 | `00` |
| ~300ms（含截图耗时） | 16 | 0.317 | 石墨 6% | `00`（新值） |
| ~600ms | 0 | 0 | 透明 | `00`（新值） |

时间线设计（总 480ms）：

| 区间 | 动作 |
|---|---|
| 0–120ms | 密钥层 `opacity 0 → 0.6` |
| 120–280ms | 底色纸 → 石墨 6%，斜纹进入 |
| 280–360ms | 数值 `steps(4, end)` 80ms 离散跳变 |
| 360–480ms | 密钥层 `0.6 → 0` |
| 480ms | 移除 `is-add-round`，恢复 idle |

> 采样时间因截图耗时比标称时间晚约 100ms；300ms 那一行的密钥层 0.317 实际已进入 360–480ms 的淡出段。时间线本身由 CSS keyframes 固定，不受采样偏移影响。

## 3. 密钥层

初始 AddRoundKey 的密钥 = `000102030405060708090a0b0c0d0e0f`。

实测 16 个 `.c-byte__key` 按 AES 索引排序：

```text
00 01 02 03 04 05 06 07 08 09 0A 0B 0C 0D 0E 0F
```

150ms 时 16 格密钥层 opacity 全部为 0.6；600ms 清零。

## 4. 数值离散跳变

- 第 1 格在 300ms 后变为 `00`（初始 AddRoundKey 后），整套值更新为 `00 10 20 30 40 50 60 70 80 90 A0 B0 C0 D0 E0 F0`。
- 数值动画为 80ms `steps(4, end)`，只改 `transform` 与 `opacity`，不是平滑滚动。
- **修复记录**：首版 `animation-fill-mode: both` 导致 280ms 前的 backwards fill 把数值 opacity 压到 0.35；改为 `forwards` 后，延迟前数值保持 `opacity: 1`，复测通过。

## 5. 通道特征与四通道并列

AddRoundKey 的通道是“叠加层 + 离散跳变”：

| 操作 | 截图 | 通道 |
|---|---|---|
| SubBytes | `F8-subbytes-mid.png` | 点状逐格 scaleY |
| ShiftRows | `F9-shiftrows-mid.png` | 整行横向位移 |
| MixColumns | `F10-mix-mid.png` | 整列同步 + 竖向扫描 |
| AddRoundKey | `F11-addround-mid.png` | 密钥叠加层 + 数值 steps |

四张截图均可在 `evidence/acceptance/` 下并排查看；四种通道没有重复的承载层。

## 7. 关闭 AddRoundKey 动效后其他操作

`document.documentElement.dataset.motion = 'reduced'` 时，`playAddRoundKey` 直接 `write(values)`，不创建密钥层/底色/数值动画。F9 的 reduced 探针第 5 步已覆盖 `add_round_key`：running animations 0、值正常。
