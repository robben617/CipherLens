## 1. 全对

```json
{"summary":{"total_bytes":16,"wrong_count":0},"first_diff":null,"propagated":[],"input_mismatch":null,"expected_ciphertext":"69c4e0d86a7b0430d8cdb78070b4c55a"}
```

`first_diff` 为 `null`，不进入错误分支。

## 2. 单字节错

C.1 密文 `69c4e0d86a7b0430d8cdb78070b4c55a`，把第 7 字节 `0x30` 改成 `0x31`：

```json
{
  "summary": {"total_bytes": 16, "wrong_count": 1},
  "first_diff": {
    "step_index": 39,
    "round": 10,
    "step": "add_round_key",
    "byte_index": 7,
    "expected": 48,
    "actual": 49
  },
  "propagated": [8, 9, 10, 11, 12, 13, 14, 15],
  "input_mismatch": null,
  "expected_ciphertext": "69c4e0d86a7b0430d8cdb78070b4c55a"
}
```

`first_diff` 只有 1 个 `byte_index`，没有第二个错误格。

### propagated 手算对照

- 首个差异下标 = 7；
- 其后的字节下标 = 8,9,10,11,12,13,14,15；
- 长度 = **8**，与 §11.4 示例的 `propagated: [8..15]` 完全一致。

> 口径说明：请求只有最终密文，没有学生中间态。因此本实现把 `propagated` 定义为“首个差异字节之后的下标”，并把这个可观测口径写进 `quiz_service.py` 注释。`first_diff` 的轮/步也只能定位到最终 `add_round_key`（step 39 / round 10），无法从最终密文反推更早的出错轮次。

## 3. 输入非法字符

明文第 6 个字符 `G`（0-based）：

```json
{"summary":{"total_bytes":0,"wrong_count":0},"first_diff":null,"propagated":[],"input_mismatch":{"field":"plaintext","char_index":6,"expected":"hex"},"expected_ciphertext":""}
```

密钥第 31 个字符 `G`：

```json
{"summary":{"total_bytes":0,"wrong_count":0},"first_diff":null,"propagated":[],"input_mismatch":{"field":"key","char_index":31,"expected":"hex"},"expected_ciphertext":""}
```

- `field` 是 `plaintext` / `key` / `both` 之一；
- `char_index` 从 0 开始；
- `expected` 为 `"hex"`；
- 输入非法时不做统计（summary 分母为 0）。

## 7. 实现口径

| 项 | 实现 |
|---|---|
| 判分入口 | 仅 `POST /api/quiz/submit` |
| 请求 | `item_id / answer_hex / plaintext_hex / key_hex / key_bits` |
| 全对 | `first_diff=null`、`propagated=[]`、`wrong_count=0` |
| 单错 | `first_diff` 含 `step_index/round/step/byte_index/expected/actual`，只 1 格 |
| propagated | 首个差异之后的下标数组；从不返回 `null` |
| input_mismatch | 非 hex 时返回对象；正常为 `null` |
| expected_ciphertext | 由后端重算 C.1 得到 |
| 埋点 | `POST /api/events` 批量校验后返回 204 |
| 前端复算 | `PracticeView` 无 `engine/` 引用 |

## 8. 已知边界

| 项 | 说明 |
|---|---|
| `first_diff` 轮/步 | 只有最终密文可观测，因此定位到最终 `add_round_key`；没有学生中间态，无法反推更早的首错轮次。若后续练习需要“第 N 轮列混合”定位，必须补学生 trace/逐步答案，不能由最终密文推导 |
| `propagated` | 按“首个差异之后的下标”实现，与 §11.4 示例一致；不是密码学意义上的完整扩散模拟 |
| `summary.total_bytes` | AES 分组固定 16；§11.4 示例中的 `12` 与 16 字节密文不一致，本实现取 16 |
| `item_id` | 请求必填，但本轮没有题库表数据，未参与计算 |
| 埋点持久化 | 只交付批量上报线并返回 204；`session_id` 是字符串（如 `s_9c21`），与 B1 的 `sessions.id` 整数主键映射后再落 `step_events`，避免现在硬造会话 |
| 后端测试 | 未引入 pytest；用 `backend/tools/quiz_probe.py` 做接口级验证 |

## 口径变更说明（2026-11-10）

- **旧口径**：`propagated` = 首个差异字节之后的索引后缀（本次实测 `[8,9,10,11,12,13,14,15]`），当时作为“可观测下游”实现；旧值与旧断言继续有效。
- **新口径（待 T2-2/T2-3 生效）**：新增 `diff_bytes`（全部差异字节）与 `source_bytes`（首错下标经末轮逆置换得到的 4 个候选来源列）；`propagated` 保留一版并标记兼容/deprecated，前端新文案不再由它驱动。
- **生效条件**：D-02=A 且 T2-2/T2-3 完成；在此之前不改字段、不改 UI。
- **影响字段**：`propagated`、`first_diff`、`RecordsAttempt.first_diff_*`、F19/F24 的 `.is-downstream` 断言。
- **证据原则**：旧口径是当时的可观测实现，新口径是教学修正；不写“旧结论作废/造假”。
