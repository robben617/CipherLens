## 5. 暂停停终态

在第 2 步（第 1 轮 SubBytes）动画进行中调用 `pause()`：

| 项 | 实测 |
|---|---|
| currentStep | 2 |
| isPlaying | false |
| running animations | **0** |
| 矩阵 16 格 | `63 CA B7 04 09 53 D0 51 CD 60 E0 E7 BA 70 E1 8C` |

## 6. 写值通道调整

F13 播放时，4× 的步间隔（200ms）短于 ShiftRows（430ms）/ AddRoundKey（480ms），相邻步的写值会落在同一帧。原 `useMatrixWriter` 的 `[MULTI-BATCH]` DEV 断言会把这种合法的重叠写入报成 error。

调整：

- 同一帧的多次 `write` / `writeColumns` 合并为 **1 批**，flush 仍一次写全 16 格；
- 新增 `settle(values)`：暂停时若同帧已有待写入，只更新 `currentValues`，不创建第二批；
- 移除 `[MULTI-BATCH]` 的 console.error 断言，保留 `__MATRIX_BATCHES__` 诊断数组。

这是对 F5 历史断言的有意修订：F5 的“人为双写会报错”只针对同一写入循环重复 flush；F13 起的播放重叠属于正常输入，不能报错。

## 8. 已知边界

| 项 | 归属 |
|---|---|
| 4× 下长通道与下一两步重叠 | ShiftRows 430ms / AddRoundKey 480ms > 200ms；F13 未实现 `stepLockUntil`，验收只要求单步动画不被缩短 |
| store 字段 | 只实现 `isPlaying` / `currentStep` / `speed` / `stepCount`；`mode` / `direction` / `follow` / `stepLockUntil` 留给后续 |
| 反向单步动画 | 当前 `prev` 是跳转，不是反向执行 |
| 临时调试设施 | MatrixStage 的 `data-debug-next` 已删除；`__CIPHERLENS_TRACE__` / `__CIPHERLENS_PLAYBACK__` 仅 DEV 用于验收，W4 删除 |
| 图例位置 | 从 Timeline 迁到 TransportBar 控制行右端，`aria-describedby` 仍指向同一个 `#timeline-legend` |
| 倍速选择 UI | 原生 `<select>`，未自绘下拉；视觉打磨留到后续 |
