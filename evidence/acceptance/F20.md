## 3. 三类误解分布

只展示三类固定枚举，不做自由文本聚类：

| key | 标签 | 条数 |
|---|---|---|
| `key_timing` | 轮密钥时机 | **4 次** |
| `mix_coefficient` | 列混合系数 | **1 次** |
| `key_schedule` | 密钥扩展方向 | **1 次** |

分布用 CSS 条形（无图表库）。归类映射（可枚举）：

| `first_diff.step` | 误解类型 |
|---|---|
| `add_round_key` | 轮密钥时机 |
| `mix_columns` | 列混合系数 |
| `sub_bytes` / `shift_rows` | 密钥扩展方向 |

> 说明：F18 诊断 store 当前只区分 `idle` / `toggle` 两类触发，不产出“误解类型”。本轮记录页以判分返回的 `first_diff.step` 做固定枚举归类；后续接入诊断规则类型时只替换映射，不改 UI 与接口形状。

## 5. 真实判分写入链路

清空记录后，通过真实 `POST /api/quiz/submit` 写入：

| 操作 | 响应 | 记录页数据 |
|---|---|---|
| 答错（字节 7 `fb → fa`） | `first_diff.step=add_round_key` | `total=1`、`correct=0`、`key_timing=1` |
| 答对 | `first_diff=null` | `total=2`、`correct=1`、`accuracy=0.5` |
| 输入非法（明文第 7 位 `G`） | `input_mismatch` 非 null | **`total=2`、`correct=1` 不变** |

即：判分成功才写入；`input_mismatch` 不进入记录与分母。

## 6. 实现口径

| 项 | 实现 |
|---|---|
| 存储 | 新增 `practice_attempts`（`item_id TEXT`、`submitted`、`is_correct`、`first_diff_*`、`misconception`、`created_at`） |
| 写入 | `POST /api/quiz/submit` 判分后调用 `record_attempt`；`input_mismatch` 非 null 直接跳过 |
| 读取 | `GET /api/records/summary` 一次返回统计、三类分布、趋势、错题列表 |
| 三态门槛 | `total=0` 空；`0<total<3` 数据不足；`total>=3` 有数据 |
| 正确率 | 后端 `correct/total`，前端只做百分比格式化 |
| 趋势 | 最近 20 次，手写 SVG `polyline` + `circle`，正确 y=14 / 错误 y=50 |
| 错题 | 最近 10 条错误，带 `first_diff_step_index` 供跳转 |
| 图表库 | **未引入**；`grep chart/echarts/d3` 为空 |
| 前端复算 | `RecordsView` 不引用 `engine/`（`NO_CHART_NO_ENGINE`） |
| 未登录 | 顶部固定「本机数据（未同步）」；不做登录拦截 |

## 8. 已知边界

| 项 | 说明 |
|---|---|
| 三类误解来源 | 当前按 `first_diff.step` 固定映射，不是 F18 诊断规则命中；诊断类型接线留待后续 |
| 做题数口径 | 统计尝试次数，不按 `item_id` 去重；PRD 的“首错用于错因分析”去重规则留待错题本阶段 |
| 0/2/10 数据 | 截图用 `records_probe.py --seed` 合成记录，仅用于三态 UI；真实写入链路另用真实判分验证 |
| 题库规模 | 仍只有 `q_042` 一道内置题，趋势/错题都来自同一题 |
| 持久化范围 | 记录存于 `backend/data/cipherlens.db`；未做登录、跨设备同步、导出 |
| 统计上限 | 趋势最多 20 条、错题最多 10 条；更大样本未做分页 |
| 服务启动 | Vite 需 `--host 127.0.0.1`，否则默认 IPv6 `localhost` 下 `127.0.0.1:5175` 不可达 |
| 验收探针 | `records_probe.py` 直接读写 SQLite，是验收设施，不是产品接口 |
