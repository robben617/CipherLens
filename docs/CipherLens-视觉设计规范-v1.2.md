## 0. 一句话结论

**不要做「漂亮的密码学 App」，要做「一台被校准过的测量仪器」。** 界面上唯一的装饰权，全部让给"高亮的精确性"和"四个真正有力的动效"；其余部分用 1px 线、字距、留白和刻度解决秩序问题。

## 1. 美学方向声明

### 1.1 方向名：**「校样」（Proof Sheet）**

把界面当作一张**工程校样纸**来排：纸底冷白、发丝线分隔、等宽数字成列、区域带图号式标签、四角有裁切刻线；而"AI 知道你卡在哪"这件事，用**红笔批注**（老师在校样边栏上用红笔划出的圈注）来表达。

**为什么适合这个产品**：AES 教学的本质是"读数"——学生要盯着 16 个字节在几十步里的变动。一台仪器的界面不需要好看，需要**可信**；而"可信"在视觉上的具体表达式是：稳定的网格、不抖动的数字列、只在你需要时出现的精确标记。校样纸恰好是"高信息密度 + 强秩序"的最佳隐喻，同时天然承载"批注 / 纠错 / 判分"三个业务动作。

### 1.2 记忆点（Memory Hook）：**红线批注**

系统察觉你卡住时，**不弹 toast、不弹卡片、不居中**，而是在 AI 辅导栏顶部那一行常驻的批注位里，用一条静止的 2px 红竖条 + 一个手绘感的方括号，写一句反问；同时用两条**非浮层**信号指回矩阵里那个具体字节：

1. 目标字节格的边框被一条 1.5px 红线逐边描出（这是格子自身的样式变化，不新增任何覆盖平面）；
2. AI 栏左边缘那条分隔线上，在目标格中心高度出现一段 **12×2px 红色刻痕**（沿既有线条走，绝不进入矩阵内容区）。

它像有人在你纸上用红笔写了句话，并用笔尖点了一下那处。全球没有一个密码学教学产品这么做，且它把"知道你哪不懂"这个唯一卖点变成了可见形态，而不是一个提示条。

> **为什么是"写在边栏"而不是"画在纸上"**：校样纸上的批注本来就在边栏，不在字符上；而且画到字符上必然覆盖矩阵——交互规格 UX-V3 明确禁止任何浮层覆盖矩阵与时间轴。改到边栏后，记忆点没有削弱，反而更贴原型。

**次级识别符号：列括线。** 状态矩阵的 4 列各有一条 1px 竖向括线，把 16 个方格先读成 4 条竖条。这既是 AES"列优先"的视觉暗示（不用一个字的解释），也是本产品截图里最容易被认出的图形特征。

### 1.3 如何通过 AI Slop Test

| 常见 slop 表征 | 本方案的对抗手段 |
|---|---|
| 紫蓝渐变 / 深底霓虹发光 | 单一强调色 = 深青墨 `h205 / C 0.088`，饱和度刻意压到 C≤0.09，亮色纸底上不产生"发光"错觉；全站**零渐变**（唯一例外是荧光笔高亮的线性展开，见 §5.2） |
| Inter / Roboto | 换 Archivo + Noto Serif SC（标题）+ IBM Plex Mono（数字），三者在同字号下的字幅与字腔完全不同 |
| 万物皆卡片 | 用 1px 发丝线 + 图号式区域标签 + 四角刻线分区；**全站只有 2 个浮层允许有阴影**（inspector 数据条、诊断批注） |
| 毛玻璃滥用 | 零 `backdrop-filter` |
| 圆角 + 通用阴影 | 圆角上限 3px；"阴影"统一降级为 1px 底线 `0 1px 0 var(--line-default)` |
| 居中一切 | 全站左对齐基线；只有字节格内的 hex 数字居中（因为它是读数） |
| 英雄指标模板 | 无 Hero 区。首页是"校样纸标题页"，工作台首屏直接是矩阵 |
| 无意义粒子背景 | 背景只有纸色 + 首页一块极淡点阵区（见 §9） |
| 圆润闪烁光标 / 弹性动效 | 光标是 2px 实心方块 + `steps(2)` 步进闪烁；**全站禁止 y 轴过冲的缓动**（`cubic-bezier` 的 y 值必须落在 [0,1]） |

### 1.4 三条视觉红线（跨页面生效，评审按此打分）

这三条不是审美偏好，是**认知正确性**要求。它们会在工作台、练习、错题本、学习记录、教师端看板里反复出现，任何一处违反都算返工。

**红线 1｜区域级、大面积的视觉通道只能表达「范围」或「程度」，不能表达「对错」。**

判错时学生会因为 AES 的雪崩性看到"全变"，但从"全变"推不出"全错"。给整个矩阵套红框，等于用最强的大面积信号把"我全错了"这个错误认知重新装回去，把文案层的归因修正整个抵消掉。所以：

- 对错 = **点级通道**（单个格子的折角、`≠`、边线）
- 范围 = **区域级中性通道**（**四角括** + 文本标签「影响范围：16 字节」；不用完整外框，因为"围起来"这个动作本身带"这块有问题"的语气）
- 受牵连 = **"安静下去"**（第 7 态 `downstream`，见 §2.3）

同一原则的其它落点：学习记录的热力图不能用红色面积表示"薄弱"，教师看板不能用整片红表示"这一届都差"——那两处只能用中性深浅 + 一个数值标签。

**红线 2｜任何无限循环动画 = 零。** 教室电脑公用、长期不关，循环动画会持续占合成层；更重要的是它会破坏"仪器应当静止"的可信感。禁止清单：呼吸、脉冲、缓慢闪烁、无限滚动的等待指示、"待机光点"。

**红线 3｜视觉强度必须与信息的重要性成正比，且不得超过它。** 最容易被忽视的是反例：首错导致 16 字节全变时，最重要的信息恰恰是"**你只错了 1 处**"——此时最大的视觉强度应当给那 1 个字节，其余全部降级。

## 2. 色彩系统

### 2.1 明暗主题策略：**只做亮色（"纸"），暗色留到 v1.2**

**理由（按权重）**：

1. **投屏是硬需求，且只有亮色能过**：教室投影仪在开灯的教室里，暗色主题的深色区域会被环境光"洗灰"，黑不下去，对比度反而崩塌；亮底深字在投影上更稳。这是次目标用户（教师）的可用性底线。
2. **长时间注视疲劳的主因是绝对亮度与眩光，不是背景明暗**：用 `oklch(0.981)` 的微冷纸白（不是纯白）比 `#fff` 降低眩光，同时保留亮底可读性。
3. **工期**：双主题 = token 双份 + 6 种字节状态 × 2 套验证，成本翻倍且必然出次级 bug。**正确做法是 token 全部走语义层（`--paper-*` / `--surface-*` / `--ink-*`），暗色将来只替换一层，不动组件。**

**替代纯黑纯白**：

- 纯白 `#fff` → `--paper-0: oklch(0.981 0.0025 250)`（微冷纸白；饱和度仅 0.0025，避免"发蓝"）
- 纯黑 `#000` → `--ink-1: oklch(0.255 0.018 258)`（墨蓝黑，对纸底对比度约 **14.8:1**，远高于 AA，但不像纯黑那样在亮底上"扎眼"）
- 最深的表面色是 `--st-key-ink: oklch(0.360 0.012 258)`（石墨）；**常规态全站没有任何元素低于 L 0.19**，演示态最深为 `oklch(0.190)`（专为投影加深的文字色）

**强调色为什么是深青而不是蓝**：深青在冷纸底上读作"仪器丝印"，蓝色读作"链接"；而 C 压到 0.088 是为了让它**永远不发光**——发光是深色系 AI slop 的第一特征，在亮色系里则会变成"廉价荧光"。

### 2.3 七态字节色板（核心交付）

**设计原则：颜色是第 7 通道，前 6 通道优先。** 每个状态由「底色 → 纹理 → 边框 → 角标 → 文字 → 墨量」六层叠加表达；纹理与角标是**独立叠加层**，可与底色共存（例如"轮密钥加"这一步里每个格子既"本步变化"又"密钥参与"）。

#### 2.3.1 常规态

| # | 状态 | 底色（通道1） | 纹理（通道2） | 边框 / 角标（通道3–4） | 文字（通道5） |
|---|---|---|---|---|---|
| A | 普通 `idle` | 无填充（纸） | 无 | 1px `--line-default` | `--ink-1` 500 |
| B | 本步变化 `changed` | 满涂 `--st-changed` `oklch(0.855 0.145 82)` | 无 | 顶部 `inset 0 2px 0 --st-changed-bar` `oklch(0.740 0.160 78)`；右上角 3px 实心琥珀角标 | `--ink-1` 600 |
| C | 选中 `selected` | `--paper-0` | 无 | **`border-color: --accent`（宽度仍 1px）+ `inset 0 0 0 1px --accent`（合起来 2px 观感，但不改 border 宽度、不位移 hex）+ 外 3px `--accent-ring`**（判分上下文中环色改 `--ink-1`，见 §9.1）。**不再用四角刻线**——理由见下方"为什么选中态不用四角刻线" | `--accent-strong` 600 |
| D | 错误 `error` | `--st-error-fill`（红 10%） | 无 | **右下角 6px 红色实心折角三角** + 底部 `inset 0 -2px 0 --st-error` + 右上格外 2px `≠` 上标 | `--st-error` 600 |
| E | 密钥参与 `key` | 石墨 6% | **45° 斜纹 hatch** | 左侧 3px `--st-key-ink` 竖条 + 右上角 4px 实心石墨方块 | `--ink-1` 500 |
| F | 已完成 `done` | 无填充（纸） | **无纹理**（去点阵） | **1px 实线 `--line-default` + 左下角 5px 缺口**（由 `__corner[data-corner="bl"]` 压一块 `--paper-0` 方块实现，**不用 `border` 断边**——断边会随 `border-color` 变化失效） | `--ink-3` 400（视觉权重约 60%） |
| **G** | **受污染 `downstream`** | **`--surface-inset`（底色内缩一档）** | **无纹理** | **1px `--line-hairline`（唯一允许的动作：降一级）**；无角标、无折角、无 `≠`、不换线型 | `--ink-3` 400 |

**为什么选中态不用四角刻线（r5 撤除，原先用了四版）**

`selected` 原来用"四角 6px L 形刻线"作非颜色第二通道，撤除它是因为**它在同一个像素位置上和 `error` 抢语义**：

1. **同位置、同尺寸、不同含义。** `error` 的身份通道是**右下 6px 折角三角**，而四角刻线里正好有**右下那条 6px 臂**。`error + selected` 不是边角情形——判错后点开那个错字节看明细，是练习流程里**必然发生**的动作。两者叠加时看起来像"一条画歪的线"，学生读不出这是两个语义在争用。
2. **四角是角标通道，且已满。** 角标通道的四个位置已按 §6.1.1 分配完（左上 reverse / 右上 changed / 右下 error / 左下 done），规则是"每格 ≤2 个、不得覆盖既有角"。再塞一套刻线进来，等于**同一个通道有了第二个 owner**，直接违反"一个通道一个 owner"。
3. **撤掉之后，单格级别不再有任何 L 形符号**，同屏只剩"容器活动区刻线 vs 范围角括"这一对（§6.7），需要校的组合从三种降到一种。

**第二通道改由外环承担**（不能只删刻线就完事，否则 `selected` 退化为纯颜色信号）：

- 必须是**环**（`outline` / `box-shadow`），离格边留 2px 空隙；**不能退化成"把边框加粗"**——加粗只是量变，环是另一种形状；
- `selected` 的完整表达是**三件套全落在边缘通道**：`border-color` + `inset 0 0 0 1px` + 外 3px 环。它与角标通道**正交**，所以永远不会和 `error` / `done` / `key` 抢位置；
- **判分上下文中环色改 `--ink-1`（近黑）**：红底 + accent 环在红色盲下会并成一团，近黑环才稳（详见 §9.1）。**作用域是整个 `[data-ctx="graded"]`，不是"仅 `error` 格"**——否则同一个选中态会因为底下那格是不是错格而换色，**同屏两种环色比一种更难读**。

**环宽不是一个可以随手调厚的数，它受格间距约束**（r5 补正，fe 的 §3.1 与 ux 的口径表都直接用这个式子）：

```
环宽 + 环离格边的偏移 ≤ --cell-gap − 1px
```

| 档 | `--cell-gap` | 环宽 | 偏移 | 外扩合计 | 余量 |
|---|---|---|---|---|---|
| 常规 | 6px | 3px | 2px | 5px | **1px** |
| 演示 | 10px | 5px | 2px | 7px | 3px |

- **常规档只剩 1px 余量**：把常规环从 3px 加到 4px，环就会碰到相邻格的边框——16 格矩阵里相邻两条边贴在一起，会读成"两格连成一块"，正好毁掉 6px gap 的 chip 语言。
- **留 1px 而不是 0**：0 余量在 125% / 150% 系统缩放下会因亚像素取整而接触，肉眼是"偶尔粘一次"的间歇性缺陷，最难查。
- **想加厚时先看式子，不要直接改数**；要突破就得同时改 `--cell-gap`，而 `--cell-gap` 一变，`downstream` 边框"降一级不移除"的判据也要重算（§12.4-1）——**这条链是连着的，不要只改一头**。

**注意适用范围**：本条只管**字节格**。`--corner-tick` 这个语言在别处仍然合法——矩阵容器的"当前活动区"刻线（§6.2）与 B 区输入框的 focus 刻线（§6.8）都保留，因为那两个组件里**没有角标通道**，不存在争用。撤的是"字节格里再出现 L 形"这一件事，不是这个语言本身。

**这条能被推翻，但推翻它不只靠"看得见"**：如果将来有投影实测证明"6px 臂 × 1px 线宽在 1080p + 3m 距离下仍清楚可辨"，刻线可以回来——**但那时必须同时把 `error` 的折角挪到别的角位**，否则右下角仍然是"同位置、同尺寸、两个语义"。**判据是两个条件同时成立：看得见，且不撞角位。** 只满足前一个就恢复，等于把 r4 那个补丁又装回去。

**第 7 态 `downstream`（受首错污染的字节）的完整语义与规格**

它不是"另一个错误标记"，而是**"安静下去"**。数据来源：`POST /api/quiz/submit` 返回的 `propagated: number[]`。

| 项 | 规定 |
|---|---|
| 视觉目标 | **减墨**，不是**加标记**。它不需要被看见，它需要的是"和那 1 个错误字节形成对比" |
| **边框降一级，不是移除** | `--line-default`（L 0.845）→ `--line-hairline`（L 0.885）。**这是唯一允许的边框动作**，理由见下方"为什么去掉边框不成立" |
| **为什么不能移除边框** | 早期 v1.1 主张"去掉边框"，已否决：矩阵是 6px 间隙的独立 chip，**每一格的外框是它自己的完整矩形**，抽掉一格的框不会被读成"安静"，会被读成"这格没画完"——在一群自带完整外框的方块里，缺一个框比浅一个框显眼得多 |
| **也不许换线型或加粗** | 不得用虚线（虚线专义是"未生效/待定/禁用"，见 §2.6），不得用点划线（本规范已无该用例，r4 删除，见 §2.6），不得加角标、不得加粗。**降一级是全部动作** |
| 底色 | `--surface-inset`（比纸深一档，ΔL 0.036）——**"退后"而不是"突出"** |
| 禁止 | **不得复用 `error` 的任何通道**：不要红、不要折角三角、不要底部 inset 红条、不要 `≠` 上标、不要 `--st-error-fill` |
| 选择器隔离 | 前端单独挂 `is-downstream`；CSS 中 **`is-error` 与 `is-downstream` 互斥**（JS 保证），且**所有承载 `error` 特征的节点**（`__corner[data-corner="br"]` 的折角、底边 `inset` 条、`__sup--neq` 上标）的显示规则必须写成 `:not(.is-downstream)` 保护 |
| 可叠加 | `is-downstream` + `is-selected` 合法（学生点开一个受牵连字节查看来源链）；`is-downstream` + `is-changed` **在判分期不叠加**（见 §9.1 上下文覆盖规则） |
| 与 F 态 `done` 的区别 | 两者都保留边框（**都不能不要**），区别在边框之外的通道：`done` = 边框满值 + **左下角 5px 缺口**（形状通道）；`downstream` = **边框降一级** + 底色内缩 + 墨量降级（"这一片先别看"）。**`done` 用形状，`downstream` 用色阶，两者不共用通道，不会互相误读** |
| 灰度可辨性 | `ink-1`（L 0.255）/ `ink-3`（L 0.545）**ΔL 0.29** —— 墨量这一档在灰度下清晰成立。底色档 `--surface-inset` 与纸只有 **ΔL 0.036**，**这一档在灰度与投影下都不可靠，不承担区分职责**，只承担"退后"的氛围。灰度下"错的 1 个（折角形状）→ 受牵连的（无形状、最淡的墨）→ 正常的（中等墨量）"三者靠**形状 + 墨量**可分，不依赖底色 |

**为什么"去掉边框"这条路在本设计里从根上不成立（这条我推翻过两版，结论留档）**

矩阵是 **`display:grid; gap:6px` 的 16 个独立 chip**（§6.2），不是连续表格：

- 每格四周都有 **6px 纸色间隙**，"外框"是这一格自己的完整矩形
- **格与格之间没有共享边**，所以不存在"抽掉一条线只影响一半"的情况——**抽掉一格的边框，那一格就与周围所有自带完整边框的格子明显不同**

这就是为什么"减墨"在本设计里只能**降级**、不能**移除**：在一群各自有完整外框的方块里，少一个外框不会被读成"安静"，会被读成**"这格没画完"**。6px 间隙是保护（画面透气），也是约束（**边框是每格的身份证**）。

由此得到 `downstream` 的唯一定义方式：

> **边框保留，只降一级（`--line-default` → `--line-hairline`）。不可移除、不可换线型、不可加粗。**

**一个已被否决的替代方案（记下来防止再被提出）**：曾考虑"把格线改为由矩阵容器统一绘制（`gap:1px` + 容器底色），格子不写 border"。它在**本设计里不成立**，且有两个独立的否决理由：

1. **与既有构图冲突**：矩阵是 `--cell-gap: 6px`（§6.2 / §7.1）。容器底色方案会在 16 格之间填出 **6px 粗的实色条带**，不是 1px 细线；若把间隙压到 1px，"16 个独立格 + 透气"的读法与 §6.2 的列括线设计同时失效。
2. **它解决的是一个不存在的问题**：该方案原本是为了消除"相邻格共享边 → 两条 1px 叠成 2px、且两格状态不同时那条边颜色一半一半"。但 **6px 间隙下每格边框完全独立，既无共享边、也无双线**。也就是说，这个方案治的病在本设计里没有。

> **教训**：判定"某条 CSS 结构有问题"之前，先查这张表自己的 `--cell-gap`。我提出这个方案时没有核对 §6.2 的 6px，直接假设了连续表格——**跟 fe 定的那条纪律是同一类错误：引用数值时不回原文核对**。

**边框宽度必须恒定 1px，位移问题用 `border-color` 而不是 `border-width` 解决**：七态之间只改 `border-color`，不改宽度，因此 `box-sizing` 怎么算都不会让 hex 位移。需要"加粗感"的状态（`selected`）用**叠加 `box-shadow: inset`** 而不是把 border 改宽——inset 画在格内，不动盒模型。

#### 2.3.2 演示态（投屏）——不透明、零纹理、零 alpha

投影仪会吃掉所有低对比细节与半透明叠加，因此演示态**换一套通道**，不换语义：

| 状态 | 演示态表达 | 承载对比度 |
|---|---|---|
| 普通 | 实心 `--paper-0` + **2px `var(--rule-region-ink)`** = `oklch(0.545 0.012 258)` 边框 | 4.6:1 ✅ |
| 本步变化 | 同常规（黄底已不透明）；顶条加粗到 **3px**，hex 字重 **700** | 顶条 4.9:1 ✅ |
| 选中 | **3px `--accent`** + 外 **5px 实心** `oklch(0.925 0.026 205)` 环（r5 补厚 1px 替代原刻线：投影下环必须够宽才看得出"双层"） | 3.4:1（由线宽 + **环的双层结构**补足，不靠刻线） |
| 错误 | **实心 `oklch(0.905 0.055 28)`** + 3px 红边 + 10px 折角 + 14px `≠` | 红边 4.8:1 ✅ |
| 密钥参与 | **实心 `oklch(0.895 0.004 258)`** + 左 **6px** 石墨条 + 右上 **5px** 实心方块 | 石墨条 9.1:1 ✅ |
| 已完成 | 无纹理；**2px `var(--rule-region-ink)` + 左下角 6px 缺口（纸色方块压上去）** + 文字 `--ink-3` | 边框 4.6:1 ✅（r5 补正：原为 0.760 / 2.9:1，投影下会被读成"没画完"）；缺口形状仍承担身份通道 |
| **受污染 `downstream`** | **边框不降级**——`border-color` 引用 `--st-downstream-border`，其演示值 = **`var(--rule-region-ink)`**，与同屏其他格**同一个值**（0.545，4.6:1）；安静感改由三样东西同时承担：底色加深到 `oklch(0.905 0.004 258)`（比纸深 **ΔL 0.06**，常规档的两倍）+ 文字 `--ink-3`=`oklch(0.415 0.012 258)`（**8.4:1** ✅）+ **字重 400**（同屏其他态均为 700） | 文字 8.4:1 ✅。**这是"演示态换一套通道、不换语义"的直接应用**：常规档用"边框浅一级"表达"退后"，投影会把浅一级的线抹平成纸色（抹平后读作"这格没画完"，比不降更糟），所以演示档把"退后"整体挪到底色与字重上承担。**引用 token 而不是硬写值**，是为了让"不降级"成为结构事实——日后改演示线色时它自动跟随 |
| 判错（整段错 / 首步即错） | **四角括（corner brackets）**：四角各一个 L 形，**实线 2px** `oklch(0.545)`，长臂 **28px** / 短臂 **28px**，内缩 6px；配骑在顶边上的标签「影响范围：16 字节」（13px） | 4.6:1；**没有完整外框、没有虚线、没有琥珀** |

**演示态为什么让"格子边框"与"区域分隔线"同色（都取 `--rule-region-ink` 0.545），层级改由别处承担**

常规态靠明度分层级（格子 `--line-default` 0.845 / 区域 `--line-strong` 0.720，区域更深）。**演示态不能这么分**：投影会把所有"浅一级"的线抹平成纸色，0.760 的格子边框在 1080p 投影上只剩 **2.9:1**，被读成"格子没画完"，而不是"格子比区域次要"。所以演示态**把可视线一律抬到 ≥4.5:1**，层级改由三样重建：

1. **留白**：区域之间 16px 起，格间只有 6px（演示 10px）；
2. **标签**：区域带图号式标签（`STATE MATRIX` / `DIAGNOSTIC`），格子没有；
3. **位置**：区域分隔只出现在两区之间，从不与格子相邻——两者在屏幕上永远不相邻，本来就不需要靠色差区分。

**"靠更淡来分层级"在投影上等于"没有层级"**——这条和 `downstream` 在演示态不降级、`done` 从 0.760 抬到 0.545，是同一条道理的三次应用。

#### 2.3.3 色盲友好论证（评审会追问，必须能背）

1. **明度是主通道**：B 态 L=0.855（填充）/ D 态 0.545 / C 态 0.500 / E 态 0.360，相邻状态 **ΔL ≥ 0.10**。红绿色盲（deutan / protan，占人群约 8%）会丢失 h82–h27 的色相差，但拿到明度差后 B≈浅、D≈中、C≈中深、E≈深，仍然可分。
2. **形状通道**：C 有**外环**（唯一有双层环的状态——环是形状，不是颜色）、D 有折角三角（唯一有角标的状态）、E 有斜纹 + 方块、F 有左下缺口（唯一有缺口的）、B 有实心色块 + 顶部厚条、G 的唯一动作是**三档同时减**（边框降一级 + 底色退一档 + 墨量降一档），**形状零新增**。通道互不重复；演示态下改为形状互不重复。
3. **位置通道**：E 的标识固定左边缘 + 右上角，D 固定右下角 + 底部，B 固定顶部。整格变灰后位置仍在。
4. **文本通道兜底**：凡"行为语义"差异（播放中 vs 暂停、缓存命中 vs 流式、输入不一致 vs 判错），一律给文本或图标，**不给颜色**。
5. **不给"正确"任何颜色**：判分正确 = 无标记（即 A 态）。少一种颜色，就少一次与 accent 青 / 成功绿混淆的机会。
6. **"受牵连"用减墨，而不是用标记**：G 态只有三个动作——文字墨量降一档、底色后退一档、边框降一级（`--line-default` → `--line-hairline`），**形状零新增、角标零新增**。学生的眼睛会自动跳到唯一有形状的那一格（D），而不会把注意力分散到 15 个同样安静的格子上。这是"安静"作为设计手段的唯一正解：**安静 = 拿掉东西，不是换成另一种颜色，也不是换成另一种线型**。
7. **七态不共时**：A/B/C/E/F 属于"播放与浏览"（工作台），D/G 属于"判分与定位"（练习）。D 与 G 严格互斥，B 与 D 也不同时出现。真正需要同时分辨的最多 4 态，这保证了灰度下的可辨性有余量。
8. **验收标准（写进测试用例，已脚本化）**：对工作台截图加 `filter: grayscale(1)`，必须仍能在 3 秒内指出"哪几个字节变了 / 哪个选错了 / 哪些是密钥字节 / 哪些是受牵连的"。做不到就调**明度**，不调**色相**。

### 2.5 结构线的分级制度（常规 1px / 演示 2px）

这是"不许万物皆卡片"的落地机制，也是投影可读性的落地机制：

| 层级 | 常规态 | 演示态 | 用在哪 |
|---|---|---|---|
| 区域级分隔（A/B/C/D/E 之间） | 1px `--line-hairline` | **2px `oklch(0.545 0.012 258)`**（4.6:1） | 五区之间 |
| 区域内部分隔（表头、行组、组内） | 1px `--line-hairline` | **不画线**：8px 留白 + 交替底 ΔL ≥0.10 | S 盒分组、密钥带分组 |
| 强调分隔 | 1px `--line-strong` | 2px `--line-strong` | 轮段分隔、当前活动区边界 |

**演示态为什么不画区域内细线**：投影会把 1px 线渲染成一条模糊的灰带或直接消失；而 8px 留白在任何投影上都不会消失。

### 2.6 线型语汇（每条线只能有一个含义）

线型是**语汇**，不是装饰。同一线型在同一界面上表示两种意思，等于两种语义互相污染。全站只允许**三种**用法：

| 线型 | 唯一含义 | 出现位置 |
|---|---|---|
| **虚线**（`dashed`） | **未生效 / 待定 / 禁用** | 空态占位格、计算中的格边、禁用按钮、未生成的时间轴、判分中的作答锁定框、拖拽预览态、数据不足的统计块 |
| **实线**（`solid`） | **已生效 / 确定** | 正常格边框、已完成格（+ 缺口）、选中、错误、四角括、区域分隔 |
| **不用线型** | **明确"不强调"** | 受污染 `downstream`（只降 `border-color`，**不换线型**）、已读消息、`.c-diagslot` 空态 |

**点划线已删除**（r4）：`done` 改为"实线 + 左下缺口"之后，全站**已无任何点划线落点**，用例数为 **0**。留着"存在但没用"的线型，等于留了一个迟早被误用的空语义——**这和本节的准入规则是同一件事的两面**。以后若真有"演示态替代纹理"的需求，按下面第 3 条走准入流程，不要在表里预先占位。

**三条纪律**：

1. **`done` 不用虚线**。它原来用虚线框，与"未生效"家族相反——**左下角的 5px 缺口才是它的身份通道**，边框改实线。
2. **虚线不能兼职表达"对错"**。判对 / 判错只靠**图标 + 文案 + 折角形状**，不许用边框线型区分。线型有专义后没有余量。
3. **新增线型用法前先在这张表里找它属于哪一行**；找不到，说明这个状态需要的不是线型，而是形状或文本。

**这条规则的来源是一次真实的冲突**：练习页的"已完成"用虚线、空态也用虚线，两个语义在同一个界面上撞过。

### 3.1 三角色选型

| 角色 | 选型 | 理由 |
|---|---|---|
| 展示 / 标题 | **Archivo** 700（拉丁）+ **Noto Serif SC** 600（中文） | Archivo 字幅略窄、字腔收紧、字重端点方硬，大字下像工业丝印；中文标题用宋体是中文技术出版物（学报 / 白皮书 / 图纸标题）的固有权重，与等宽数字对撞后立刻脱离"网页 App"语感 |

**为什么不用 Inter / Roboto**：Inter 的笔画对比度近乎为零 + 完美均质几何 + 被大模型生成页面用成了视觉指纹，学生一眼会归到"AI 做的作业"；Roboto 同理。Archivo 在 14px 下的字幅比 Inter 窄约 4%，这在 16 格 × 多列的密集网格里直接等于多出半个格的可用宽度；而它在 700 字重下的方硬端点，是"仪器面板"与"消费级 SaaS"的分水岭。

**加载策略（10 天工期红线）**：优先 `@fontsource/archivo`、`@fontsource/ibm-plex-mono`（只取 400/500/600）。`Noto Serif SC` 600 体积大 → 只做**标题用字子集**（首页 + 区域标题的百来个字），或降级为系统宋体 `"Songti SC", "SimSun"`；`Noto Sans SC` 走 `unicode-range` 分片按需加载。**fallback 必须显式写全**，避免首帧 FOUT 导致网格位移。

```css
--font-ui:      "Archivo", "Noto Sans SC", "PingFang SC", "Microsoft YaHei", system-ui, sans-serif;
--font-mono:    "IBM Plex Mono", "JetBrains Mono", ui-monospace, "SFMono-Regular", Consolas, monospace;
```

| `--lh-body` | `1.65` | — | 长读正文（演示态降为 1.50） |
| `--lh-mono` | `1.20` | — | 数字块 |

**字重纪律**：全站只用 400 / 500 / 600 / 700 四档，**不加载 300**（亮底细字在投影上直接消失）。中文标题用 600 而非 700（宋体 700 太"海报"）。

### 3.3 十六进制数值排版规范（硬规则）

| 规则 | 规定 | 理由 |
|---|---|---|
| 大小写 | **全大写**（`2B 7E 15 16`） | FIPS-197 附录、S 盒表、教材全部大写；混写会在抄写对照时出错 |
| `0x` 前缀 | 网格 / 表格 / 展示中**一律不加**；仅"单值输入框"和"公式表达式"保留 | 16 格里加前缀吃掉 25% 宽度，是纯噪声；但输入语境必须显式声明进制 |
| 分组 | 字节间 `4px`；密钥 / 密文 32 位**每 8 位一组**（`2B7E1516 28AED2A6 ABF71588 09CF4F3C`），组间 `8px` | 与密钥扩展的"字（word）= 4 字节"结构对齐，学生一眼能把字和字节对应起来 |
| 字距 | 格内 `0.06em`；长串 `0.02em` | 2 位数字在 1px 边框内需要呼吸；长串字距过大会破坏"一个整体值"的感知 |
| 数字形态 | `font-variant-numeric: tabular-nums` **强制开启** | 滚动替换时不发生宽度跳动 |
| 0/O、1/l 区分 | 靠字体字形（Plex Mono 原生区分），**不加斜杠、不额外标记** | 斜杠 0 在 16px 下会变成噪点 |
| 十进制辅助 | `--fs-micro` + `--ink-3` + 前缀标签 `dec`，**用不同字号而非不同颜色** | 同色不同大小 = 层级；不同颜色 = 语义，会把辅助值误读成"有含义的状态" |
| 换行 | **禁止**。溢出用 `text-overflow: clip` + 悬停 inspector | 半个字节换行是本产品最致命的视觉错误 |

两套都是 **8 个值、严格单调**。`[data-mode="present"]` 与 `[data-density]` **正交**，可叠加。

**密度归属规则（定稿，替代"整页一刀切"）**：**density 由页面容器决定；页面内嵌的密集组件可以单独覆盖 `--cell-size` 桶与 spacing，但不得改变页面级 `--sp-*` 与 `--fs-body`。**

| 页面 / 场景 | 页面级 density | 内部覆盖 |
|---|---|---|
| 工作台 PG-2 | `compact` | — |
| 首页 PG-1 | `roomy` | — |
| 练习 PG-6 | `roomy` | 错因定位嵌入的小矩阵 → **compact 的 cell 桶**（44/52/62/72），间距仍走页面级 roomy |
| 单步训练 PG-7 | `roomy` | 矩阵 → compact 的 cell 桶 |
| 学习记录 PG-8 | `roomy` | — |
| **S 盒浏览器 PG-3** | `roomy`（**仅外壳**：标题 / 搜索 / 说明） | **16×16 表格本体走 `compact`** | 
| 密钥扩展全屏 PG-4 | `roomy` | 44 字纸带走 `compact` |

**为什么 S 盒浏览器不能整体判 roomy**：16×16 = 256 格，在 roomy 的 `--sp-3:16 / --sp-4:24` 下整表宽高会直接超出 1280×720 的可视区。它和 PG-6 的错因矩阵是同一条规则的两个用例——**外壳宽松、数据密集处收紧**。

实现上只需在组件根写 `data-density="compact"` 覆盖即可，不新增 token 集。

**节奏规则（3:1 原则）**：组内 = `--sp-2`，组间 = `--sp-6`，**永不出现 20 / 28 / 40 这类中间值**。视觉上的"呼吸"靠"组间 24 / 组内 8"的 3 倍差，而不是靠加大整体留白——高密度界面里加大留白只会让屏幕装不下。

### 4.4 AI 栏收起（F 键）：栅格伸缩的正确做法

- **不做宽度动画。** `grid-template-columns` 或 `width` 过渡会在 280ms 内每帧重排 16 个格，正是性能红线禁止的事。
- 正确做法：`C 区 opacity 120ms → 0` → 换栅格（一帧）→ `opacity 120ms → 1`。总 240ms，观感比 280ms 宽度动画更快，像仪器换量程。
- 字节格尺寸用**离散桶 + 容器查询**，**不用连续 `clamp`**：

```css
/* ── 常规档：跟随 stage 宽度（AI 栏收起时矩阵变大是期望行为） —— 上界锁死 72px ── */
--cell-size: 44px;
@container stage (min-width: 520px) { --cell-size: 52px }
@container stage (min-width: 640px) { --cell-size: 62px }
@container stage (min-width: 780px) { --cell-size: 72px }
/* 88px 在普通模式永不可达：1366×768 下 4×72 + 3×6 = 306px 已是矩阵区上限，
   再大就要挤掉轮密钥轨。这条用"常规档最高只有 780px 断点"表达，不靠注释。 */

/* ── 演示档：只跟视口，不跟 stage ── */
[data-mode="present"] .c-matrix__grid { --cell-size: 72px }        /* 降档（<1120px） */
@media (min-width: 1120px) {
  [data-mode="present"] .c-matrix__grid { --cell-size: 88px }      /* 主档（≥1120px） */
}
```

**为什么演示档用视口媒体查询、不用容器查询**：容器查询会让格径取决于 AI 栏是否收起——教师讲课时一按 `F` 收起 AI 栏，矩阵格突然从 72 跳到 88，投影画面跳一下，这恰恰是投屏最不能有的。**演示态要的是"整节课尺寸不变"**，所以绑视口（讲到一半不会去改窗口大小）。

**为什么不做 88 / 76 两档**：两档只差 12px，在 1m 观看距离下肉眼几乎不可辨，等于白增一个状态；而 1120px 以下的投影场景本来就少见。**回落 72px 一档解决。**

**W4 可执行判据（第 11 项）**：
> 演示态且视口宽度 **< 1120px** 时 —— `.c-matrix__grid` 的计算 `--cell-size` === `72px`，且 16 个格在同一行内排满 4 列、`scrollWidth === clientWidth`（无横向滚动条）、无换行。
> 演示态且视口宽度 **≥ 1120px** 时 —— 同上但 `--cell-size` === `88px`。
> 两档都必须：`document.querySelector('.c-matrix').scrollWidth <= clientWidth`。

理由：连续 `clamp` 在换档那一帧会算出十几档中间尺寸，等于每帧强制重排 16 个格；离散桶只跳一档。

- 收起后 E 区 48px 竖条内保留：竖排标签 + 提问图标 + **方框内的数字角标**（不用圆点，圆点是 slop 语言且与时间轴诊断标记语义冲突）。

## 5. 动效语言

### 5.1 时长与缓动档位

**缓动必须是纯减速 / 对称曲线，`cubic-bezier` 的 y 值必须落在 [0,1]**（禁止过冲 = 禁止回弹 / 弹性 / 弹簧）。

```css
--e-out-quart:    cubic-bezier(0.16, 1, 0.30, 1);   /* 值替换、状态切换、入场 */
--e-out-quint:    cubic-bezier(0.22, 1, 0.36, 1);   /* 叙事型出场（批注） */
--e-in-out-cubic: cubic-bezier(0.65, 0, 0.35, 1);   /* 对称位移（行移位） */
--e-step-4:       steps(4, end);                    /* 离散跳变（XOR） */
--e-linear:       linear;                           /* 扫描线、时间轴 */
```

| Token | 时长 | 缓动 | 用于 |
|---|---|---|---|
| `--d-1` | **80ms** | out-quart | hover / press / focus 微反馈 |
| `--d-2` | **160ms** | out-quart | 状态切换、inspector 淡入、AI 段落入场 |
| `--d-3` | **280ms** | in-out-cubic（位移）/ out-quart（数值） | 行移位、列混合扫描、**单步核心动效** |
| `--d-4` | **420ms** | out-quint | 诊断批注出场、面板开合、聚焦跳转 |
| `--d-linger` | **1200ms** 保持 + **600ms** 淡出 | linear | 变化痕迹保留后归位 |
| `--d-stagger-*` | 20 / 40 / 60ms | — | 错峰（见 §5.3） |

### 5.2 核心动效：一个字节从 A 变成 B

四个设计约束：**格子本身绝不位移**（16 格网格一抖就崩）、**宽度绝不变化**（tabular-nums）、**不做缩放**、**颜色变化必须留痕但必须退场**。

| 层 | 动作 | 参数 |
|---|---|---|
| ① 数值 | **垂直滚动替换**：旧值 `translateY(0 → -100%)` 淡出，新值 `translateY(100% → 0)` 进入，格内 `overflow: hidden` 裁剪 | 280ms `--e-out-quart` |
| ② 底色 | **荧光笔扫过**：`linear-gradient(90deg, var(--st-changed) 0 100%)` 的 `background-size` 由 `0% 100%` → `100% 100%`，方向从左到右 | 280ms `--e-out-quart` |
| ③ 顶条 | `box-shadow: inset 0 2px 0 var(--st-changed-bar)` 淡入（不占布局、不产生 0.5px 抖动） | 160ms |
| ④ 角标 | 右上角 3px 实心琥珀角标淡入 | 160ms |
| ⑤ 退场 | 该格不再变化后保留 **1200ms**，然后底色 / 顶条 / 角标在 **600ms** 内淡回 A 态 | `--d-linger` |
| ⑥ 文字 | **字重瞬时切换**：加粗（500 → 600）与数值滚动**同帧发生**，不进动效序列；退场时同样瞬时回 500 | 0ms（离散） |

> **字重为什么不做过渡**：字节格用的是 IBM Plex Mono，**静态字重**（非可变字体），`font-weight` 在静态字重间不可插值——CSS 会退化成离散跳变，写不写 `transition` 都一样。要真做 280ms 字重插值必须换成可变字体栈，为一次 16px 数字加粗付出字体体积与 FOUT 风险不值得。**视觉上就是一次干净的瞬间加粗，反而更像仪表跳数。**

**不做的事**：不做翻牌 3D、不做 `scale` 弹一下、不做格内发光、不做边框加粗到 2px（会挤动内边距）、**不做字重补间**（见上）。

### 5.3 四种操作的差异化动效（必须可被一秒识别）

四种操作**各占一条独立的视觉通道**，互不重叠：

| 操作 | 通道特征（一句话识别） | 具体参数 |
|---|---|---|
| **字节替代 SubBytes** | **点状、逐格、吸收** | 每格走 §5.2 全流程；`scaleY 0.94 → 1` 60ms（像被"压入盒中"）；**列优先 stagger 20ms/格**（0→3 列，每列 0→3 行）；**同步在 S 盒面板画十字准星**：1px `--accent` 的横线 + 竖线，在交叉格闪烁后 120ms 淡出。这是全局教学价值最高的一处联动 |
| **行移位 ShiftRows** | **整行横向位移（全站唯一的横向位移）** | **位移主体是 DOM 行轨**：每行一个 `.c-row` 包裹层做 `transform: translateX`，`overflow: hidden` 按格裁剪，移出左边界的字节用两个副本首尾相接完成回绕。280ms `--e-in-out-cubic`；第 r 行左移 r 格；**行序 stagger** row0 0ms / row1 40ms / row2 80ms / row3 120ms。**Canvas 只负责回绕瞬间那道 1px 描边闪（60ms）**——理由见 §5.9 图层分工 |
| **列混合 MixColumns** | **整列同步 + 垂直扫描线（全站唯一的竖向扫描）** | 同列 4 格**零 stagger 同步**变化（与 SubBytes 的点状错峰形成强对比）；该列上方落下一条 `1px × 列宽` 的计算线，从上到下扫过 4 格，280ms **linear**；扫过后整列叠 `--accent-soft` 12% → 0（600ms 淡出）；**列序 stagger 60ms**（col0→col3），总 460ms（一轮里最重的一步，允许更长） |
| **轮密钥加 AddRoundKey** | **叠加层 + 离散跳变（全站唯一不对数字用平滑滚动）** | ① 16 个轮密钥字节以 60% 不透明度"贴"到矩阵格上（120ms 淡入）；② 格子底色纸 → 石墨（160ms）；③ 数值用 **`steps(4)` 80ms 离散跳变**（仪表数字跳，表达"XOR 是瞬时位运算，不是过渡"）；④ 密钥层 120ms 淡出；⑤ 斜纹 hatch 随密钥层一起进出 |

**总结成一句给评审的话**：点状错峰 = 替代；横向平移 = 移位；竖向扫描 = 混合；离散跳变 + 叠加 = 异或。四条通道没有一条重复。

### 5.4 播放节奏与动画时长**解耦**（关键 token）

> **`--step-interval: 800ms`**
> 映射：`--step-interval: calc(800ms / var(--speed))`，speed ∈ {0.5, 1, 2} → **1600 / 800 / 400ms**（若后续增加 4× 档则为 200ms）

单步动效**固定 280ms**；播放速度**只改步间隔**，不改动效时长。

理由：拉长动画曲线会让位移在低帧率投影上累积抖动，且"慢动作"在教学中反而看不清哪一步在动；**慢速时看到的是清晰的停顿，不是慢放的抖动**。

**倍速与 C2 摘要句的联动规则（易漏）**：

| 倍速 | C2 变化摘要句的更新动效 |
|---|---|
| 0.5× | **必须保留** 160ms `--d-2` 淡入。慢速时这句话是主要阅读对象 |
| 1× | 保留 160ms |
| **2×（400ms/步）** | **必须去掉全部更新动效，直接换文**。每秒变 2.5 次文字，任何 transition（哪怕 80ms）都会糊成噪点，反而比不加快 |
| 4×（若实现） | 同 2× |

这条也是动效归零后"节奏不丢失"的实现基础（见 §5.8）。

### 5.5 时间轴拖拽的预览动效原则

> 拖拽期间**禁止播放任何单步动效**。

- 拖拽中：直接**快照替换**（≤2 帧），只在两处给连续反馈：
  1. 时间轴游标改**空心**（2px 描边不填充）——这是"预览 vs 执行"的第二通道，不靠颜色；同时轨道右侧出现文本 `浏览中`。
  2. 矩阵区整体 `opacity: 0.92` + 叠一层极淡横纹（`repeating-linear-gradient` 3px/3px，α 0.03），暗示"预览 / 非确定态"；松手后 120ms 内恢复。（演示态禁用此横纹，改 2px 虚线外框）
- 拖拽停住 **≥300ms** 后，才允许该步动效**重播一次**（280ms），作为"这一步做了什么"的确认。
- **性能红线**：拖拽中禁止触发 AI 请求、禁止写诊断历史、禁止 Canvas 重排尺寸。

### 5.6 AI 流式回答呈现

- **不做假打字机**（已经有真 SSE，再叠打字机会造成双重节奏）。
- 流式原则是**稳定的行增长**：token 直接 append；容器 `min-height` + 底部 **24px 保留区**，避免每帧高度抖动。
- **段落级入场**：每个 markdown 块（段落 / 列表 / 公式）**首次出现**时 `opacity 0→1` + `translateY(4px→0)`，160ms `--e-out-quart`；块**内部**的 token 零动画。
- **光标**：不是闪烁竖线，而是 **2px × 1em 的实心方块**，`steps(2)` 1.2s 闪烁——仪器"待机"感，比圆润光标冷。
- **引用真实数值**：`--font-mono` 13px + `--surface-inset` 底 + 左侧 2px `--accent` 竖线 + 1px 下边框（可点击提示），**不做代码块样式**（代码块 = 开发者工具语义，这里是"引文"）。
- **流式结束**：不弹跳、不缩放，只在最后一行末尾淡入一条 **16px 宽 1px 短横线**，400ms 后淡出 = "封口"。
- **跟随策略**：仅当滚动位置在底部 48px 内才自动跟随；否则显示底部一条 24px 的"↓ 新内容"小条（1px 边框，无圆角），点按才回到底部。
- **缓存命中**：**整段同时出现**，不做任何流式模拟（假流式会让用户以为在生成），并在消息头加文本标签 `来自常见问题`。

### 5.7 诊断批注的出场（记忆点，「红线批注」）

**位置**：AI 辅导栏顶部 **40px 常驻批注位**（演示态 56px）。该位**即使无提示也占位**（显示 11px `DIAGNOSTIC —`），原因：出现时才插入会推动对话流产生位移，违反"不遮 / 不打扰"的实施意图。

**形态**：静止的 2px 红竖条 + 手绘感三笔方括号 + 一句反问 + 三选项（是 / 不是 / 这提示不对）+ 右上角 × 。**不是 toast、不是气泡、不居中、不遮任何内容。**

时间线（总 420ms）：

| 时刻 | 动作 | 参数 |
|---|---|---|
| 0–120ms | 目标字节格边框被一条 **1.5px `--st-error`** 线逐边描出（SVG `stroke-dashoffset` 顺时针） | 120ms `--e-out-quart` |
| 0–420ms | 批注位内：2px 红竖条 + 方括号 + 文本 `opacity 0→1`、`translateY(2px)→0` | 140ms `--e-out-quint`（延迟 280ms 开始） |
| 120–200ms | AI 栏左分隔线上出现 **12×2px 红刻痕**，y 对齐目标格中心 | 80ms `--e-out-quart` |
| 保持 | 批注**完全静止**：不呼吸、不脉冲、不闪烁、不抖 | — |
| 关闭 | 点 × 或已作答 → `opacity→0` **200ms**，**不做退场位移**（避免"被抽走"的失重感） | — |

**克制条款（写进验收）**：
1. 同一时刻**最多 1 条**批注；
2. 两条之间至少间隔 **45 秒**；
3. 仅在页面**空闲 20s**（无输入、无拖拽、无播放、AI 未流式）后才允许出现；
4. **不抢滚动、不禁用交互、不自动聚焦输入框**；
5. 批注**永不使用循环动画**（原 v1.0 的"竖线 1.8s 循环生长"已删除：它在公用教室电脑上会持续占合成层，且违反"批注必须静止"）；
6. 首次出现时，批注下方 8px 处给一行 11px `--ink-3`：`这是系统的推测，不是判错`——这句话决定了它是"老师"还是"监考"。

### 5.8 `prefers-reduced-motion` 与页内开关：归零后信息不丢失

页内开关位置：**账户菜单 → 动效：标准 / 精简**，默认跟随系统。`[data-motion="reduced"]` 与 `@media (prefers-reduced-motion: reduce)` 走同一段 override。

```css
@media (prefers-reduced-motion: reduce), [data-motion="reduced"] {
  --d-1: 0ms; --d-2: 0ms; --d-3: 0ms; --d-4: 0ms;
  --d-linger: 0ms; --d-fade-linger: 0ms;
  /* --step-interval 故意不动：节奏必须保留 */
}
```

**归零后的静态替代（信息不能丢）**：

| 场景 | 归零后 |
|---|---|
| 变化字节 | 直接换终值 + **右上角 3px 实心琥珀角标常驻**（不是 1.2s 后淡出——无动效时"哪个变了"只能靠静态标记） |
| 行移位 | 不位移，格内显示文本旋转量 `←1` / `←2` / `←3`，内容已按移位后顺序呈现；该行底 2px 琥珀条 |
| 列混合 | 不扫描，列括线变 2px `--accent` + 列顶文本标签 `MIX` |
| 轮密钥加 | 不跳变，格内出现 `⊕` 上标 + 密钥轨对应字同高亮 |
| 播放节奏 | `--step-interval` 不变，节奏感仍在 |
| 循环动画 | 全站零循环动画（常态即如此） |

**给前端的硬技术点**：归零不能只把 `--d-*` 设为 `0ms`。`stroke-dashoffset` 类动画在 `transition-duration: 0` 下可能停在中间值（描边留半截），必须同时 `animation: none` 且 `el.getAnimations().forEach(a => a.cancel())`。

### 5.9 性能红线：不要动的属性

| 禁止 | 原因 / 替代 |
|---|---|
| `width / height / top / left / margin` | 触发 layout。用 `transform`，或直接重绘 Canvas |
| `box-shadow` 的模糊半径 | 每帧重绘阴影是最大开销。用 `inset` 实心条或 1px 边 |
| `filter: blur()` / `backdrop-filter` | 全站禁用（也是 slop 特征） |
| 大面积元素的 `background-position` | 只允许在 **≤24px** 的字节格内做（扫光 / 斜纹） |
| 常驻 `will-change` | 只在 `.is-playing` / `.is-dragging` 期间加，结束即移除 |
| 同帧动画元素 > 64 个 | Canvas 一次重绘优于 64 个 DOM transition |
| **16 个字节值各自用 DOM transition** | 本项目最易踩的坑。**必须同一个 rAF 批处理**驱动 16 个格子的 transform |
| 栅格宽度的过渡动画 | 见 §4.4，改用 opacity 淡出换挡 |
| 判分错误的 `shake` 抖动 | 消费级语言，且在高密度网格里引起误读。用描边 + 折角替代 |

**图层分工（v1.1 定稿，三条修正已并入）**

| 层 | 负责 |
|---|---|
| **DOM** | 16 个字节数值与交互、**行移位位移**、**网格 1px 基线**、S 盒行列高亮线 |
| **Canvas** | 列混合竖向扫描线、行移位回绕瞬间的 1px 描边闪、其他**会动的**几何 |
| **SVG** | 静态结构与连线——列括线、批注刻痕、四角刻线、S 盒十字准星 |

**三条修正的理由（不是渲染成本，是可读性）**：

1. **行移位位移归 DOM 行轨，不归 Canvas。** Canvas 逐帧平移会让 16 个 hex 数字在 280ms 内全程亚像素模糊（`fillText` 无 subpixel 对齐），而后端 `waitKeyframe` 必须等位移结束才能写终值释放锁——也就是说这 280ms 里矩阵是糊的。**这不是性能问题，是清晰度问题：本产品的核心资产就是"数字可读"。**
2. **网格 1px 基线归 DOM。** dpr 为 1 或非整数（125% / 150% 缩放）时，Canvas 的 1px 线会落在 0.5px 上，渲染成 1.5–2px 的灰线，且不同缩放下粗细不一致——"发丝线"这个主力分区语言会在别人的电脑上直接失效。DOM 的 `border` / `linear-gradient` 由浏览器做像素对齐，各缩放一致。
3. **字重不补间。** 见 §5.2。

**两个已知取舍**：
- DOM 基线在 `resize` / 主题切换时无需重绘（浏览器负责），代价是像素对齐只能到整数 px——这正是我们要的。
- Canvas 保留下来的三件事（扫描线、回绕闪线、其他动态几何）本来就允许亚像素（它们是"运动模糊"语义），所以不存在清晰度损失。

16 个 DOM 节点的 `transform` **不是**性能问题；把 hex 文字画进 Canvas 导致亚像素模糊 + 无法选中，才是真正的问题。

### 6.1 字节格 Byte Cell

| 项 | 规格 |
|---|---|
| 尺寸 | 离散桶 44 / 52 / 62 / 72px（容器查询，见 §4.4）；演示态 `88px` |
| 间距 | `6px`（演示态 `10px`） |
| 圆角 | **2px**（上限 3px）。理由：接近直角才有仪器丝印感；完全 0 圆角在低 DPI 投影上会被看成缺角 |
| 边框 | 1px `--line-default`；**无外阴影、无内阴影**（除 B 态 `inset` 顶条） |
| 文字 | `--font-mono` 500 / `--fs-byte` / `letter-spacing: 0.06em` / `tabular-nums` / 居中 |
| 状态 | 见 §2.3；纹理与角标是**叠加层**，可与底色共存 |
| Hover（80ms） | 边框 → `--line-strong`；格内右上角出现 4px 的 1px 小十字（"可测点"）；`transition-delay: 240ms` 后在格**下方 6px** 浮出 inspector 数据条 |
| Inspector 数据条 | **不是气泡**。`--surface-raised` 底、1px 边框、**3px 圆角**的 2 行条：`dec 197` / `0xC5 · 1100 0101 · ASCII Å`（`--fs-micro` mono `--ink-3`），一条 1px 竖线连回该格上边缘。**无箭头、无三角、无阴影扩散**（全站仅此与批注可用 `--shadow-float`） |
| 选中 | `border-color: --accent` + `inset 0 0 0 1px --accent` + **外 3px `--accent-ring`**（**不用四角刻线**，见 §2.3.1 撤除理由）；inspector 从 hover 态**钉住常驻** |
| 焦点（键盘） | `outline: 2px solid var(--accent); outline-offset: 2px; box-shadow: 0 0 0 4px var(--paper-0)` —— 这是一条**双环**：内环贴格边、2px 纸色空隙、外环在最外。**焦点不用角标 / 刻线通道**，靠"双环 + 空隙"这个结构本身与选中态的单层外环区分（选中的环距格边 3px、且无空隙；焦点环距格边 2px 起、中间夹 4px 纸色）。两者同时成立时（刚被判错又刚被 Tab 聚焦）结构仍然可分，不需要第三种符号 |

#### 6.1.1 角标四角分配（硬规则，防未来撞车）

一个格子上最多会同时出现 3 个角标（反向单步 + 已变化 + 错误），必须先定死位置，否则每加一个状态就要打一次架。

| 角位 | 唯一归属 | 形状 |
|---|---|---|
| **左上** | 反向单步 `is-reverse` | 6px `◀` |
| **右上** | 已变化 `is-changed` | 3px 实心琥珀方块（演示态 4px） |
| **右下** | 错误 `is-error` | 6px 红折角三角 |
| **左下** | 已完成 `is-done` | 5px 缺口（**纸色方块压上去**，不是 border 断开） |

**DOM 只需要 2 个角位元素，不是 4 个**（r5 补正，原先写了 3 个专用元素 `__flag` / `__fold` / `__notch`）：

```html
<span class="c-byte__corner" data-corner="tr" aria-hidden="true"></span>
<span class="c-byte__corner" data-corner="br" aria-hidden="true"></span>
```

- **为什么是 2 个**：纪律 1 规定同格最多 2 个角标，**DOM 上限就配 2 个**——另外两个角永远不会同时出现，多建一个节点是留给未来出错的余地。位置由 `data-corner="tl|tr|br|bl"` 驱动，形状 / 颜色 / 尺寸全部按角位查上面那张表。
- **不要退回"3 个专用角位节点"**（fe 问的"合并是不是漏"）：**不是漏，是合并**。专用节点（`__flag` / `__fold` / `__notch`）只有在"同一个角要同时放两个东西"时才需要多一个节点——而纪律 1 已经把"同角不共存"钉死了，所以专用节点永远有一个是空的。**通用节点 + `data-corner` 是正确形态**，条件是下面这一条必须做到。
- **角位重排必须是同一帧内原子完成**（这是 2 个通用节点的唯一技术代价）：一格从「左上 + 右上」变成「右上 + 右下」时，两个元素的 `data-corner` 要在**同一次 DOM 写入里改完**（同一次 `patch` / 同一个 `requestAnimationFrame`），**不许一处一处地改**。分开改会出现中间态：两个元素短暂都挂着 `tr`（或短暂都不挂），表现在投影上就是**角标"飞过去"或者闪一下**——16 格矩阵里一次判分要重排 15 格，会连成一片抖动。验收：切判分上下文时逐帧截图（或用 `MutationObserver` 断言一趟里 `data-corner` 的变更次数 ≤ 角标数 × 1）。
- **为什么缺口用"纸色方块"而不是 `border` 断开**：`border-style` 断边会随 `border-color` 变化而失效（`downstream` 降级、判分上下文换环色都会碰到边框），而**一块 5×5 的 `--paper-0` 方块压在边框上**与边框色完全解耦，任何状态下都成立。同理，`is-done` 的缺口和 `is-downstream` 的降级可以同时存在而不互相破坏。

**四条纪律**：

1. **同一格最多 2 个角标**。三个以上说明这一格的语义已经过载，应当拆分到"字节抽屉"里表达，而不是继续往格子上堆。
2. **新增角标必须先申请一个空位**。四角已满即视为"不再接受新角标"，新状态只能走底色 / 边框 / 文本通道。
3. **任何标记不得进入格心**。格心是 hex 数值，被占即不可读——这是本产品最硬的一条。`⊕`（密钥加）与 `≠`（错误）都是**上标**，定位在"格外 2px"而不是"格内居中"。
4. **角标尺寸不随格径等比**，按公式取整：
   `--flag-size: clamp(3px, calc(var(--cell-size) * 0.045), 4px)`
   → 62px 档 = 3px、72px 档 = 3px、88px 档 = 4px。折角三角与缺口按 `--flag-size * 2` 取值（6 / 6 / 8px）。
   理由：等比放大到 88px 时 3px 角标只有 3.4%（太小），缩到 44px 时又会有 5%+（太大），必须钳位。

### 6.2 状态矩阵容器

- 4×4 `display: grid`，`gap: 6px`，**不做旋转、不做透视**（AES 状态矩阵就是平铺 4×4）。
- **列优先的视觉暗示（不许用文字解释，这是最容易被忽略的教学点）**：
  1. 列标签 `c0 c1 c2 c3` 放在**上方**（12px mono `--ink-3`），行标签 `r0–r3` 放在**左侧**——标签主次位置本身说明"列是主索引"；
  2. **每列外侧一条 1px 竖向括线**，四列各自成为一条"竖条"。最强的一招：16 个方格先被读成 4 条竖条，而不是 4 条横条或 16 个独立方块；
  3. 列括线在"列混合"步骤中，被操作的整列变 2px `--accent`；
  4. 顶部一条 1px 横线 + 4 个 8px 短刻度，对齐四列中心。
- 容器本身：**零底色、零边框、零阴影**，只在"当前活动区"时给四角 6px 刻线。
- 轮次标识：`ROUND 3 / 10` — `--font-mono` `--fs-micro` uppercase `letter-spacing: 0.10em` `--ink-3`，位于矩阵左上角上方 8px。
- 摘要句（C2）：**默认只给一句话**（`本步 16 个字节中 4 个被替换：下标 0、5、10、15`）+ 一个 `逐字节 ▸` 行内展开器。默认展示 16 组 hex 对照会把矩阵淹掉。

### 6.3 时间轴控件（4 条轨道，详细尺寸图）

这是全站密度最高的控件：要同时承载「轮分段 / 轮号 / N 个步刻度 / 诊断标记 / 提问标记 / 当前位置」6 件事。**唯一可行的解法是分轨（垂直分工），不是分色。**

#### 6.3.1 D 区总高度（三档，不含"加高"）

| 组成 | 常规 | 常规·压缩档<br>`@media (max-height:780px)` | 演示 |
|---|---|---|---|
| 控制行 | 40px | **36px** | 52px |
| 时间轴区 | 64px | **56px** | 84px |
| **`--transport-h` 合计** | **104px** | **92px** | **136px** |

压缩档内部：轮号带 16→**14**、刻度轨 10→**8**、标记轨 20→**18**、游标行 14→**12**，四个 padding/gap 全部 ≥1px。

**压缩档的硬规则：任何断点下不得减少轨道条数。** 轨道是这类控件的结构，压掉一条就丢一类信息（压掉轮号带 → 学生不知道在第几轮；压掉标记轨 → 学习足迹消失）。压缩只允许"减高度"，不允许"减通道"。

在 1280×720 极限视口下：`720 − 56(A) − 92(D) − 24(内边距) = 548px` 给 B/C/E；矩阵 4×52 + 3×6 = 226px 装得下，且 C 区仍能保留步标题 + 摘要句 + 密钥轨。

#### 6.3.3 各轨道规格

**① 轮号带（替代色相区分）**

| 项 | 常规 | 演示 |
|---|---|---|
| 段底交替 | 偶数轮 `--paper-0` / 奇数轮 `--surface-inset`（ΔL 0.036） | `--paper-0` / `oklch(0.900 0.004 250)`（**ΔL 0.10**） |
| 段间分隔 | **2px `--line-strong`**（段内步之间**不画线**） | 2px `oklch(0.545 0.012 258)`（4.6:1） |
| 轮号文本 | 11px mono `--ink-3`，段内居中 | 13px `oklch(0.415 0.012 258)` |

> **为什么不用色相分轮**：8–14 种色相在色盲与投影下都不可辨，且色相一多就变成"彩虹条"，正好落在 slop 的语言里。轮边界由「2px 线 + 明暗跳变 + 轮号文本」三重冗余定位，灰度化后仍成立。

**② 刻度轨**：每步一条 1px 竖刻度（常规高 6px / 演示 6px），轮边界刻度 **2px 宽、高 10px**。**步数与轮数由 trace 数据驱动，UI 不写死 24 或 40。**

**③ 标记轨（上下列轨，不合并；形状携带语义）**

| | 诊断标记 | 提问标记 |
|---|---|---|
| 位置 | 标记轨**上沿** | 标记轨**下沿** |
| **形状** | **5px 实心圆**（演示 6px） | **5px 实心方**（演示 6px） |
| **语义** | 一个**时刻**——"我这一刻卡住了" | 一次**关注**——"我在这一步问过" |
| 颜色 | `oklch(0.545 0.195 27)`（错误语义的深色，但形状不含错误含义） | `--accent` |
| 叠加 | 同一 x 上圆在上、方在下，**互不合并** | |
| 层级 | 标记轨内 **z=3，高于游标** | 同左 |
| 命中热区 | **一步一个热区**：整列宽 × 标记轨全高（常规 20px），**上下两个标记共用一个 `<button>`** | 同左（不是两个热区） |
| 键盘 | `tabindex`（roving），`[` / `]` 跳到下一个**有标记的步**，见 §6.3.5 | 同左 |

**为什么是圆 / 方，而不是"圆 / 短横条"（这条曾被提出又撤回，理由值得记下来）**：短横条在语义上更漂亮（一个时刻 vs 一段关注），但它和**正上方的 ② 刻度轨**打架——刻度轨已经有"1px × 6px 竖刻度"，在 AES-256 的 58 步场景里，短横条会被压到 10×2px，与竖刻度混读成"又一种刻度"。**形状方案必须与相邻轨道已有的语汇共存**，这是比语义对齐更硬的约束。

而短横条原本的两个优势（宽度通道、语义对齐）已经被另外两个机制覆盖：**位置通道**（上 / 下轨）解决区分，**图例**解决解释。剩下的只有成本。

**为什么热区是"一步一个"，而不是"一标记一个"（r5 改动，前两版都错）**

时间轴上同一步可以同时有圆和方（叠加行）。所以"一标记一个热区"这条路上只有两个选择，**都不成立**：

| 方案 | 为什么不成立 |
|---|---|
| 两个热区各"整列宽 × 20px" | 两个**完全重合**的矩形，只有 z 高的那个点得到；键盘更糟——按两次 Tab，焦点环画在同一个方框上，用户会以为"焦点没动" |
| 两个热区各"整列宽 × 10px"（上下半区） | 不重合了，但**两个都不满足 24px 间距判定**：上半区 y0–10 与下半区 y10–20 上下相接，以 A 的 bbox 中心（y5）为心、半径 12px 的判定圆覆盖 y −7…17，与 B（10…20）必然相交；反向同理。**不是"各让一半"，是两个都不达标** |

**正解：一个 `<button>` 承担整列宽 × 标记轨全高，两个标记是它内部的两枚 `<i class="c-mark__shape">`（**不是伪元素**——图例要原样复用同一枚元素，伪元素只能复用规则，见 §6.3.4）。**

- **不重合**：一步只有一个热区，垂直方向上下都是非交互轨道带（② 刻度轨 / ④ 游标行），满足 spacing 例外；
- **意图不分流**：在时间轴这一层，用户想表达的是"这一步有标记"，**不是"我要精确点到那个圆"**。要选具体哪一条，进 E 区标记卡——卡里按类型分组列出每条，每条自己可点、可聚焦、高度 28px **单独达标**；
- **Tab 站更少**：58 步里被标记过的步通常只有 3–8 个，键盘用户走完标记组只需 3–8 次，而不是"标记条数"次。

**24×24 在 58 步时物理上不可能（列宽约 10px），因此走 Equivalent 例外——代价是三条等价路径必须真的实现：**

1. `[` / `]` 逐标记跳转（跨步跳，同一步不重复停留）；
2. 时间轴滑块 `←` / `→` 到任意步（含无标记步）；
3. E 区卡内每条标记可点、可聚焦、28px 高。

**删掉任一条，例外即刻失效。** 这一条既是解释，也是 W4 的可执行验收项。

**为什么方块不横跨整列**：若标记横跨整列，相邻两步的形状会首尾相接成一条连续线，读不出"一格一个"。**但命中热区仍然是整列宽**——视觉效果与靶子大小不必一致。

**热区宽度绝不写死像素**：列宽是数据驱动的（24 步 ≈ 25px、58 步 ≈ 10px），写死 12px 在 58 步下会跨到相邻步，出现"点第 13 步落到第 14 步"。热区取**该步列容器的 100%**，列容器由 `--i` 与 `--step-w` 定位。

**为什么标记 z 高于游标（修正 v1.1 初稿的错误）**：原方案是"游标压住标记时标记左移 1px 露出"，但 2px 游标 + 5px 标记、左移 1px 只露 1px 边，等于没露。改为标记 z=3 压过游标——**游标的当前位置已经由"游标行 + 步号文本 + 矩阵内容"三重表达，标记轨内不需要它再抢占层级**。

> **为什么不合并成一条**：4–5px 尺寸下形状通道本身就弱（色盲无影响，但投影缩放 + 1m 观看距离下基本不可辨）。把差异挪到**位置通道**（上 / 下）后形状只作辅助；且叠加时不必发明第三种形状——任何"合并后怎么表达两个语义"的方案都比"两个都在"更绕。代价是标记轨 20px、transport 104px，这个代价已确认接受。

**④ 游标行**

- 游标本体：**2px × 46px** `--accent` 竖条，纵向贯穿 ①–③（常规 y=2–48；演示 2px×54px，y=4–58）。
- 步号：游标正下方 11px mono `13 / 24`（演示 13px），距游标 4px；靠近左右端点时**翻转到游标另一侧**并做 8px 内缩，永不出界。
- **拖拽态：游标改空心**（2px 描边、不填充）——"预览 vs 执行"的第二通道，不靠颜色；同时轨道右侧出现文本 `浏览中`（11px，`--surface-raised` 底 + 1px 框）。
- **末步**：游标右端加 4px 短横帽；播放键图标换成「重播」（形状差异）。
- **未生成**：整条轨道 **2px 虚线外框** + 中央文本 `生成后显示 N 步`（**不用降低透明度当唯一信号**）。
- **冲突优先级**（游标 / 标记 / 轮边界落在同一 x）：**标记 z=3 > 游标 z=2 > 轮边界线 z=1**。理由见 §6.3.3。轮号带与标记轨垂直不重叠，所以"轮分段"永不被遮挡。

#### 6.3.4 图例规格（team-lead 硬要求，交付时验收）

**用户第一次看到上下两排标记，必然不知道分别是什么。必须给图例，不许让用户靠猜。**

| 项 | 规格 |
|---|---|
| 位置 | **控制行右端**（不在时间轴行内，避免与标记抢垂直空间），距右内边距 12px，垂直居中 |
| **共享槽位** | 该位置是一个**共享槽位**（`--tl-hint-slot: 188px` 定宽）：<br>· 时间轴**聚焦时** → 显示键盘提示 `← → 单步，PgUp/PgDn 跳轮`（11px `--ink-3`）<br>· 其余时间 → 显示图例<br>· **两者永不同时需要，也永不并排**，且**都不新增行高**<br>· **两个内容节点都常驻 DOM**，切换只改可见性：图例节点换成 `.sr-only`（`clip-path` 视觉隐藏）、键盘提示节点 `hidden` 取消。**图例节点绝不允许消失**——它是时间轴 `aria-describedby` 的目标，目标一消失，读屏就什么也听不到。**"消失"有四种写法，症状完全一样，四样都要禁**：`display:none`、`visibility:hidden`、`hidden` 属性（它还能被 CSS 的 `display` 规则覆盖回去，是最容易误用的一个）、`aria-hidden="true"`（最隐蔽：节点还在渲染树里、`getBoundingClientRect()` 也正常，但 describedby 一样读不到） |
| **读屏可达（双断言验收）** | 聚焦时间轴滑块后，对图例节点同时断言两条：① `getComputedStyle(el).display !== 'none'`；② `el.getBoundingClientRect().width > 0`。`.sr-only` 应得 **1px**——**若得 0，说明被 `clip` / `clip-path` 裁成零尺寸**，等于又消失了一次。这条必须做成自动化，因为"眼睛看得见"和"读屏读得到"在这里是两件事 |
| 内容 | `系统推测` 与 `我的提问` 两项**左右并排**，每项 = 一个高 `var(--tl-mark-band)`（常规 20px / 演示 24px）的**定高盒** + 4px + 11px `--ink-3` 文本（文本在盒内垂直居中），两项之间 16px。**盒内只放该条目对应的那一个图形**（诊断=5px 圆 / 提问=5px 方）。**本文档此处不画字符示意**——凡是写成 `●`/`▪` 的地方，最后都会被照抄成字符 |
| **图例里的上下位置必须保真** | 圆贴在它的盒**上沿**、方贴在它的盒**下沿**——**和轨道上一模一样**。理由：图例要教的不是"两个符号"，是"**圆总在上、方总在下**"这个位置通道。如果图例把两个形状都垂直居中，学生学到的是一条错规则，回到轨道上仍然要重新猜 |
| **形状实现（硬要求）** | **图例符号与轨道标记用同一个元素、同一个 class、同一段 CSS**：`<i class="c-mark__shape" data-kind="diag">`（圆）/ `data-kind="ask"`（方）。**不新写一套样式、不换尺寸、不用 `●` `▪` 字符**。字符的字面尺寸、基线、笔画粗细由字体决定，而验收要求"图例符号与轨道标记形状尺寸完全一致"——用字符必然失败；**用两个 class 各写一套也会漂**，因为图例与轨道是两处使用点 |
| **复用的是哪一层（fe 问的"要不要 `[data-ctx="legend"]` 覆盖"）** | **复用发生在原子层，不在按钮层**：共用的是 `<i class="c-mark__shape" data-kind>`，**不是 `.c-mark` 按钮**。图例里**没有** `.c-mark`——它是一个不含热区、不含 `data-kinds`、不含 tabindex 的纯展示宿主（`<span class="c-legend__item">` 内的那枚 `<i>`）。**所以图例永远不会出现"一个宿主同时装两个形状"的情形，也不需要任何定位覆盖。** 两条边界由此确定：① `<i>` 自身的形状 / 尺寸 / 圆角 / `position` 全部写在 `.c-mark__shape` 上，**不依赖父级 `data-kinds`**——父级只负责"哪一枚该显形"（§9.3 的闸门）；② 一旦有人为图例写 `[data-ctx="legend"] { … }` 之类的覆盖来挪位置，"像素级一致"这条验收就立刻失去意义，**该覆盖本身就是 bug** |
| 常规态显示条件 | 存在诊断标记 **或** 存在提问标记 **或** 用户曾展开过图例 → 常显；以上都不成立时，该槽位显示一个 **16×16 的 `?` 图标按钮**（1px 框，11px 字，**`aria-label="时间轴标记图例"`**），点击**把同一槽位的内容换成图例**（**不做浮层**——槽位在控制行右端，控制行在时间轴上沿，浮层只能向下弹出并压住时间轴，违反 §6.3.4 禁止项第 3 条） |
| 演示态 | **强制常显、不折叠**（教师讲解需要），字号升到 13px，形状升到 6px。**投影下不能有"要靠猜"的东西** |
| 首访提示 | `localStorage` 无记录时，图例文本下方给一条 **1px 下划线 1.2s 淡出**（一次性，**不得异步循环**；`prefers-reduced-motion` / `[data-motion="reduced"]` 下改为静态显示 1.2s 后直接消失，无淡出） |
| 禁止 | 禁止循环脉冲、禁止固定间隔重复提示、禁止把图例做成浮层遮挡时间轴、禁止只用颜色区分两种标记、禁止图例与键盘提示同时出现在槽位里 |

**图例与标记的一致性检查（写进验收）**：灰度截图下，图例中的圆 / 方必须与轨道上的圆 / 方**形状一致、尺寸一致**；任何一项不一致就是 bug。**因为共用同一个 class，这条检查在实现上应当"天然通过"——如果需要额外写样式才能对齐，说明复用没做到。**

#### 6.3.5 标记的键盘与读屏规格（原来只有鼠标热区，是缺口）

**热区只服务鼠标；键盘与读屏用户必须有等价路径。**

| 项 | 规格 |
|---|---|
| 可聚焦 | **每个"有标记的步"是一个可聚焦元素**（不是每条标记一个——理由见 §6.3.3 热区），纳入 transport 的 **roving tabindex**（整组只有一个 `tabindex="0"`，其余 `-1`，用方向键在组内移动） |
| Tab 顺序 | `控制按钮组 → 时间轴滑块 → 标记组（进最近的 1 个）`；不允许标记被 Tab 跳过。**常显图例不占 Tab 站**——它是纯文本、没有任何操作，多一个站只会拖慢键盘用户。图例改为挂在时间轴滑块的 `aria-describedby="tl-legend"` 上：**读屏用户一聚焦时间轴就先听到"系统推测 / 我的提问"，比单独一个 Tab 站更早、也更省事**。只有"无标记时的 `?` 折叠按钮"可聚焦，排在滑块之后 |
| 快捷键 | `[` 跳到上一个**有标记的步** / `]` 跳到下一个。**同一步不重复停留**——一步有两类标记时只算一个停靠点，具体选哪一条在 E 区卡里做（r5 起撤销"诊断优先于提问"这条：它属于"一标记一热区"的模型，那个模型已废） |
| `Enter` | 在 **E 区展开一张「标记详情」卡**（与诊断提示同一个落点），**不做浮层**。理由：控制行在时间轴上沿，浮层向上弹会压到密钥轨与矩阵底边、向下弹直接出视口——而 C 区（矩阵）是唯一不可遮的（UX-V3）。E 区本来就是"解释这一步"的地方，这个落点比浮层一致，也不涉及遮不遮的问题。**卡片复用 `.c-diagslot` 槽位**，高度仍锁死 `--diag-row-h` |
| `Esc` | 关详情 |
| 聚焦播报 | `第 13 步，共 24 步，第 2 轮 列混合。1 条系统推测，2 次提问`（两类计数**合并成一条播报**）；无标记的步不是停靠点，所以不需要"此步无标记"这句 |
| 焦点态 | 常规：`outline: 2px solid var(--accent); outline-offset: 2px; box-shadow: 0 0 0 4px var(--paper-0)`；演示：§7.2 的双层环（3px 近黑 + 黄环 + 外侧 8px `▸`）。**热区是整列宽 × 20px 的透明块，焦点环画在热区上会是一条比标记大得多的框**——这是有意的：它告诉用户"这一整列都属于这一步" |
| 视觉提示 | 焦点落在标记上时，该步在轮号带的轮号加下划线（1px，`--accent`）——**聚焦不只靠环，还要告诉全班"这是第几轮的哪一步"** |
| 时间轴本身的键盘 | `← / →` 单步（执行语义）、`PageUp / PageDown` 跳轮（跳转语义）、`Home / End` 首末步 |

**验收口径（纯键盘走通整条链路）**：`V` 载入向量 → `Space` 播放 → `Space` 暂停 → `→` 单步 → `A` 聚焦 AI 输入框 → 提问 → `Esc` 关批注 → `[` / `]` 跳到下一个标记 → `Enter` 看详情。**全程不碰鼠标，且每一步都有可见焦点。**

### 6.4 S 盒 16×16 表（256 格的密度问题）

**核心策略：把 256 格做成一"张表"，不是 256 个按钮。**

- 主体是 `<table>`：行 / 列头 = `0–F`（11px mono `--ink-3`，`--paper-1` 底，`position: sticky`）。
- 单元格：**28 × 22px**，12px mono 数字，**无边框**；仅每 **4 列 / 4 行**一条 `--line-hairline` 分组线，形成 4×4 大分块。理由：等距网格的扫描靠**分组线**，给 256 格每格描边会直接炸成噪点。
- 高亮：当前查询的行与列各画一条 **1px `--accent` 整行 / 整列线**（横贯整表），交叉格填充 `--st-changed` + 字重 600。**这一处是全产品"啊哈时刻"的候选**——学生第一次看见"一个字节进去，交叉点跳出来"。
- 不显示十进制（太挤），底部一行 inspector：`S[0x3F] = 0x75`。
- 正 / 逆 S 盒：**同一张表**，页签 `S-BOX` / `INV S-BOX` 切换；切换用 **160ms 交叉淡入**（**禁用横向滑动**——会与"行移位"语义混淆）。
- 滚动：`overflow: auto`（高 22×17 ≈ 374px，768 高度下需要滚动），表头 sticky。
- 演示态：单元格 32×26px、数字 13px，且**只显示"放大镜窗口"**——被查询的行 / 列构成的 4×4 十字区域放大呈现，而不是整表。

### 6.5 密钥扩展字序列（44 字）

- 呈现为一条**水平"纸带"（ribbon）**，不是 44 个卡片。
- 结构：按轮分组 `W0-3 | W4-7 | … | W40-43`（AES-128 共 11 组）。每组一个 1px `--line-default` 框的块（**这是"框"不是"卡片"**：无底色、无阴影、无圆角），块内 4 个字横排，组内用 1px 竖线分隔（**组内 gap = 0**）。
- 每个字 8 位 hex（`2B 7E 15 16`），`--fs-micro` / `--fs-label` mono。
- 组间 `12px`；溢出横向滚动 + 顶部 1px 刻度尺；当前轮组自动滚入视图（`scroll-behavior: smooth` **仅此一处允许**）。
- 高亮：参与当前轮密钥加的那 4 个字 → 石墨底 + 斜纹（沿用 E 态纹理，语义一致）。演示态改实心 + 左 6px 条。
- 悬停某字 → 下方浮出 1 行 11px 公式（`W[i] = SubWord(RotWord(W[i-1])) ⊕ Rcon[i/4] ⊕ W[i-4]`），并用 1px 引线连回该字。公式保留 `⊕` 符号（不用 `XOR` 文字，符号更省宽且有数学感）。

### 6.6 AI 辅导栏

- 宽 **360px**（≥1440 → 400px；折 48px），1px `--line-hairline` 左线；**无卡片、无阴影、无毛玻璃**。
- 顶部：`AI 辅导 / TUTOR`（11px uppercase）+ **上下文标签** `CTX: R3 · MixColumns · C[1]`（mono 11px，1px 框，点击清除）。这个标签是"我知道你在问哪一步"的证据，必须常显。
- **消息不用气泡**：
  - 用户消息：**左对齐**，`--surface-inset` 底，左侧 2px `--line-strong` 竖线，内边距 `8px 12px`
  - AI 消息：**全宽无底**，左侧 2px `--accent` 竖线，内边距 `0 0 0 12px`
  - 理由：气泡是消费级 IM 语言；"批注 / 引文"式排布是文档语言，且在 360px 里气泡的内边距要吃掉 40px 横向空间——高密度界面负担不起。
- 正文 `--fs-body` 15px / `--lh-body` 1.65（长时间阅读）；段落间距 12px。
- 内联数值：mono 13px + `--surface-inset` 底 + 1px 左线 + 2px 圆角 + 1px 下边框（可点击）。
- 输入框：底部固定 96px；`textarea` 2 行起、最多 5 行自增；1px `--line-default`，focus 时 → 1px `--accent` + 四角刻线（**不用 glow 光晕**）。
- 折叠态：48px 竖条，竖排标签 + 右上角 **1px 方框内的未读数字**（不用圆点）。
- 空态：`选中任意一步，问我"为什么"` + 3 个建议提问（左对齐文本按钮，1px 下划线，无底色无边框）。
- 降级 / 来源标识：均为**消息头一行文本标签**（`来自常见问题` / `通用讲解（未引用当前数值）` / `离线讲解：先用这份看` / `已停止`），不改变消息底色。

### 6.7 错误字节高亮（练习判分定位）

三条通道同时给，全部不依赖颜色：
1. **右下角 6px 红色实心折角三角**（像纸被折起一角）——最醒目且最像"批注"；
2. **底部 `inset 0 -2px 0 var(--st-error)`** 条；
3. **右上格外 2px 的 `≠` 上标**（11px mono）。

- 底填充 `--st-error-fill`（10% 红）；演示态改实心 `oklch(0.905 0.055 28)`。
- **不做 shake、不做红色闪烁、不做描边脉冲。**
- 正确值不额外显示；仅在"对比模式"开启时，在格下方 11px `--ink-3` 显示 `exp C5`。
- 判分总结条：插入在 transport 栏**正上方**的一条 40px 高横条（**不是 toast**）：左 `12 个字节中 3 个错误`，右 `跳到第 1 个错误 →`（文本按钮）。点按后矩阵聚焦 + 该格 420ms 描边，**不滚动整页**。
- **整段错（首步即错）走"点 + 面"分离结构，不给矩阵套红框**：

| 元素 | 通道 | 表达什么 |
|---|---|---|
| 真正错的那 **1 个**字节 | 错误通道（6px 红折角 + 底部 2px inset 条 + `≠` 上标 + 2px 红边） | **对错**——唯一的错误语义承载点 |
| 其余受污染的字节（`propagated`） | **第 7 态 `downstream`**：只降不改——1px 极淡实线 `--line-hairline`（**边框保留，只降一级**）+ 底色内缩一档 + `--ink-3` 400；无角标、无折角 | **"别管这些"**——它们不是错，是被牵连 |
| 矩阵范围 | **四角括（corner brackets）**：四角各一个 L 形，**实线 2px** `--rule-scope-ink`，长臂 28px、内缩 6px；配骑在顶边线上的标签 `影响范围：16 字节`。**没有完整外框、没有虚线、没有琥珀** | **范围**——角括在设计语言里从来是"选区标记"（截图框 / 选框 / 聚焦区），只说明"范围在这里"，不说明"这里好不好" |
| 判分结果条 | 可以用错误样式 | 结果条说"不对"是准确的；矩阵说"全红"不准确 |

  配文：`从第 1 步的字节替代就出现差异，后面的结果都受影响` + `你只错了 1 处`。

  **为什么是四角括而不是完整外框**：完整边框仍然是一个"围起来"的动作，而**围起来本身就带"这块有问题"的语气**。角括不是——它只标注范围，不评价范围。同时它复用了本设计系统已有的"四角刻线"语言（活动区指示用的那个），只是尺寸放大到 28px、线宽 2px，与 6px 的"当前活动区"小节线区分开。

  **也不用虚线角括**：虚线已被"未生效 / 待定 / 禁用"占用（§2.6），再用一次会让虚线失去固定含义。

  **角括与"四角刻线"会不会在同一屏混淆——不会，但判据不是尺寸差，是位置。**

  先立一条通用判据（适用范围超过本条，写进 §11）：

  > **两个含义不同的同族符号，不能靠尺寸差区分，必须靠位置或标签区分。**
  > 理由：尺寸差是**可压缩的**——视口变窄、浏览器缩放、投影 gamma 都会把它吃掉，"28px vs 6px"在 1024 投影 + 125% 缩放下看起来可以差不多；**位置不会缩，标签不会缩**。

  按这条判据，本设计里"L 形角标"这一族一共三层，各自的落点互不重叠：

  | 元素 | 表达什么 | 落点 | 尺寸 | 标签 |
  |---|---|---|---|---|
  | **活动区刻线** | "矩阵这一块是当前操作区" | **容器外圈**，贴容器边界**向外**画 | 臂长 6px、线宽 1px | 无 |
  | **范围角括** | "这 16 字节是被牵连的范围" | **内缩 6px**，落在格边界**内侧** | 臂长 **28px**、线宽 **2px** | **必带**骑顶边的「影响范围：16 字节」 |

  **r5 起只有两层**：`selected` 的四角刻线已撤（§2.3.1），单格级别不再有任何 L 形。所以需要校的组合从三种降到一种——**容器外圈刻线 vs 容器内缩 6px 角括**，两者分居容器边界的内外两侧，永不重叠。少一层不是能力下降，是**把"三方共存"的问题化简成"两方共存"**。

  两层在位置上分别落在"容器外"与"容器内缩 6px 处"，**不共用任何一条边**。判分时同屏出现（工作台矩阵自带活动区刻线 + 判错叠加的范围角括），学生仍然能读出：外圈 = 这块在操作，内缩的大括号 = 这片被牵连。**学生不需要知道它们叫什么。**

  §1.4 红线 1 的直接应用：学生从整块红框里只会得到一个结论——"我全错了"，而这恰恰是三层反馈要防的归因错误（AES 雪崩性：首错则后全错）。**视觉的强度必须和信息的重要性匹配，而这里最重要的事实是"错得很少"。**

### 6.8 输入区（B）

宽 268px（roomy 场景无此约束）。密度从高到低：
1. `明文` 输入（8 字节 hex，mono 14px，1px 底框，focus 加四角刻线）
2. `密钥` 输入（同规格，16 字节）
3. `长度 [128 ▾]`
4. `载入标准向量`、`生成 ▶`
5. `─ 参数 ─` 轮数（只读）
6. `─ 轮密钥 ─` `w[8..11] ▸`（C4 密钥轨入口）

- trace 已生成后可**整体折叠成一行摘要**（`3243f6a8… · AES-128 · 加密`），把宽度让给矩阵与 AI；折叠态记入 URL。
- 主按钮：**无填充**，1px `--accent` 边框 + `--accent` 文字，高 32px，圆角 2px；hover 填充 `--accent-soft`；pressed `scale(0.98)`。理由：全站唯一有"填充"的按钮只应出现在破坏性 / 终结性动作上。
- **校验状态**（长度非法 / 非 hex）一律**行内**，且给出具体位置与期望值：`当前 28 位，AES-128 需要 32 位`、`第 9 个字符 'k' 不合法`。输入框右端出现 1px 红竖条；非法字符位置加 2px 红下划线。

## 8. 首页视觉方案

### 8.1 首页定位（已变更）

首页**不再是三个入口（看 / 练 / 问）**，改为：

1. **两个入口**：看（可视化工作台）/ 练（练习模式）
2. **一键载入标准测试向量**（辅助动作，视觉权重低于两个主入口）
3. **3 条示范问题**（告诉用户"可以这样问"，但"问"已降级为工作台内的能力，不再是独立入口）

### 8.2 核心难题与解法

> **它是全站唯一允许"空"的一页，而空页最容易变成平庸的居中排版。**

解法：**把首页做成一张工程图纸的"标题页 + 图签栏"，而不是一张欢迎页。**

- 空的地方不放装饰，放**结构**：一条 48px 的短线、一个 4 行 2 列的图签表、一块极淡点阵区。这三样都不表达内容，只表达"这是一个有规格的容器"。
- **绝对不居中**。全页采用左对齐到 72px 基线（roomy 密度），右侧 40% 留白——留白本身是设计，不是"没做完"。
- **没有 hero 大标题**：主标题只有 `--fs-display` 上限 46px 的两行，且左对齐、行宽受限（`--measure: 68ch`）。

- 禁止 hero 大标题（超过 46px 的字不要出现在首页）
- 禁止居中（任何一块都不许 `text-align: center` / `margin: 0 auto`）
- 禁止插画、图标插画、3D 图形、渐变、粒子
- 禁止三张等大卡片 / 三个等大入口
- 禁止"特性三点式"（图标 + 标题 + 一句描述 × 3）
- 禁止 `100vh` 满屏居中 + 向下滚动的营销结构；首页高度 = 内容高度（约 720px），768 屏幕下不需滚动

## 9. 六个关键组件的 DOM 伪结构

类名约定：`c-` 前缀 = component，`is-` 前缀 = 状态，`__` = 元素（BEM 元素层）。**状态一律写在根元素上，禁止写在子元素上**（避免 `is-` 散落导致 CSS 选择器不可穷举）。

### 9.1 字节格 `c-byte`

```
<div class="c-byte"                          ← 状态全部挂这里
     role="gridcell"
     tabindex="-1"
     aria-label="第 2 行第 2 列，值 63，本步已变化"
     data-row="1" data-col="1">
  <span class="c-byte__stage">               ← overflow:hidden，裁剪滚动替换
    <span class="c-byte__val is-current">63</span>
    <span class="c-byte__val is-incoming" aria-hidden="true">7C</span>
  </span>
  <span class="c-byte__corner" data-corner="tr" aria-hidden="true"></span>  ← 角位元素 ①：左上 reverse / 右上 changed / 右下 error / 左下 done，由 data-corner 驱动
  <span class="c-byte__corner" data-corner="br" aria-hidden="true"></span>  ← 角位元素 ②：同格最多 2 个角标，所以 DOM 只要 2 个
  <span class="c-byte__sup"   aria-hidden="true">≠</span>  ← 错误上标（格外 2px，不进格心）
  <span class="c-byte__sup"   aria-hidden="true">⊕</span>  ← is-xor（reduced-motion 下的密钥加替代）
  <span class="c-byte__hint"  aria-hidden="true">←1</span> ← reduced-motion 下的行移位旋转量
</div>
```

**角位元素只有 2 个，这是配"同格 ≤2 个角标"的上限，不是偷懒**：另两个角永远不会同时出现，多建节点等于给未来留出错余地。`data-corner` 取 `tl` / `tr` / `br` / `bl`，形状与尺寸按 §6.1.1 那张表查，不在 DOM 里硬编码。**`is-done` 的缺口也走 `data-corner="bl"`**——压一块 `--paper-0` 方块，与 `border-color` 解耦。

**根元素可用状态（7 + 4 个行为态）**：`is-changed` `is-selected` `is-error` `is-key` `is-done` `is-downstream` `is-ghost`（空 / 未输入）| `is-reverse` `is-xor` `is-disabled` `is-dragging`

**状态的 CSS 优先级顺序（实现必须按这个 order 写，fe 直接按此写 `classList`）**

所有状态规则同为 `.c-byte.is-x`（特异度 0,2,0），**靠源码顺序决定胜负**。从低到高：

| 序 | 状态 | 影响层 | 说明 |
|---|---|---|---|
| 1 | `.is-done` | 边框 + 左下缺口 + 文字墨量（**无纹理**） | 最弱的底层语义，"有内容的旧值" |
| 2 | `.is-downstream` | 边框 `border-color` 降一级 + 文字墨量（**只降不改：不加粗、不移除、不换线型**） | 覆盖 done |
| 3 | `.is-key` | 左竖条 + 右上方块 + 斜纹（**不改底色**） | 叠加层，永远不抢底色 |
| 4 | `.is-changed` | 底色 + 顶部厚条 + 右上角标 | 底色层最高 |
| 5 | `.is-reverse` / `.is-xor` | 角标 / 上标（图形层） | 只加图形，不改色 |
| 6 | `.is-selected` | 边框（`border-color` + `inset`）+ **外环**（判分上下文改近黑） | 边框层最高；**不占角标通道** |
| 7 | `.is-error` | 折角 + 底部条 + `≠` + 底色 | 图形层最高 |
| 8 | `.is-ghost` / `.is-disabled` | 整体降级 | 覆盖一切，**必须带 `:not()` 保护或 `!important`** |

**合法叠加**（JS 可同时挂，视觉按上表叠加）：
`is-changed + is-key`（轮密钥加）、`is-changed + is-selected`、`is-error + is-selected`、`is-downstream + is-selected`

**互斥（JS 必须保证不同时挂）**：
`is-error` ✕ `is-downstream`、`is-ghost` ✕ 其余全部、`is-disabled` ✕ 其余全部

**唯一需要"同时表达"的组合态是 `is-error + is-selected`**（判错后学生点开那个错字节看明细）。两态的通道本来就不抢：

| 通道 | `is-error` 占 | `is-selected` 占 |
|---|---|---|
| 底色 | `--st-error-fill` | —（不改底色） |
| 右下角 | **6px 折角三角 + `≠` 上标** | — |
| 底部 | `inset 0 -2px 0 --st-error` | — |
| 边框 | —（宽度仍 1px，颜色不变） | **`border-color: --accent`** + `inset 0 0 0 1px --accent` |
| 外环 | — | **外 3px 环，颜色改 `--ink-1`（近黑）** |
| 四角（角标通道） | **右下 6px 折角三角**（唯一占用者） | **不占用** |

**现在没有冲突了，而且这不是"凑巧"**：`selected` 的全部表达落在**边缘通道**（`border-color` + `inset` + 外环），`error` 的全部表达落在**角标通道 + 底色 + 底边条**。两个通道**正交**，所以组合时既不需要让位规则、也不需要判断谁优先——**这才是 r5 撤掉 `selected` 四角刻线的真正收益**。

> r4 里我写过一条补救规则："折角赢，`selected` 在 `is-error` 时整体不画刻线"。那是**补丁**：冲突本身是刻线带来的（刻线的右下那条臂与折角的折角三角同位置同尺寸），补丁只能让它不显眼，不能让它不存在。**r5 把冲突从源头去掉**，那条让位规则随之作废。

**判分上下文里外环必须换色**（这条不能省）：`--st-error-fill` 是红底，`--accent` 环是青，在红色盲（deutan / protan，约人群 8%）下两者明度接近、并成一团。改用 `--ink-1`（对红底 12:1）后，"这一格被选中"在任何色觉下都成立。

```css
.c-matrix[data-ctx="graded"] .c-byte.is-selected { --accent-ring: var(--ink-1); }
/* 只换环色，不动 border-color：accent 边对红底仍有 3.4:1，且它是"选中"的第二重确认 */
```

**上下文覆盖规则（判分结果展示期间）**：进入"判分结果"上下文后，**`is-error` / `is-downstream` 覆盖 `is-changed`**。

- 理由：判分那一刻用户关注的是**对错**，不是**变化**。此时 16 个格子里 `is-changed` 全都为真（AES 雪崩性），如果它继续占着底色，`error` 与 `downstream` 就都读不出来。
- 实现：`.c-matrix[data-ctx="graded"] .c-byte.is-changed:not(.is-error):not(.is-downstream) { /* changed 样式静音 */ }` —— **用上下文属性克制，不要用 `!important`，也不要让 JS 摘 class**（摘 class 会让"退出判分后恢复变化高亮"变成一次状态重建，成本高且易错）。
- 退出判分上下文（`data-ctx` 回到 `play`）后，`is-changed` 自动恢复，无需重算。

**选择器隔离硬要求**：**所有承载 `error` 特征的节点**——右下折角（`.c-byte__corner[data-corner="br"]`）、底边 `inset` 条、`≠` 上标——的显示规则必须带 `:not(.is-downstream)`：

```css
.c-byte.is-error:not(.is-downstream) .c-byte__corner[data-corner="br"] { /* 折角 */ }
.c-byte.is-error:not(.is-downstream) .c-byte__sup--neq { /* 上标 */ }
```

否则一旦状态机出错，受污染的 15 个格子会同时长出红折角，正好触发红线 1 要防的"满屏红"。**注意：闸门挂在"触发条件"上，不挂在"伪元素"上**——折角已经移进 `__corner` 元素，只护旧写法的 `::before` 会漏掉真正渲染的那个节点。

**禁止**：不要为每种状态写独立选择器树；全部走 `.c-byte.is-x .c-byte__y`。

**根元素可用状态**：`is-empty` `is-playing` `is-dragging` `is-at-start` `is-at-end` `is-focused`
**关键实现点**：
- `--i`（步下标）与 `--span`（该轮步数）是**唯一的数据接口**，所有 x 坐标由 CSS `calc()` 从这两个变量算出。前端只改 `--i`，不改 DOM 结构。
- `.c-mark__shape[data-kind="diag"]` 画 **5px 实心圆**（上沿），`[data-kind="ask"]` 画 **5px 实心方**（下沿）。**形状由 `<i>` 子元素承担，不用伪元素**——伪元素无法被图例"原样复用"，图例那边还要一个宿主元素，多一层间接就多一处对不齐。`::after` / `::before` 不用于扩热区（热区由元素自身尺寸承担，见下条）。
**"哪一枚显形"的闸门（r5 补正：两枚常驻，不用 `v-if`）**：

```css
/* 形状与位置只写在 <i> 自己身上，完全不依赖父级 data-kinds。
   图例里的同一枚 <i> 没有 .c-mark 父级，照样按这段渲染 —— 这就是"像素级一致"的机制。 */
.c-mark__shape { position: absolute; left: 50%; transform: translateX(-50%);
                 width: 5px; height: 5px; background: var(--ink-2); }
.c-mark__shape[data-kind="diag"] { top: 0;    border-radius: 50%; }
.c-mark__shape[data-kind="ask"]  { bottom: 0; border-radius: 0; }

/* 闸门只藏"另一类"：两个都有时两条规则都不命中，两枚同时显形 */
.c-mark[data-kinds~="diag"]:not([data-kinds~="ask"]) .c-mark__shape[data-kind="ask"],
.c-mark[data-kinds~="ask"]:not([data-kinds~="diag"]) .c-mark__shape[data-kind="diag"] { opacity: 0; }
```

- **为什么"藏"而不是"不渲染"**：标记是**追加**的（学生每做一步才多一类），用 `v-if` 意味着每次追加都在 24 步列表里重建一次子节点；而 `<i>` 的引用一旦脱离文档，`el.style.xxx = …` **不报错也不显示**，只在真机偶发（同 §9.7.1 的 `isConnected` 那条）。
- **为什么用 `opacity` 不用 `display:none`**：`display:none` 会把元素从渲染树摘掉，DevTools 里量不到尺寸——**"形状尺寸完全一致"这条验收从此只能靠肉眼**。`opacity: 0` 保留盒，隐藏的那枚仍能量出 5×5。
- **`data-kinds` 是单值枚举 + `~=`**：只允许 `diag` / `ask` / `diag ask` 三种，**不做第三类**。新增标记类型前先问：它是"系统推测"还是"我的提问"？都不是，就说明它该进 E 区卡，而不是轨道。


- **热区 = 整列宽 × 标记轨全高，一步一个**：`.c-mark { width: 100%; height: var(--tl-mark-band); background: transparent }`，宽取该步**列容器的 100%**（列容器由 `--i` + `--step-w` 定位），**绝不写死像素**——58 步下列宽约 10px，写死 12px 会跨到相邻步。可视图形只占其中 5–6px，**视觉大小与靶子大小不一致是有意的**。
- **两个图形是两个 `<i aria-hidden>` 子元素，不是伪元素**（r5 补正）：`<i class="c-mark__shape" data-kind="diag">` 贴上沿、`data-kind="ask"` 贴下沿。**为什么不用 `::before`/`::after`**：图例要"像素级一致地复用同一个符号"，而 `<i>` 可以让轨道的图形与图例的图形用**同一个元素、同一个 class、同一段 CSS**；伪元素方案只能复用"伪元素规则"，图例那边仍要一个宿主元素，多一层间接就多一处可能对不齐。**不要拆成两个 `<button>`**——两个整列宽的热区会完全重合（点不到）或各让一半（两个都不满足 24px 间距），详见 §6.3.3。
- **图例与轨道共用同一个 `<i class="c-mark__shape" data-kind="…">`**——同一个元素、同一段 CSS，验收的"像素级一致"因此是**结构上天然成立**，而不是靠两处写一样的值去凑。
- `.c-mark` 在标记轨内 **z-index: 3，高于游标**（游标 z=2）；不要做"游标压住标记时标记偏移"的处理（2px 压 5px 只露 1px，等于没露）。
- `.c-mark` 必须是可真聚焦元素（`<button>` + roving tabindex），键盘规格见 §6.3.5。
- `.c-timeline` 的 `role="slider"` 必须支持 `←/→`（执行语义）与 `PageUp/PageDown`（跳转语义）、`Home/End`；标记组不在此滑块内，避免嵌套控件冲突。

**三个元素的关系（fe 问的正是这个）**：

| 元素 | 职责 | 生命周期 |
|---|---|---|
| `.c-diagslot` | **常驻槽位**。锁死 `height: var(--diag-row-h)`，内容变化时高度不变 | 页面存活期间永不卸载 |
| `.c-diagslot__idle` | 空态占位文本 `DIAGNOSTIC —`（11px `--ink-4`） | 有提示时 `display:none` |

**关键实现点**：
- `.c-annotation` 是 `.c-diagslot` 的**唯一子元素**（`__idle` 除外），**绝不 `position: fixed`** —— 它是行内块，不是浮层。
- 槽位高度锁死 `var(--diag-row-h)`，任何状态下都不变；批注出场只动 `opacity` 与 `translateY(2px→0)`，**不动高度**（否则槽位被撑高，对话流位移）。
- 若将来批注内容变长（比如引用了 4 个数值），走 `max-height` 展开 + 槽位内部滚动，**仍然不许撑高槽位**。
- `--tick-y` 由 JS 从"目标字节格的 `getBoundingClientRect().top` − 舞台顶"算出，写成 CSS 变量；**不要用 JS 直接改 `top` 样式**（会触发 layout），因为批注出场时恰好有 16 个格子在动描边动画。
- `.c-annotation__tick` 必须 `position: absolute; left: -1px`（压在 E 区左分隔线上），**不得进入 C 区**。
- 三条克制条款（一次最多 1 条 / 间隔 45s / 空闲 20s）由状态机保证，不由 CSS 保证；CSS 只负责"不许有循环动画"。
- `aria-live="polite"` 挂在槽位而非批注上：批注被卸载时读屏仍能播报最后一次内容。

### 9.7 三个组件的 Vue SFC 骨架（fe 明确要求，只给这三个）

**先立一条硬规则，三个组件全部适用：**

> **`<template>` 里禁止出现 `v-if` / `v-else` / `<template v-if>` 来控制状态子元素。**
> 一律**常驻 DOM**，用 `data-state` / `is-*` 类切可见性（`display:none`、`visibility:hidden`、`opacity:0` 都行——它们都不销毁节点）。
> 理由：`useMatrixWriter` 与 `useByteRefs` 都是**按索引缓存节点引用**的（16 格 × 每次动画取一次 `el`），`v-if` 会在状态切换时销毁并重建节点，缓存里的旧引用变成游离节点，写进去的值不报错但也不显示——**这类 bug 只在真机上偶发，最难查**。

#### 9.7.1 `c-byte`（`ByteCell.vue`）

```vue

<script setup>

const props = defineProps({
  index: Number, row: Number, col: Number,
```

**给 `useMatrixWriter` 的接口约定（这条比样式重要）**：

| | 约定 |
|---|---|
| 节点引用 | 只允许缓存 `valCur` / `valNext` 两个节点，**且必须校验 `el.isConnected`** 再写（判分上下文切换时组件可能被 `v-for` 的 key 变化整体重建） |
| 写值 | 写 `textContent`，**不写 `innerHTML`**（避免每次创建文本节点，16 格 × 24 步会留下大量待回收对象） |
| 触发动画 | 只切 `is-current` / `is-incoming` 两个类，**不直接改 `transform` 内联样式**——内联样式会盖掉 `[data-motion="reduced"]` 的归零规则 |
| 状态互斥 | `error` 与 `downstream` 由 JS 保证不同时挂；CSS 再挂一层 `:not(.is-downstream)` 闸门（§9.1） |

**状态类映射（顺序无关，只是拼类名）**：`is-changed` `is-selected` `is-error` `is-key` `is-done` `is-downstream` `is-ghost` `is-reverse` `is-xor` `is-disabled`。

**`c-mark` 的三层分工（fe 问的"谁撑热区"——答案：元素自身，两个图形是子元素）**：

| 层 | 由谁承担 | 尺寸 | 说明 |
|---|---|---|---|
| **热区** | **元素自身**（`width: 100%`、`height: var(--tl-mark-band)`、`background: transparent`） | 整列宽 × 20px（演示 24px） | 宽取**该步列容器的 100%**，**绝不写死像素**（58 步下列宽约 10px，写死 12px 会跨到相邻步）。绝不用伪元素扩热区——伪元素扩出的区域**不在元素的命中测试父链上**，`@click` 绑在元素上时点在伪元素上有时不触发 |
| **诊断圆** | `<i class="c-mark__shape" data-kind="diag">` | 5×5px（演示 6×6） | 贴上沿；`border-radius: 50%` |
| **提问方** | `<i class="c-mark__shape" data-kind="ask">` | 5×5px（演示 6×6） | 贴下沿；`border-radius: 0` |

**两个图形是 `<i>` 子元素而不是伪元素**——这解决了一个原来被伪元素绑死的限制：`::before` 只能画一个形状，而一步要能同时有两个标记；同时图例要"像素级一致地复用"，`<i>` 可以让两处用**同一个元素、同一段 CSS**。**圆在上、方在下是位置通道，两个 `<i>` 互不干扰。**

**`--i` / `--span` 的唯一数据接口**：

```css
/* --step-count 由 JS 写入（trace 长度），--step-w 是派生量。
   两者都不进 §10 的 token 表：它们不是设计参数，是布局计算。 */
.c-timeline { --step-count: 24; --step-w: calc(100% / var(--step-count)); }

.c-mark,
.c-timeline__cursor {
  left: calc(var(--i) * var(--step-w) + var(--step-w) / 2);
  transform: translateX(-50%);
}
.c-timeline__round { width: calc(var(--span) * var(--step-w)); flex: none; }
```

- `--i` 由**每个标记自己**带（`style="--i: 3"`），`--span` 只给轮号带用。
- 前端只改 `--i` 的数值，**不改 DOM 结构、不改 left 内联值**。这样 `[` / `]` 跳转、roving tabindex、`aria-label` 三者都不需要重算布局。
- `--step-w` 由容器 `calc(100% / var(--step-count))` 算出，`--step-count` 来自 trace 长度——**这是 24 步与 58 步唯一的差别**，不需要第二套布局。

**父组件 `Transport.vue` 负责**：`aria-describedby="tl-legend"` 挂在 `.c-timeline`；`.c-legend` 节点常驻（收起时换 `.sr-only`，见 §6.3.4）；`role="slider"` 与标记组是**兄弟关系，绝不嵌套**。

**`data-state` 三态下哪些子元素保留（fe 的原问题，逐条答）**：

| 子元素 | `expanded` | `collapsed`（用户手动收起） | `answered`（点了"是/不是"） |
|---|---|---|---|
| `__bar` 2px 红竖条 | 显示 | **显示**（收起后仍要能看见"这里有一条批注"） | 显示 |
| `__bracket` | 显示 | 显示 | 显示 |
| `__q` | 完整 | **`overflow:hidden` 截到 1 行**（不是 `display:none`——截断仍留可读片段） | 保留原文（用户要能回看"系统当时猜的是什么"） |
| `__disclaimer` | 首访才显示 | 隐藏（`display:none`，它是可有可无的说明） | 隐藏 |
| `__acts` 三个按钮 | 显示 | 隐藏 | **整组换成一行文本 `已记录`**（`__acts` 节点仍在，内容替换） |
| `__count` 剩余条数 | 显示（>1 时） | 显示 | 显示 |
| `__close` | 显示 | 显示 | 显示 |
| `__tick` 12×2 红刻痕 | 显示 | **显示**（它是"批注 ↔ 矩阵"唯一的位置索引，任何状态都不能丢） | 显示 |

- **高度不变是硬要求，且不是靠 CSS 猜出来的**：`.c-diagslot` 锁死 `height: var(--diag-row-h)`，`.c-annotation` 与 `__text` 都 `overflow: hidden`。三态**只改内部可见性与行数**，不改槽位盒模型。**不要用 `max-height` 过渡来"折叠"**——那会让槽位高度参与过渡。
- `answered` 态**不清空批注**：学生选了"不是"，还要能看见系统原来猜的是什么；清空会让他无法确认"我刚才否掉的是哪一句"。
- 关闭 / 换提示 = **整个 `.c-annotation` 卸载**（这是唯一允许的 `v-if`，因为它挂在槽位内部，不涉及 `c-byte` 的引用缓存）。

## 11. 执行纪律（贴进 README，评审按此打分）

1. **先做灰度验收**：任何新组件，截图加 `filter: grayscale(1)`，信息层级必须还在。做不到就调明度，不加颜色。
2. **16 格的位置永不变化**：动效只允许动 `transform` / `opacity` / `background-size`（仅 ≤24px 元素）/ `stroke-dashoffset`。任何引起 reflow 的写法直接打回。
3. **发丝线是唯一的分区语言**：看到一个"卡片"容器，先问能不能用一条 1px 线 + 一个图号标签替代。能，就替掉。
4. **圆角 2px，阴影只给两个浮层，渐变零个**。这是最容易被"顺手美化"破坏的三条。
5. **动效只有 4 个是重要的**：字节值滚动、行移位、列混合扫描、红线批注。其余所有过渡都应在 80–160ms 让人注意不到。**多做一个动效，记忆点就被稀释一分。**
6. **任何循环动画 = 零**。包括"轻微呼吸""缓慢脉冲""等待闪烁"。
7. **文本比对必须跑一遍**：`第 N 步`、`第 N 轮`、`下标从 0 开始`、`AES-128 / 192 / 256`、`字（word）= 4 字节` —— 这五处术语在全站字面一致，视觉上不因字号不同而改变写法。
8. **区域级通道只表达范围或程度，不表达对错**（§1.4 红线 1）。任何"给一大片区域上错误色"的冲动，都要先问：这块颜色会不会让用户得出一个比事实更悲观的结论。
9. **每个可视化标记都必须是可真聚焦元素**。鼠标热区不算可达性；`[` / `]` 跳转、`Enter` 展开、焦点环、播报文案四件齐备才算完。验收口径：纯键盘走通「载入 → 播放 → 提问 → 关批注 → 跳标记」。
10. **琥珀永远不兼职表达"有问题"**。`--st-changed` 这组琥珀色系是学生看得最多的颜色（"已变化"），一旦兼职警告语义，`changed` 态的语义就废了。**"有问题"只有红色能说，且只在那个真正错的字节上。**
11. **线型只有一个含义**（§2.6）：虚线 = 未生效 / 待定 / 禁用；实线 = 已生效 / 确定；不用线型 = 不强调。**点划线已无用例并删除，不得复活**。新增用法前先在表里找归属，找不到说明这个状态需要的不是线型。
12. **角标四角归属不可变更**（§6.1.1）：左上反向 / 右上已变化 / 右下错误 / 左下已完成；同格 ≤2 个；新增须先申请空位；**任何标记不得进格心**。
13. **`border-width` 七态恒定 1px，只准改 `border-color`**（§2.3.1）。需要"加粗 / 更重"的观感时用 **`box-shadow: inset 0 0 0 Npx`** 叠加，**不改 `border-width`**。原因：改宽度会挤动内容，hex 数字会横移 1px——而在这个界面里"数字位移"是"数值变了"的语义，等于凭空制造一次假的变化信号。同理，**任何状态都不许改 `padding` / `margin` / `font-size` 来"强调"自己**。
14. **两个含义不同的同族符号，不能靠尺寸差区分，必须靠位置或标签区分**（§6.7）。尺寸差会被视口、缩放、投影吃掉；位置和标签不会。新增任何"L 形 / 括号 / 角标"类符号前，先在同一张位置表里找到自己那一层，找不到就说明这个含义需要的是文字。

15. **形状只用子元素画，不用伪元素画**（§6.3.4 / §9.3）。`::before` / `::after` 是**每元素 2 个的全局预算**，而且是**会静默用完的资源**：`::before` 已经被别人占了，你再写一条 `::before` 规则不会报错，只会让**原来那个形状消失**——这种 bug 在 hover 前不出现，只在演示现场出现。所以：① **凡是需要被第二处"像素级复用"的符号，必须是真实元素**（子元素才能被图例原样搬走，伪元素只能搬规则，宿主还得多一个）；② **每条新增伪元素规则，后面必须写一句"这个元素上另一个伪元素还剩着 / 已经用完了"**；③ **`::before` / `::after` 空闲不等于可以用**——先问三件事：能不能用 `outline`？能不能用子元素？用了之后别人还剩什么？

16. **叠加态的外扩必须留 1px 余量，且公式写下来**（§2.3.1）：`环宽 + 偏移 ≤ gap − 1px`。放在 `gap` 里刚好等于 gap 的元素，在 125% / 150% 系统缩放下会因亚像素取整而接触——**"算出来刚好"和"看起来分开"是两件事**（与第 14 条、以及"把几何不重叠当成间距达标是两回事"同源）。任何"外扩类"视觉（外环、focus 双环、`outline-offset`、角标越界、角括内缩）都要写这个式子，**不许只写一个数**。

#### 关于"把格线交给容器画"的裁决（这条要留档，防止第五次被提出）

团队里提出过一个更优雅的方案：**格线 owner 从格子移到容器**（`display:grid; gap:1px; background:var(--line-default)`，格子只填背景色，`selected` / `error` 改用 `box-shadow: inset`）。它在"连续表格"的模型里完全成立，但**在本设计里不成立**，因为本设计的矩阵不是连续表格：

- §6.2 与 §10 的 `--cell-gap` 是 **6px**（演示态 10px），不是 1px。容器底色方案会在 16 格之间填出**6px 粗的实色条带**，不是 1px 细线；若为它把间隙压到 1px，"16 个独立格 + 透气"的读法与 §6.2 的列括线设计同时失效。
- 该方案原本要治的病（相邻格共享边 → 两条 1px 叠成 2px、状态不同时边色一半一半）**在 6px 间隙下不存在**：每格边框完全独立，既无共享边也无双线。

> **教训（第二次记）**：判定"某条 CSS 结构有问题"之前，先查这张表自己的 `--cell-gap`。**引用数值时不回原文核对**，会得出一个听起来更优雅、但与本设计几何冲突的方案。

**常规态文字为什么是 `--ink-3` 而不是 `--ink-4`**：`--ink-4` 在本规范里的唯一职责是"禁用"，对纸底约 **2.6:1**。受牵连字节的值在"点开看来源链"时**仍然是要读的数字**，用 2.6:1 承载它，会同时破两条：token 契约（§3.5 / §10 注释写明"仅禁用态允许"）与正文 4.5:1 的无障碍基线。`--ink-3` 对 `--ink-1` 是 **ΔL 0.29**，灰度下已经是极清晰的一档，"足够安静"不需要靠 2.6:1 来证明。而 `done` 也用 `--ink-3` 不会混淆——**两态靠形状分开（缺口 vs 无缺口），不靠墨量**。
