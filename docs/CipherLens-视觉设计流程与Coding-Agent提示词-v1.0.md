### 0.3 四条协作纪律（四份文档不互相打脸的原因）

这轮设计里同一个参数被打翻过 3–5 次，每次都不是"没人负责"，而是**信息在角色之间转述时丢了约束**。以下四条是从实际事故里长出来的，不是先验规范：

| # | 纪律 | 它防的那次事故 |
|---|---|---|
| **D1** | **跨角色传数值时引用原句，不许改写成短语** | "8px × 2px 横条"被转述成"横条"，尺寸丢失后两组人各自实现出不同版本 |
| **D2** | **"见文档"不算交代**：跨文档依赖必须写清"哪个文件的哪一节、依赖什么结论" | 有人写"按视觉规范处理"，但视觉规范里那条已经改过三版，读者取到的是旧版 |
| **D3** | **同一参数出现在两处时，必须标注"权威处"** | 色值同时写在视觉规范和交互规格里，改一处忘另一处，两份文档互相矛盾。**本项目的权威处划分**：色值与视觉参数 → 《视觉设计规范》；行为与阈值 → 《信息架构与交互规格》；接口契约 → 《前端实现规格》§11；产品逻辑 → PRD。其余文档**只标"以 XX 为准"，不复制数值** |
| **D5** | **一份文件只有一个落笔者** | 两个角色各自"改一份拷贝"会让版本分叉——曾出现"我核过的那版打不开"。规则：谁的文件谁落笔，其他角色只提修改建议 |
| **D6** | **废弃一个被引用的名字时，保留名字、清空语义，不要删除** | 删 CSS token 会让旧代码引用到 `undefined`——**静默失败**，没有任何报错；把值改成 `none` 才会在 review 或渲染时被发现。同理适用于字段名、接口参数、状态枚举：**删除是静默失败，改值是可见失败** |
| **D4** | **判定"某处结构有问题"之前，先查这份文档自己已经定了什么** | 主理人提出"格线改由容器画"，而矩阵的 `--cell-gap: 6px` 早已写在同一份文档的 §6.2，两者物理冲突（详见 4.6 F3 记录） |

## 1. 设计上下文（Design Context）

> 这一章是给 Coding Agent 的**世界观**。不理解它，做出来的东西会是一个"能播动画的网页"，而不是这个产品。

### 1.1 四个基本事实

| 维度 | 内容 |
|---|---|
| **谁在用** | 主：网络工程/信息安全大三学生，会写代码、理解异或与矩阵、不熟 GF(2⁸)。场景是课后自习（1366×768 笔记本）与考前集中复习（连续注视 40 分钟以上） |
| **次要用** | 任课教师，**课堂投影**，开着灯，后排看不清 |
| **要完成什么** | ① 跟着动画看懂某一步改了哪几个字节；② 卡住时问一句"为什么"；③ 做题错了想知道错在第几轮第几步；④ 教师投屏讲一节课 |
| **该有什么感觉** | **精密仪器感 / 技术文档感**。不是消费级产品的活泼，不是营销落地页的炫技，是"值得信任的测量工具"。气质参照：示波器、频谱仪、工程图纸、专业音频设备面板 |

### 1.2 设计立场（一句话）

> **不做"漂亮的密码学 App"，做"一台被校准过的测量仪器"。**
>
> 界面上唯一的装饰权，全部让给「高亮的精确性」和「四个真正有力的动效」；其余部分用 1px 线、字距、留白和刻度解决秩序问题。

**方向名：校样（Proof Sheet）** — 把界面当一张工程校样纸来排：冷白纸底、发丝线分隔、等宽数字成列、区域带图号式标签。而"AI 知道你卡在哪"这件事，用**红笔批注**来表达（老师在校样边距上写的那句批注）。

### 1.3 记忆点

**红线批注**：系统察觉你卡住时，不弹 toast、不弹卡片，而是在 AI 栏顶部出现一条红竖条 + 手绘感方括号 + 一句反问，同时目标字节格边框被红色逐边描出、AI 栏左分隔线上出现 12×2px 红刻痕。

这是全产品唯一一个"别人没有"的可见形态。**所有装饰性设计都要为它让路**——多做一个动效，记忆点就被稀释一分。

### 1.4 五条不可违反（宪法级）

| # | 规则 | 违反的后果 |
|---|---|---|
| V1 | **零渐变、零毛玻璃、零 `backdrop-filter`** | 立刻变成 AI slop |
| V2 | **圆角上限 3px，阴影只允许 2 个浮层** | 变成"万物皆卡片" |
| V3 | **1px 发丝线是唯一分区手段**（禁止用卡片容器分区） | 信息密度高的界面会炸成碎片 |
| V4 | **禁止一切回弹/弹性缓动**（`cubic-bezier` 的 y 值必须在 [0,1]） | 仪器感变成玩具感 |
| V5 | **区域级、大面积的视觉通道只能表达"范围"或"程度"，不能表达"对错"** | 学生看到一片红 → "我全不会" → 放弃 |

> V5 是从一次具体冲突里长出来的：为"首步即错导致整段都错"设计区域级红框，直觉上合理，但它只会传达"你全错了"。正确做法是只有真正错的那 1 个字节标红，其余"下游污染"字节安静下去，范围信息用中性外框 + 文字标签。

### 1.5 反 AI Slop 自查（每个新组件都过一遍）

| 会暴露"这是 AI 做的" | 本项目的对抗手段 |
|---|---|
| 紫蓝渐变、深底霓虹发光 | 单一强调色深青墨，饱和度刻意压到 C≤0.09，全站零渐变 |
| Inter / Roboto | Archivo + Noto Serif SC + IBM Plex Mono |
| 万物皆卡片 | 1px 发丝线 + 图号标签 + 四角刻线 |
| 居中一切、hero 大标题 | 全站左对齐基线；首页无 hero，直接是命令条 |
| 无意义粒子背景 | 零；仅首页右留白有极淡点阵 |
| 圆润闪烁光标、弹性动效 | 2px 实心方块 + `steps(2)` 步进闪烁 |
| 万物皆有阴影 + 大圆角 | 圆角 2px，阴影仅 2 处浮层 |

**一句话检验**："如果告诉别人这是 AI 做的，他会立刻相信吗？" 会，就是失败。

## 2. 设计流程（本次实际走过的路径）

### 2.1 标准 SOP

| 阶段 | 角色 | 产出 | 交接物 |
|---|---|---|---|
| 1 | 视觉设计架构师 | 美学方向、色彩/字体/空间、动效语言、组件视觉规范、投屏模式 | 视觉设计规范 |
| 2 | 体验设计师 | 信息架构、页面级交互、状态清单、无障碍、**逻辑走查（反推 PRD）** | 信息架构与交互规格 |
| 3 | 前端工程师 | 组件树、store 设计、渲染分层、动效参数表、性能预算、**分阶段 Coding Agent 提示词** | 前端实现规格 |
| 4 | 主理人（我） | 审分歧、裁冲突、回写 PRD、汇编 | 本文档 |

**关键机制：交叉审查**。阶段 2 会挑战阶段 1 的方案，阶段 3 会挑战阶段 1 与 2 的可行性。这不是流程冗余，本次**三个真正的严重问题都是交叉审查发现的**（见 2.3）。

### 2.2 时间线

```
PRD v0.1 ──→ 视觉方向 ──┐
                          ├──→ 交叉审查（发现 3 个冲突）──→ 裁决 ──→ PRD v0.3
            体验规格 ─────┤
                          │
            前端规格 ─────┘         └──→ 本文档
```

### 2.3 被否决的五个方案（决策记录，这部分比结论更有价值）

| 被否决的方案 | 谁提出 | 否决理由 | 改成什么 |
|---|---|---|---|
| **区域级红色虚线框**套住整个矩阵（表达"整段都错"） | 视觉 | 学生从整块红框只能得到"我全错了"，正是三层反馈要防的归因错误；且"围起来"这个动作本身就是"这块有问题"的语气，换成灰色也只是换了色相、没换语气 | 只有真错的那 1 个字节标红，其余用 `downstream` 态安静下去；范围用**四角括（四个 L 形角标，不封口）+ 骑在顶边的文字标签**表达 |
| **诊断触发 = 单点停留 >8s / 连续回退 3 次** | PRD v0.1 | 8s 根本不够读完一段 AI 回答；反复回退恰恰是最用功的学生在对比前后态。**误判代价远高于漏判** | 空闲 ≥20s 且无有效操作，**或**同一 1–2 步窗口往返 ≥3 次且单次停留 <3s |
| **AI 栏跟着当前步自动生成正文** | PRD v0.1 | 每步都刷屏，打断矩阵区；token 成本变成"步数 × 访问次数"，不可控；削弱"先自己看"的节奏 | 预取不预显：只更新上下文头，正文必须点击才生成 |
| **首页三个入口（看/练/问）** | PRD v0.1 | "问"脱离步骤上下文就丢了唯一护城河，是伪需求 | 两入口（看/练），"问"降级为工作台内能力 |
| **前端 engine 复算判分** | 前端 | 双实现 = 双倍"状态矩阵列优先"风险；3.5 周维护不了两套引擎 + 两套标准向量测试；离线演示时 FastAPI 就在本机，前提不成立 | 后端 `POST /api/quiz/submit` 返回三层反馈，前端只渲染 |

### 2.4 三处"视觉意图正确但物理上做不到"的修正

| 原方案 | 实际约束 | 修正 |
|---|---|---|
| 行移位用 Canvas 逐行平移 | Canvas 逐帧平移会让 16 个 hex 数字全程亚像素模糊 | 位移改 **DOM 行轨 `translateX`**，Canvas 只画回绕瞬时描边闪 |
| 网格 1px 基线用 Canvas | dpr 为 1 或 125%/150% 时 1px 落 0.5px，渲染成 1.5–2px 灰线 | 网格基线改 **DOM 绘制** |
| 字重 500→600 做 280ms 过渡 | 等宽字体是静态字重，要插值必须引入可变字体 | **瞬时切换**，不进动效序列 |

> 这三条都不改变视觉结果，只改变实现载体。教训：**视觉规范说"要什么效果"，工程规范说"用什么画"**，两者不能混。

## 3. 产品逻辑如何映射成界面（核心章节）

> **这一章是本文档存在的理由。** Coding Agent 最容易犯的错是：看到"三层结构"，就做成三个页面；看到"七种字节状态"，就平均用力。下面说的是三层如何落在**同一屏**上。

### 3.1 三层 → 三个可见区域 → 三个可验收信号

| 产品层 | 界面落点 | 用户可感知的证据 | 对应功能 |
|---|---|---|---|
| **看得见** | 舞台区（C 区）：4×4 矩阵 + 轮密钥轨 + 步标题 + 变化摘要句 | 拖轮数滑块，矩阵与密钥扩展长度实时变化（证明是真实引擎，不是录好的动画） | F1 / F2 / F11 / F12 |
| **讲得清** | AI 栏（E 区）：上下文标签 + 提问 + 流式回答；引用的数值用 mono 字体 + 内凹底 | 回答里出现**你这一屏正在看的那个数** | F3 |
| **知道你哪不懂** | 批注位（E 区顶部）+ 矩阵上的关联信号（格边框描出 + 侧线刻痕） | 你不懂的时候，**它先开口**，而不是等你去找帮助 | F4 |

### 3.2 三个层为什么必须在同一屏

因为三层的因果关系是**同一条时间轴上的**：学生在第 24 步停住 → 问 → 得到解释 → 继续。任何一层被搬到独立页面，这条因果链就断了。

所以：

- **AI 栏不可是独立页面**，必须是工作台的常驻侧栏（可收成 48px 窄条，但不许跳走）
- **S 盒、密钥扩展不是独立页面**，是抽屉或工具菜单下的旁路（回答"一个单点问题"然后回工作台）
- **练习模式可以是独立页面**，因为它的任务边界是清晰的（做题），但判分结果必须能一键跳回工作台对应步
- **首页只负责一件事**：把用户送进工作台，附赠一个"不用配置就能开始"的标准向量

### 3.3 一句话验收

> 打开工作台，不点任何按钮，能否在 10 秒内回答这三个问题：**这一步在做什么？改了什么？我能不能在这里问？**
>
> 三个都能，界面就是对的；少一个，说明三层结构某一层被藏起来了。

## 4. 设计系统速查

> 完整值见 `CipherLens-视觉设计规范-v1.2.md` 第 10 章（可直接粘贴的 `:root` 块）。这里只放 Coding Agent 必须记住的部分。

### 4.1 关键 Token

| 类别 | 值 |
|---|---|
| 纸底 | `--paper-0: oklch(0.981 0.0025 250)`（不用纯白 `#fff`） |
| 主文字 | `--ink-1: oklch(0.255 0.0180 258)`（不用纯黑 `#000`） |
| 强调 | `--accent: oklch(0.500 0.0880 205)` 深青墨，C≤0.09 是刻意压低的，**不要调鲜艳** |
| 变化字节 | `--st-changed: oklch(0.855 0.1450 82)` 荧光黄 |
| 错误 | `--st-error: oklch(0.545 0.1950 27)` |
| 字节格 | `--cell-size` 离散桶 44/52/62/72（演示 88）；`--cell-gap: 6px`；`--r-cell: 2px` |
| 缓动 | `--e-out-quart: cubic-bezier(0.16, 1, 0.30, 1)`；禁用一切过冲曲线 |
| 时长 | `--d-1: 80ms` / `--d-2: 160ms` / `--d-3: 280ms` / `--d-4: 420ms` |
| 播放节奏 | `--step-interval: 800ms`（**与动效时长解耦**，0.5×=1600 / 1×=800 / 2×=400） |

### 4.2 字节七态（语义定义，视觉值见规范 §2.3）

| 态 | 语义 | 关键约束 |
|---|---|---|
| `idle` | 普通 | 无填充，1px `--line-default` 边框 |
| `changed` | 本步变化 | 满涂荧光黄 + 顶部 inset 2px 深黄条；**格子本身绝不位移、绝不缩放** |
| `selected` | 被选中 | 2px accent 边框 + 四角 6px L 形刻线 + 外 3px 环 |
| `error` | 判错 | 10% 红底 + 右下角 6px 折角三角 + 底部 inset 2px + 右上 `≠` 上标 |
| `keyed` | 密钥参与 | 6% 石墨底 + 45° 斜纹 + 左侧 3px 竖条（**叠加层，不占底色**） |
| `done` | 已播放 | **无纹理 + 1px 实线 `--line-default` + 左下角 5px 缺口**（缺口是它唯一的形状身份）+ 字重降级。**不得用点阵、不得用虚线** |
| **`downstream`** | **受首错污染** | **不得复用 `error` 任何通道**；`is-downstream` 不得被 `is-error` 选择器命中；目标观感是"安静下去"。**边框保留、只降一级（`--line-default` → `--line-hairline`），演示态不降**（见下节"四条冻结口径"） |

> **`border-width` 恒定 1px 是七态的共同前提**：上表的"2px / 3px"一律实现为「1px `border-color` + `box-shadow: inset` 叠加」，**不许直接改 `border-width`**。原因：改宽度会让 hex 位移 1px，而矩阵里位移 1px 会被读成"这个数值变了"。

**灰度验收**：截工作台 + `filter: grayscale(1)`，3 秒内必须能指出「哪几个变了 / 哪个错了 / 哪几个是被牵连的 / 哪些是密钥字节」。做不到就调明度，不调色相。

### 4.3 四操作四通道（必须一秒可辨）

| 操作 | 通道 | 实现主体 |
|---|---|---|
| 字节替代 | **点状**、逐格、列优先错峰 20ms；同步在 S 盒面板画十字准星 | DOM |
| 行移位 | **整行横向位移**（全站唯一横向）；移出边界的字节从另一侧回绕；行序错峰 40ms | **DOM 行轨** + Canvas 画回绕闪线 |
| 列混合 | **整列零错峰同步** + 垂直扫描线（全站唯一竖向）；列序错峰 60ms，总 460ms | Canvas 扫描线 + DOM 数值 |
| 轮密钥加 | 密钥层叠加 + 数值用 **`steps(4)` 离散跳变**（表达 XOR 是瞬时位运算） | DOM |

### 4.4 图层分工（硬规定）

| 层 | 负责 |
|---|---|
| **DOM** | 16 个字节数值与交互、行移位位移、网格 1px 基线 |
| **Canvas** | 列混合竖向扫描线、回绕瞬时描边闪、其他会动的几何 |
| **SVG** | 静态结构与连线（列括线、刻痕、四角刻线、S 盒十字准星） |

**绝不要把 hex 文字画进 Canvas**（亚像素模糊 + 无法选中 + 读屏读不到）。

### 4.6 四条冻结口径（改过多次，到此不再讨论）

这四条在本轮设计里各自被推翻过 3–5 次，每次都是"看起来又有一个更好的值"。**冻结的原因不是"这次的值最好"，而是每次改动的收益都小于"四份文档再次不同步"的代价。** Coding Agent 直接照此实现，不要重新设计。

| # | 口径 | 最终值 | 曾经的错误方向 |
|---|---|---|---|
| **F1** | **时间轴标记形状** | 诊断 = 上沿 **5px 圆点**；提问 = 下沿 **5px 方块、直角无圆角**。演示态 6px。**两者尺寸恒定，不随步数变化** | 曾三次改成"2px 高 × 8px 宽横条"（语义上像"一段关注区间"）。否决原因：① 提问在数据模型里是"某一步的提问次数"，是**离散点**不是区间，8px 宽度不对应任何量；② 与正上方 6px 处的 1×6px 竖刻度混读成"又一种刻度"；③ 横条宽度若随列宽变，图例永远无法与轨道像素级一致 |
| **F2** | **图例符号实现** | **复用轨道标记同一个 class**（`<i class="c-mark--ask is-legend">`），只覆盖定位、不覆盖尺寸与形状。**禁止写 `●` / `▪` / `▬` 字符** | 曾用 Unicode 字符做图例。否决原因：字符的尺寸、基线、笔画粗细由字体决定，"图例与轨道像素级一致"这条验收永远过不了 |
| **F3** | **`downstream` 边框** | 常规态：`--line-default` → `--line-hairline`（**降一级**）；演示态：**不降**，与其他态同为 2px `oklch(0.760)`。安静感由「底色 + 墨量」承担（演示态加"字重 400 对 700"）。**禁止：删边框、改 `border-width`、尺寸内缩、换线型** | ① 删边框 → 6px 间隙下一格没有框会被读成"没画完"；② 尺寸内缩 1.5px → "小"读作异常，"轻"才读作安静；③ 格线改由容器画（`gap:1px` + 容器底色）→ 与既有 `--cell-gap: 6px` 冲突，且它要治的"共享边/双线"在间隙布局下根本不存在 |
| **F4** | **几何量一律不动** | 七态 `border-width` **恒为 1px**，只改 `border-color`；需要"2px / 3px"的厚度观感时用 `box-shadow: inset` 叠加。**扩及其它几何属性：任何状态都不许改 `padding` / `margin` / `font-size` / 宽高来"强调自己"** | 曾让 `selected` 用 2px、`error` 用 3px 边框。否决原因：改宽度会让 hex 位移 1px，而矩阵里位移 1px 会被读成"这个数值变了"。**推论**：在这个界面里，任何位移或缩放都不是"强调"，而是语义污染——它会被读成"数值变了"或"这格有毛病" |

> **F3 的一个记录**：它被推翻的过程里，有一次是主理人（我）提出的"格线改由容器画"——**提出时没有核对文档里已有的 `--cell-gap: 6px`，直接假设成连续表格**。这个错误值得留在这里：它和 F1 的教训是同一条——**判定某个结构有问题之前，先查这份文档自己已经定了什么。**

**F5｜同族符号不能靠"尺寸差"区分，必须靠位置或标签区分。**

这条是 F1/F3 背后的通则，值得单列：本设计里 L 形符号出现了三次（活动区刻线 / 单格选中刻线 / 判错范围角括），如果靠"6px vs 28px"区分，**尺寸差会被视口宽度、整页缩放、投影缩放三层依次吃掉**，剩下一屏三个 L 形，谁也说不清哪个是哪个。最终解法是三层各占一个位置，**不共用任何一条边**：

| 符号 | 位置 | 有无标签 |
|---|---|---|
| 活动区刻线 | 容器外圈，**向外** | 无 |
| ~~单格选中刻线~~ | **已取消**——`selected` 改用「4 边 `inset` 描边 + 外环」，不再用 L 形。原因见下 | — |
| 判错范围角括 | 容器**内缩 6px** | **必带**「影响范围：N 字节」 |

> **为什么把格内的 L 去掉**：`error` 的右下折角与 `selected` 的四角刻线是**同位置、同尺寸、不同语义**，而"判错后点开那个错字节看来源链"是必然动作——那一刻右下角会出现"折角三角 + 一条 6px L 臂"叠在一起。更根本的是：只要格内还留一个 6px L，容器内缩 6px 的角括就和它同尺寸，F5 这条判据自己就破了。**所以 L 形族只保留两层，都在容器级，靠位置分。**

同理，`downstream` 与 `done` 不靠墨量区分（两者都是 `--ink-3`），而靠**有无缺口形状**区分。**结论：能用位置和标签的地方，不要用尺寸；尺寸是最后手段，因为它最容易被环境吃掉。**

```text

它们优先于你的审美默认值。

【产品】CipherLens · 密码透镜，一个会看你操作、知道你卡在哪一步的 AES
可视化教学平台。三层：看得见（四步可视化）/ 讲得清（选中任一步提问，
AI 带该步真实数值回答）/ 知道你哪不懂（记录停顿与回退，主动反问）。

【用户】大三网络工程/信息安全学生，课后自习（1366×768）与考前长时间注视；
另有教师课堂投影（开着灯、后排看不清）。

【设计立场】不做"漂亮的密码学 App"，做"一台被校准过的测量仪器"。气质参照
示波器、频谱仪、工程图纸。界面上的装饰权全部让给"高亮的精确性"和仅有的
几个有力动效，其余用 1px 线、字距、留白、刻度解决秩序。

【五条宪法，不可违反】
V1 零渐变、零毛玻璃、零 backdrop-filter

V4 禁止一切回弹/弹性缓动，cubic-bezier 的 y 值必须落在 [0,1]

后端 FastAPI，REST + SSE。

downstream 表示"受首错污染"，不得复用 error 的任何视觉通道，

禁止常驻 will-change（只在 .is-playing / .is-dragging 期间加）。
```

## 8. 原型反推 PRD 的规则

> 你提的要求是"如果原型中发现逻辑不顺，要反向修改 PRD"。这需要一条判据，否则每次设计讨论都会陷入"要不要改需求"的拉锯。

### 8.1 什么情况必须回改 PRD

| 判据 | 本次实例 |
|---|---|
| 原设计在**真实使用场景下会误导用户** | 区域级红框 → "我全不会" |
| 两个需求**互相矛盾**，无法同时满足 | AI 栏自动出内容 vs 单活动焦点纪律 |
| 原方案的**成本前提不成立** | 前端双引擎：3.5 周维护不了两套 |
| 原方案的**触发条件抓不到目标行为** | 8s 停留抓不到"快速来回翻步"这种最典型的困惑 |
| 原设计**丢失了产品唯一护城河** | 首页"问"入口，脱离步骤上下文 |

### 8.2 什么情况只改设计，不改 PRD

| 判据 | 本次实例 |
|---|---|
| 目标不变，只是**实现载体**换了 | 行移位从 Canvas 改 DOM、网格基线改 DOM |
| 目标不变，只是**视觉表现**换了 | 时间轴标记形状的三次反复：横条 → 方块（横条宽度是数据驱动的，无法与固定尺寸图例做到一致） |
| 只是**数值微调** | transport 72→104px、A 条 64→56px |
| 只是**补一个状态**，不改变行为 | 新增 `downstream` 第 7 态 |

### 8.3 本次记录

| 类别 | 条数 | 明细 |
|---|---|---|
| 回改 PRD | 15 条 | 12 条来自体验走查（详见 PRD v0.3 变更记录）+ 3 条来自后续交叉审查（诊断双条件、`downstream` 态、7.1 视觉红线） |
| 只改设计 | 6 条 | 三处图层修正、时间轴标记形状、transport 高度、A 条高度、离散桶尺寸、AI 栏收起方式 |
| 否决的设计方案 | 5 条 | 见 2.3 |

**记一条经验**：这一轮下来，改 PRD 的条数（15）远多于改设计的条数（6）。这说明**逻辑问题比视觉问题多得多**——所以做原型时先走一遍逻辑，再谈好看。反过来做，会白画很多稿。
