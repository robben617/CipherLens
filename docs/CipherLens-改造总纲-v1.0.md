## §0 一页看懂

**改什么**：不是加功能，是给一堆能用的零件装上讲解逻辑。

| 现在 | 改完 |
|---|---|
| 首页 9 行 DOM、两行字挤在左上角 | 五段结构，第一屏说清「这是什么、能干什么」 |
| 只能看写死的 FIPS 向量 | 输入自己的明文和密钥 |
| 16 个数字，没有任何解释 | 每步四件套：人话 / 类比 / 数学 / 常见误解 |
| 「字节代换」「列混合」当标题用 | 12 条术语，首次出现就地展开，含纠错行 |
| 40 个孤立动画 | 10 轮循环，每轮结尾一张小结卡 |
| AI 吐一串十六进制 | 结论 / 为什么 / 下一步 / 依据 四块 |
| S 盒页 4 行空壳、密钥扩展弹「未接入」 | 可算的 S 盒 + 可展开的 11 组轮密钥 |
| 只能加密 | 加密 + 解密双向 |
| 8 张表 7 张零写入 | 练习与记录真实落库 |
| 「来源候选字节：4 个（source_bytes）」 | 「你第 3 个字节在**第 2 轮列混合**时算错了，先回看那一步」 |

**改完什么效果**：一个完全不懂密码学的人，从打开首页开始，能自己走完「知道这是什么 → 看懂一步 → 看懂一轮 → 手算一格 → 手算一轮 → 讲清为什么安全」这条完整链路，不需要旁边有人讲。

**工作量**：15.4 人日明细，按 16 人日排期，5 人并行约 9 个工作日。

## §1 三个根因

所有表面问题归到最后只有三条，方案里每个功能都在解其中一条。

### 根因一：缺路（结构性）

首页是死胡同——点进工作台后回不来，练习页和记录页各自手写一个「返回首页」，样式还不一样。没有任何页面告诉用户「你现在在整条学习路径的哪一步」。

> 对应：**F01**（外壳与导航）、**F05**（41 格进度地图）、**F06**（三关引导）

### 根因二：缺台阶（教学性）

三个断点，一个比一个致命：

| 断点 | 现状 | 后果 |
|---|---|---|
| 单步 → 一轮 | 能看到第 7 步变了 4 格，但没人说「这一轮完成了混淆、扩散、密钥叠加」 | 40 步看完，不知道走了 10 轮 |
| 看懂 → 会做 | 练习第一题就要填 32 位完整密文 | 100% 卡死，然后关页面 |
| 会做 → 讲得出 | 走完 40 步没有任何收束 | 面试问「AES 为什么安全」，答不出来 |

> 对应：**F15**（一轮小结卡）、**F12**（四级练习梯度）、**F16**（雪崩实验）

### 根因三：缺人话（文案性）

不是没有文字，是文字写在给开发者看的地方。三处最典型：

- **首页连一句承诺都没有**——只有标题和「进入工作台」；
- **矩阵 16 个数字没有任何读法**——不说清「灰 = 没动、黄 = 这一步改了、斜纹 = 参与密钥运算」，新手看到的就是天书；
- **判分反馈用内部字段名**——`source_bytes` 出现在用户界面上。

**术语这一层还要单独说**：`SubBytes / ShiftRows / MixColumns` 译成「字节代换 / 行移位 / 列混合」，看着像人话，其实全是陷阱——用户以为自己懂了「移位」，看到矩阵错位时会觉得「这不是我理解的那个移位」。**中文译名制造了虚假的熟悉感，比英文原名更危险。**

> 对应：**F02**（首页承诺）、**F04**（解说层 + 12 条术语）、**F12**（人话错因）、**F13**（安全边界页脚）

## §4 两条数据线

改造的骨架是代码，血肉是两份数据文件。**这两份没写，功能做出来也是空壳。**

### 4.1 `frontend/src/data/step-copy.ts`——13 段文案

每步一条，四个字段：

```ts
export const STEP_COPY: Record<string, StepCopy> = {
  sub_bytes: {
    plain:  '把每个字节换成 S 盒里对应的那个值。',      // 人话：做什么
    analog: '像查字典：给一个字，翻到它，抄下解释。',    // 类比
    math:   'b′ = S[b]，S 是一张 256 项固定表。',       // 数学：只给结论式
    pitfall:'不是随便换个值——表是固定的，谁算都一样。',  // 常见误解
  },
  // shift_rows / mix_columns / add_round_key 同构
}
```

**四件套里 `pitfall` 最重要**，市面上没有这种写法，但它是唯一能解决「以为自己懂了」的手段。

### 4.2 `frontend/src/data/glossary.ts`——12 条术语

五个字段：`name` / `en` / `action` / `analogy` / `pitfall`。

| 级 | 12 条 |
|---|---|
| L1（9） | 状态矩阵、轮、字节代换、行移位、列混合、轮密钥加、S 盒、密钥扩展、轮密钥 |
| L2（3） | 混淆、扩散、GF(2⁸) 与异或 |

**L3 不进主表**（只在用到处给一句话）：轮常数 Rcon、分组模式、逆 S 盒、填充。

**四个必须写清的 `pitfall`**：

| 术语 | 要拆穿的假熟悉 |
|---|---|
| 字节代换 | 不是随便换，是查一张 256 项固定表 |
| 行移位 | 第 r 行循环左移 r 字节，位移量由行号决定 |
| 列混合 | 顺序完全不变，值全变了 |
| 轮密钥加 | 是按位异或，不是算术加法 |

**呈现方式（这是本次最关键的一处修改）**：

- 首次出现**就地展开**三行卡，插在解说条内，不弹窗不跳页；
- 之后收为虚线下划线，hover / Tab 回看；
- D 区加「本步术语」按钮，给「滑过去了但后面卡住」的人一条回头路。

**为什么不用 hover 做主方案**：初学者不会去 hover 一个自己不认识的词——他不知道该查，直接滑过去，然后卡在后面某一步，还不知道卡在哪。**hover 只服务回看，不承担首次教学。**

**必须同源**：现在有 5 处各写一遍的步骤名映射（`Timeline.vue:90`、`PracticeView.vue:141`、`aes_impl.py:27`、`tutor_service.py:9`、`records_service.py:22`），全部改为读同一份数据；后端加 `GET /api/glossary`，让 AI 回答引用同一文案。否则界面和 AI 会说出两个版本，用户以为是两个不同的东西。

## §5 红线（八条，不许碰）

前五条沿用既有规范，后三条为本次新增。

| # | 红线 | 原因 |
|---|---|---|
| 1 | 字节格间距恒为 `--cell-gap: 6px` | 改了整块矩阵尺寸变，所有截图和验收作废 |
| 2 | 七态字节通道不新增第八态 | 通道已排满，加一态必然与既有态混淆 |
| 3 | 状态变化只改颜色/描边，**不改尺寸、不位移** | 位移会造成视觉跳动，40 步看下来极累 |
| 4 | 判分只在后端，前端不复算 | 前端复算等于给答案 |
| 5 | 投影下正文对比度 ≥ 4.5:1 | 教室投影会吃掉一档对比度 |
| 6 | 不引 UI 框架（Element/Vuetify）、图标库、字体 CDN | 大赛环境网络不可控；且会让「精密仪器」气质变成通用后台 |
| 7 | 不改任何数值口径（827/82/81、Recall@5 0.90 之类） | 数值是评测出来的，改了就对不上评测集 |
| 8 | 不把内部术语上屏（A 区/B 区/C 区、`source_bytes`、`op`） | 这是给开发者看的，用户看不懂 |

**特别提醒一处 token 陷阱**：字节格取 `--rule-region-ink`（常规 0.845 / 演示 0.545），**不是 `--line-default`**——后者在演示模式下只有 0.760，投影出来是 2.9:1，必灰。

### 6.2 手工（答辩前必过）

1. 给一个**没学过密码学的人**，只看首页 30 秒，问「这是干什么的」，能答对。
2. 他能不看说明书，自己找到输入框，输入任意明文。
3. 他走 40 步时，每一步都能说出「这一步在干什么」（四件套的第一句）。
4. 走到第 4 步（一轮结束）时，小结卡能让他说出「刚才走完一轮了」。
5. 矩阵 16 格的中心位置在整个过程中**不位移**（改造前后截图对比，top 差值 = 0）。
6. 开启系统「减少动态效果」后，F14 动画静态显示，不闪。
7. 投影（或把亮度调到 60%）下，字节格数字仍可辨认。
8. 术语卡：任取 4 条，`pitfall` 字段非空且能在页面上看到。
