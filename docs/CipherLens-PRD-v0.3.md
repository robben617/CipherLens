# 第一部分 · 核心问题清单

## Q1 产品解决什么问题？

**问题定义**：AES 的四步（字节替代、行移位、列混合、轮密钥加）在教材里是静态图和公式，学生能背流程但建立不起直觉。现有可视化工具能"播放"这个过程，但播完就结束——**学生卡住的那一刻，没有任何东西回应他**。

拆成三个可验证的具体问题：

| 编号 | 问题 | 表现 | 可验证方式 |
|---|---|---|---|
| P-1 | 四步是黑盒变换 | 学生能说出"先字节替代再行移位"，但说不清某一步具体改了哪几个字节、为什么这么改 | 让学生指着屏幕说"这一步改了哪 4 个字节"，说不出的比例 |
| P-2 | 工具只演不教 | 播放器无法回答"我这一步为什么错"，只能从头再放一遍 | 现有工具里找不到"针对当前步骤提问"的入口 |
| P-3 | 卡壳无人知晓 | 教师看不到全班在哪一步集体卡住，只能凭经验重复讲 | 教师端无任何步骤级数据 |

**本项目只解决 P-1 与 P-2，顺带为 P-3 留数据接口（教师端为 P2，可砍）。**

## Q2 目标用户是谁？

| 角色 | 画像 | 核心目标 | 能力水平 | 使用频率 |
|---|---|---|---|---|
| 学生（主） | 网络工程/信息安全专业大三，正在学《密码学》或《信息安全技术》，刚学完 AES 轮函数 | 考试能算对、答辩能讲清、不靠死记硬背 | 会写代码，理解异或与矩阵，但不熟悉 GF(2⁸) | 每周 2–3 次，考前集中 |
| 教师（次） | 任课教师，需课堂投屏演示 + 课后了解学情 | 演示直观、知道谁没懂 | 高，但不愿学新工具 | 每学期数次 |

**主用户判定依据**：任务书方向一明确面向"校园/实训"场景，且要求"AI 辅导对话"，辅导对象是学生。教师端不在任务书要求内，故降级。

**画像可靠性声明**：以上画像基于任务书要求与选题参考推断，**未做真实用户访谈**。第 3 周需补 3–5 名同班同学试用并记录反馈（这同时是大赛 H3 的得分依据）。

## Q3 用户现在的解决方案及不足？

| 现有方案 | 学生怎么用 | 不足 |
|---|---|---|
| 教材静态图 + 板书 | 看、抄、背 | 看不到中间状态变化；无法回看某一步 |
| 手算练习 | 纸上算一两轮 | 极易出错且不自知；算错不知道错在第几步 |
| 开源可视化工具（GitHub 上 7 个同类，已调研） | 输入明文点播放 | 能播能单步，但**回答不了"我为什么错"**，也不会主动发现你卡住 |
| 视频教程 | 看别人讲 | 单向、不能按自己的输入算 |
| 直接问通用 AI（ChatGPT 等） | 描述问题后提问 | **它不知道你在第几轮第几步、屏幕上是什么数**，只能泛泛讲；也不会主动发现你卡住 |

**关键洞察**：通用 AI 助手是本品最强的替代品，但它缺两样东西——**当前步骤的真实数值**、**你的操作行为**。这两样恰好是我们的产品壁垒。

## Q4 竞品与差异化在哪？

竞品分三层，差异化逐层说明：

| 层级 | 代表 | 它做到哪 | 我们的差异 |
|---|---|---|---|
| 同类可视化工具 | GitHub 上 7 个项目（AES_Visualizer / AES-TraceLab / cipherflow-visualizer / CryptoViz 等） | 逐步可视化、单步、S 盒、部分配解释文字 | **它们停在"看得见"，我们做"看不看得懂"**：记录操作轨迹 → 判定误解 → 主动反问 |
| 挑战式学习平台 | CryptoHack | 动手破解、积分、难度分级 | 它是"做题驱动"，需要先有基础；我们是"理解驱动"，从看懂开始 |
| 通用 AI 助手 | ChatGPT 类 | 泛化讲解、随时可用 | **不知道你的上下文**：我们注入当前 `StepSnapshot` 真实数值 + 误解标签，它只能猜 |

**三点硬差异化（调研范围内无同类实现）**：

| 编号 | 差异化 | 为什么别人做不到 |
|---|---|---|
| D1 | 操作轨迹 → 误解判定 → 主动反问 | 需要专门埋点采集停顿/回退/重复点击，并设计误解规则库，纯可视化项目没有这层 |
| D2 | LLM 上下文注入当前步骤真实数值 | 需要引擎产出结构化快照并对齐提示词，多数项目没有结构化 trace |
| D3 | 判分定位到"第几轮第几步哪个字节" | 需要引擎能反向对比中间状态，选择题型做不了 |

**差异化边界（明确不做）**：不做第二算法（RSA/SM4/DES）、不做剧情闯关、不做 3D 场景。理由：选题参考明确"不要贪多"，且方向四面向非技术人群，与任务书人群不符。

## Q5 MVP 做什么？哪些先不做？

**这里有个前提必须先说清**：本项目不是纯商业项目，MVP 不能按"砍到最小"来定义。

> **实训的 16 项交付是验收底线，一项都不能砍；大赛的 6 项是叠加层。**
> 所以 MVP 的定义是：**先保证 16 项验收全过的最小闭环，再在这一层之上加差异化。**

## Q6 最终形态？

**Web 网站（Vue3 单页应用 + FastAPI 后端），不是小程序、不是 App、不是插件、不是内部工具。**

| 形态 | 是否可行 | 判定依据 |
|---|---|---|
| **Web 网站（选）** | 可行 | 任务书模块 1 硬性要求 Vue.js 前端、模块 7 要求部署上线；大赛硬性要求 Web 网站且决赛须现场真实演示 |
| 小程序 | 否 | 任务书未要求；多一端多一套调试；Canvas 动画在小程序上表现受限 |
| App | 否 | 分发成本高，评委无法现场安装 |
| 浏览器插件 | 否 | 与"教学平台"定位不符，无法承载多页面结构 |
| 内部工具 | 否 | 大赛要求可访问、可演示；内部工具无公网入口则无法现场评审 |

**技术形态补充**：单页应用 + 后端渲染接口文档，桌面端优先（≥1280×720），响应式适配到平板，不做手机端专项优化。

# 第二部分 · PRD 主体

## 1. 产品定位

**一句话**：一个会看你操作、知道你卡在哪一步的 AES 可视化教学平台。

**三层结构**（这是与所有同类工具的本质区别）：

| 层 | 做什么 | 用户感知 |
|---|---|---|
| 看得见 | 四步 + 正逆 S 盒 + 状态矩阵 + 密钥扩展，播放/单步/回退/调参 | "原来这一步是这么变的" |
| 讲得清 | 选中任一步提问，AI 带着**这一屏的真实数值**回答 | "它讲的是我正在看的数" |
| 知道你哪不懂 | 记录停顿/回退/反复点击，判定误解，主动开口问 | "它先发现我不懂" |

**不做什么**（定位反面试金石）：不做算法百科、不做 CTF 靶场、不做游戏化闯关、不做通用密码学课程平台。

## 2. 用户痛点与场景

### 痛点优先级

| 编号 | 痛点 | 严重度 | 频率 | 现有方案为何不行 |
|---|---|---|---|---|
| PT-1 | 说不清某一步改了哪几个字节 | 高 | 每节课 | 静态图只有前后态，没有"变的是哪几个" |
| PT-2 | 算错了不知道错在第几步 | 高 | 每次练习 | 纸面手算无中间态可比对 |
| PT-3 | 卡住时无人可问（老师不在、同学也不会） | 中高 | 课后高频 | 通用 AI 不知道你的上下文 |
| PT-4 | 不知道自己是"没懂"还是"算错" | 中 | 考前 | 无诊断，只有对错 |

### 三个用户故事

| 编号 | 故事 | 验收标准（Given/When/Then） |
|---|---|---|
| US-1 | 作为刚学完 AES 的学生，我想在任意一步停下来问"为什么"，以便不靠死记硬背也能理解轮函数 | Given 已生成 trace 且停在第 3 轮列混合，When 点击该步的"问这一步"，Then **首字 3 秒内到达**、20 秒内完成，且解释中至少出现 2 个该步真实数值 |
| US-2 | 作为做错练习的学生，我想知道错在第几轮第几步哪个字节，而不是只看到红叉 | Given 提交错误密文，When 判分完成，Then 返回首次出现差异的轮次、步骤名与字节下标，并在矩阵上高亮该字节 |
| US-3 | 作为在同一位置反复回退的学生，我想被主动发现，而不是自己去翻帮助 | Given 页面**空闲 ≥20s 且期间无任何有效操作**（非单纯停留），或反复回退后仍未产生有效操作，When 命中诊断规则，Then **AI 栏顶部出现一条"红线批注"反问**（红竖条 + 手绘方括号，不进浮层、不遮矩阵与时间轴），同时目标字节格边框被红色逐边描出；若用户点"不是"，同类提示 10 分钟内不再出现 |

## 3. 需求范围

### 3.1 功能清单

| 编号 | 功能 | 优先级 | 关键规则 |
|---|---|---|---|
| F1 | AES 可视化引擎 | Must | 自实现，不调加密库；状态矩阵列优先；每步产 `StepSnapshot`；**只对变化字节做动画** |
| F2 | 步进控制 | Must | 逐步播放 / 单步前后 / 跳过整轮 / 时间轴任意跳转 / 密钥长度 128·192·256 切换 |
| F3 | 步骤级 AI 辅导 | Must | 上下文注入当前快照；只讲这一步；SSE 流式；**双阈值降级（首字 3s 安抚 / 总 20s 降级）**。**响应分三类 intent**（v0.2）：`hint`（只给提示）/ `explain`（完整讲解）/ `check`（判对错）。诊断触发的反问默认 `hint`，但**每条 hint 末尾必须留"给我完整解释"出口**——学生连续追问三次都被"你想想看"打回，是 AI 产品最招恨的行为 |
| F4 | 认知诊断 | Should | 3 类误解规则（轮密钥时机 / 列混合系数 / 密钥扩展方向）。**触发条件为两条取或**（v0.3）：① 页面空闲 ≥20s 且无有效操作（单纯停留读 AI 回答不算卡住）；② **同一 1–2 步窗口内往返 ≥3 次且单次停留均 <3s**（快速来回翻步是"我在对比前后两屏"的典型形态，总停留时间很短，纯超时条件抓不到；附条件"单次停留 <3s"用于排除慢速往返——那是学生在仔细对照阅读，属于会学习的行为）。**频率限制**：同屏最多 1 条、间隔 ≥45s；**必须提供 `?debug=diagnosis` 可复现入口**（答辩演示用）；主动反问不给答案，但必须留"给我完整解释"出口 |
| F5 | 练习模式 | Must | 加解密填空 + 参数调试；客观题程序判分。**判分反馈分三层**（v0.2）：第一层一句总结（"12 个字节中 3 个错误"）→ 第二层定位首个差异（轮/步/字节）→ 第三层**错误传播图**：把因首个错误而受污染的下游字节"灰化"而非标红。理由：AES 具有雪崩性，第一步算错则后续全错，满屏红会让学生归因为"我全不会"从而放弃。**为此字节需要第 7 态 `downstream`**（v0.3）：去角标 + 边框降一级（`--line-default`→`--line-hairline`，宽度仍 1px）+ 底色退一档 + 弱化文本，**不得复用 `error` 样式、不得被 `is-error` 选择器捕获**，否则第三层失效。**注意：不是"1px 灰虚线"——虚线在本项目里专表"未生效/待定/禁用"，`downstream` 不属此列；也不能删边框，6px 间隙下缺一条框会被读成"这格没画完"** |
| F6 | 用户与学习记录 | Must | 注册登录、算法历史、错题本、学习轨迹 |
| F7 | 教师端学情 | Could（可砍） | 全班步骤级卡壳分布热力图 |
| F8 | ECB/CBC 对比 | Should（有余力） | 只做这两个模式；图像加密轮廓对比 |

## 5. 核心流程

### 5.1 主流程（学生第一次看懂一步）

```
进入首页
 └→ 点"一键载入标准向量"或自填明文/密钥
     └→ 工作台生成全量 trace（后端算，前端拿快照数组）
         └→ 点"逐步播放"：矩阵按步更新，只对变化字节做 200ms 过渡
             └→ 播放到任意步停下（暂停 / 单步 / 点某格）
                 └→ 右侧 AI 栏自动带出"这一步在做什么"的引子
                     └→ 学生点"问这一步"或直接输入问题
                         └→ AI 返回解释（流式），解释里出现该步真实数值
                             └→ 学生可继续追问（多轮）
```

**关键设计（v0.2 修订）**：AI 栏**预取不预显**——切步时只更新上下文头 `CTX: R3 · MixColumns · C[1]` 与本地建议 chip，**解释正文必须由用户点击才生成**。

原方案是"跟着当前步自动出内容"，此设计已否决。理由有三：① 每步都自动生成正文，等于每步都在刷屏，矩阵区的变化会被右侧文字流打断，"单活动焦点"被破坏；② 自动生成会让 token 成本变成"步数 × 访问次数"，成本不可控；③ 学生未提问就给出答案，会削弱"先自己看、再看解释"的学习节奏。

**配套**：生成 trace 后**不自动播放**，页面显示"已算完全部 24 步，按空格开始"。理由：自动播放会立刻启动空闲计时从而干扰诊断判定，且用户第一反应是找暂停按钮——开场就把主动权交给用户，体验更稳。

### 5.2 分支流程（被诊断发现）

```
学生在第 2 轮列混合附近，页面空闲 ≥20s 且期间无有效操作（或反复回退后仍未产生有效操作）
 └→ 前端埋点累计（本地节流，不实时打接口）
     └→ 命中规则 → 上报事件 → 后端诊断返回误解类型
         └→ AI 栏顶部出现"红线批注"（2px 红竖条 + 手绘方括号 + 一句反问）
            "你是不是在困惑：列混合为什么会让一个字节扩散到一整行？"
            （下方 11px 小字：这是系统的推测，不是判错）
            关联位置用两条非浮层信号：目标字节格边框红色逐边描出 + AI 栏左分隔线上的 12×2px 红刻痕
             └→ 点"是" → AI 展开讲解 + 给一个单步训练入口
             └→ 点"不是" → 记录否定，同类提示 10 分钟内不再出现
             └→ 不理会 → 批注保留，transport 标记轨上留一个诊断圆点（可回看）

**形态约束（v0.2 修订）**：批注**不得覆盖矩阵与时间轴**，故取消原"左侧 40px gutter"方案，改写在 AI 栏顶部。理由是批注本身是"边栏里的批注"，而不是画在字符上的圈注——这与校样纸的隐喻反而更一致。

**阈值修正说明（v0.2）**：原方案"同一位置连续回退 3 次或单点停留 >8s"已否决。理由：① 8 秒停留根本不能作为卡住的证据——认真读一段 AI 回答通常要 20 秒以上；② 反复回退恰恰是会学习的学生行为（在对比前后状态），把它当卡住信号会误伤最用功的人；③ **误判的代价远高于漏判**——一次"你是不是不懂"的错误质疑，会让学生觉得系统在监视他。故改为"空闲时长 + 无有效操作"的组合条件，并把频率压到间隔 ≥45s。

**答辩专用**：提供 `?debug=diagnosis` 强制触发入口。现场演示不能靠"请大家等 20 秒"。

**异常兜底**：若诊断接口失败，静默不提示，不打断学习。

### 5.3 异常流程

| 场景 | 处理 |
|---|---|
| 明文/密钥长度非法 | 输入框即时标红 + 说明正确长度，不等到提交才报错 |
| 明文超过 1 个分组 | 提示"当前版本只演示单分组"，只取前 16 字节并明确告知 |
| AI 接口超时（>8s） | 降级为本地预写模板 + 一行轻提示"当前为离线讲解" |
| AI 返回内容不含本步数值 | 前端标记为"通用讲解"，不当作步骤级回答展示 |
| 未登录就想存错题 | 提示登录，允许先练，登录后合并本地记录 |
| 刷新页面 | 通过 URL 参数 + localStorage 恢复上次的明文/密钥/步序 |
| 导出失败 | 保留在当前页，给出重试入口，不跳走 |

## 6. 技术方案

### 6.1 整体架构

```
┌────────────────────── 浏览器（Vue3 + Vite + Pinia） ──────────────────────┐
│ 展示层   SVG/Canvas 渲染器（矩阵 / S盒 / 密钥扩展）                       │
│ 控制层   步进控制器（播放 / 单步 / 回退 / 时间轴）                         │
│ 采集层   操作埋点（停顿 / 回退 / 重复点击），本地节流后批量上报            │
└───────────────────────────────┬───────────────────────────────────────────┘
                                │ REST + SSE
┌───────────────────────────────▼───────────────────────────────────────────┐
│ FastAPI（Python 3.11）                                                     │
│  aes/     引擎与 trace 生成（纯函数，无外部加密库）                        │
│  session/ 会话与操作事件                                                   │
│  tutor/   AI 辅导（上下文裁剪 / 缓存 / 超时降级）                          │
│  quiz/    题库 / 判分 / 错因定位                                           │
│  export/  CSV / JSON / PNG                                                 │
│ SQLite：users / sessions / step_events / diagnoses / quiz / attempts       │
└───────────────────────────────┬───────────────────────────────────────────┘
                                │
                     ┌──────────▼───────────┐
                     │ LLM API（码道 / 华为云）│
                     └──────────────────────┘
```

### 6.2 核心数据结构（前后端契约）

```python
StepSnapshot:
  index: int              # 全局步序，时间轴定位用
  round: int              # 0..Nr
  op: str                 # sub_bytes | shift_rows | mix_columns | add_round_key
  state_before: bytes     # 16 字节，列优先
  state_after: bytes
  changed_bytes: list[int]# 变化的字节下标 → 前端 diff 高亮
  round_key: bytes        # 本步参与的轮密钥
  meta: dict              # 该步专属：如列混合的系数、S盒输入输出对
```

**为什么这么设计**：① 时间轴拖拽按下标取快照，无需重算；② 四种操作共用一套渲染器；③ AI 辅导直接把快照序列化进 prompt，天然满足"携带真实数值"。

| POST | `/api/aes/step` | 单步变换（单步训练用） | 只算一次操作 |
| GET | `/api/aes/sbox` | S 盒 / 逆 S 盒 / 逆查 | 支持 `?q=` 查询 |

### 6.4 AI 调用设计

| 环节 | 策略 |
|---|---|
| 上下文构造 | 系统提示 + 当前 `StepSnapshot`（截断为可读摘要，约 200 token）+ 前后各 1 步摘要 + 误解标签。**不传全量 trace** |
| 提示词约束 | 只讲这一步；必须引用本步至少 2 个数值；不确定就说"这一步我不能确定"；不给答案只给提示（诊断场景） |
| 输出形式 | SSE 流式，首字延迟优先 |
| 超时与降级 | **双阈值**：首字 3s 未到 → 显示"正在取这一步的数据"（不降级，仅安抚）；总 20s → 降级本地预写模板。缓存命中 → 直接返回不调模型。**原方案"8s 超时"已否决**：它会与 US-1 的"8 秒内返回"在同一时刻冲突，出现"字刚出来又被降级替换"的闪烁 |
| 匿名配额 | 未登录每会话 10 问、每日 20 问（服务端计数）。**原方案无限制**，可被脚本打穿成本 |
| 可追溯 | 每次记录 model 版本 + prompt 版本 + 输入快照哈希，便于复现 |
| 成本控制 | 开发期默认走本地模板，仅联调与演示开真模型 |

### 6.5 数据模型（SQLite）

| 表 | 关键字段 |
|---|---|
| `users` | id, username, password_hash, created_at |
| `sessions` | id, user_id(nullable), **mode**(learn/present/practice/quiz), plaintext, key, key_bits, **anon_merged**(bool), created_at, **last_active_at** |
| `step_events` | id, session_id, step_index, event_type(pause/back/click_repeat), dwell_ms, created_at |
| `diagnoses` | id, session_id, step_index, misconception_type, responded(bool), created_at |
| `quiz_items` | id, type, difficulty, misconception_tag, question, answer, explanation |
| `attempts` | id, user_id, item_id, submitted, is_correct, first_diff_round, first_diff_step, first_diff_byte |
| `tutor_logs` | id, session_id, step_index, prompt_ver, model_ver, latency_ms, degraded(bool) |

**`session.mode` 字段的必要性（v0.2 新增）**：教师用演示模式投屏时产生的操作轨迹，会与学生学习轨迹混在一起，直接污染学情热力图——制造出"全班都卡在列混合"的假象，而实际只是老师在演示时停在那里。故必须在写 `step_events` 时就按 `mode` 分流，`mode=present` 的会话**不进入学情统计**。这是三条独立的事，不要混为一谈：
- **演示模式** = 一个视图状态（放大 + 提对比 + 删次要信息），写 `session.mode='present'`
- **教师端看板（PG-11）** = 一个独立页面，读的是学生 `mode='learn'` 的聚合数据
- **埋点分流** = 数据层规则，决定哪些事件进入统计

**匿名会话合并规则（v0.2 新增）**：未登录也可完整使用，本机生成错题本（`localStorage`）。一旦产生第一条记录，即出现常驻轻提示"登录后可跨设备保留"。登录时执行合并：以 `session_id` 为主键合并，`anon_merged=true` 留痕，冲突时以时间较新的记录为准，**不覆盖用户已登录后产生的数据**。原方案等到"点加入错题本"才提示登录，属于典型流失点。

**两个必须在 UI 上显式标注的隐蔽约定**（来自交互走查）：
1. **字节下标从 0 开始**：教材常用 1 起编号，学生按教材去找会找不到。诊断文案与判分定位中出现的下标，必须在界面某处一次性显式说明"下标从 0 开始"。
2. **状态矩阵是列优先**：必须用视觉手段（列括线 + 列标签置于上方）常驻暗示，而不是靠文字解释一句就过。

### 7.1 视觉设计红线（v0.3 新增，适用于全站与后续所有页面）

> **区域级、大面积的视觉通道，只能表达"范围"或"程度"，不能表达"对错"。**

这条来自一次具体冲突：为"首步即错导致整段都错"设计区域级红色虚线框，直觉上合理（整个区域都有问题），但会把已修正的归因错误重新装回去——学生看到整块红框只会得到"我全错了"这一个结论，而这正是 F5 第三层要防止的事。

正确做法：只有真正错的那 1 个字节用 `error` 态；其余下游污染字节用 `downstream` 态安静下去；区域的"范围"信息用**四角括（四个 L 形角标围出范围，不封口）+ 文字标签**（如"影响范围：16 字节"）表达。

> **为什么是"四角括"而不是"外框"**：围起来这个动作本身就带"这块有问题"的语气，只是从红色换成了灰色——**换了色相，没换语气**。四角括只标出边界、不形成闭合轮廓，读的是"从这里到这里"，不是"这一块有问题"。

**红线一的执行细则（v0.3 修订，这条改过三次，理由全部留档）**：

`downstream` 的视觉实现出现过三个结论，最终定稿的是第三条：

| 版本 | 结论 | 为什么不行 / 行 |
|---|---|---|
| v1.1 | 去掉格子边框 | 矩阵每格的外框是它自己的完整矩形，抽掉一格的框不会被读成"安静"，会被读成**"这格没画完"**——在一群自带完整外框的方块里，缺一个框比浅一个框显眼得多 |
| v1.2 | 边框降一级（极淡实线） | 方向对，但**只对常规态成立**；演示态降一级会被投影抹平成纸色，抹平后同样变成"没画完" |
| v1.2 中途 | 格线改由矩阵容器统一绘制（`gap:1px` + 容器底色），格子不写 `border` | **已作废**。矩阵是 `--cell-gap: 6px` 的独立 chip 布局，容器底色会在 16 格之间填出 6px 实色条带而非 1px 细线；且该方案要治的"相邻格共享边/双线"在 6px 间隙下**根本不存在**（每格边框互不接触）。**提出它的人（我）没有核对 §6.2 已有的 `--cell-gap`** |
| **定稿** | **边框保留，宽度恒为 1px，只有 `border-color` 随状态变**：常规态 `--line-default` → `--line-hairline`（降一级）；**演示态不降**（与其他态同为 2px），安静感由底色 ΔL 0.06 + 字重 400 对 700 承担。需要"加粗感"的状态用 `box-shadow: inset` 叠加，不动 `border-width` | 前两版争的是"降多少"，真正缺的是另一条：**`border-width` 一改，hex 就位移**。把宽度钉死在 1px 之后，"降级/加粗"都不用碰盒模型，位移恒为零 |

**这条的普适形式（改过一次，这一版才成立）**：

1. **宽度的恒定性与颜色的可变性必须分开**——`border-width` 恒定、`border-color` 承载状态，需要厚度就用 `inset` 叠加。任何"改宽度"的状态都会让内容位移，而矩阵里位移 1px 就会被读成"数值变了"。
2. **"减墨"类状态的上限是"还看得出这是个格子"**——低于这条线就不叫安静，叫缺失。演示态因为对比度被投影压缩，"还看得出"的下限会提高，所以在演示态宁可不靠边框表达差异。

**这条不只适用于练习页**——错题本的错题分布、学习记录的步骤热力图、教师端看板都会再遇到。凡是"一片区域有问题"的表达，都不许用"红色面积"。

**矩阵格四角分配规则**（v0.3 新增，防未来撞车）：

| 角位 | 用途 |
|---|---|
| 左上 | 反向单步 |
| 右上 | 已变化 |
| 右下 | 错误 |
| 左下 | 已完成 |

约束：同格最多 2 个角标；新增角标须先申请空位；**任何标记不得进格心**（格心是 hex 数值，被占即不可读）。本轮已出现三个角标几乎同时出现的情况，不定规则下一次加状态必然冲突。

**红线二：视觉强度必须与信息的重要性成正比，且不得超过它。**（"不得超过"是关键——首错导致整片变化时，最重要的信息是"你只错了 1 处"，而不是"这一片都有问题"。）

**线型语汇必须钉死，不许兼职**：

| 线型 | 唯一含义 |
|---|---|
| 虚线 | 未生效 / 待定 / 禁用 |
| 实线 | 已生效 / 确定 |
| 不用线型 | 明确"不强调" |
| 点划线 | 仅演示态，替代纹理 |

准入规则：新增线型用法前先在这张表里找它属于哪一行；**找不到，说明这个状态需要的不是线型，而是形状或文本**。本轮核查发现"虚线"被使用 11 次且语义一致（空格占位、计算中、禁用态、判分锁定等），唯一例外是"已完成"态误用虚线框——该例外已改为实线 + 左下缺口。
