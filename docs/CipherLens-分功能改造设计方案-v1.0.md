## §0 这份文档怎么用

### 0.1 三条执行纪律

1. **先契约后实现**：每个功能先定「输入 → 处理 → 输出 → 验收」，再动代码。
2. **一次一个功能**：功能之间允许有依赖（见 §5 依赖列），但不允许一个提交里混两个功能。
3. **验收可复现**：每个功能的验收条目必须是「点哪里、看到什么」，不能写「体验更好」。

### 0.2 每个功能的统一模板

本文 §6 的每个功能都按同一结构写，缺一项就不算设计完成：

| 段落 | 回答的问题 |
|---|---|
| 目标 | 用户能多做到一件什么事 |
| 现状（带证据） | 现在是什么样，问题出在哪个文件哪一行 |
| 前端改动 | 加/改哪些文件，布局、状态、交互、无障碍 |
| 后端改动 | 接口契约、数据结构、错误码 |
| 验收 | 怎么判断做完了 |
| 不做什么 | 防止改飞 |

### 0.3 与既有文档的关系

本文**不推翻**以下文档，只在其上做增量，冲突时以本文为准（因为本文晚于它们且基于实测代码）：

## §1 现状诊断：三层结论

任务书要的是「看得见、讲得清、练得会」。目前三层各自的真实状态：

| 层 | 结论 | 关键证据 |
|---|---|---|
| **看得见** | 达标 | 五区布局成型；七态字节；四轨时间轴；Docker 下 `POST /api/aes/trace` 返回 `69c4e0d8…`，与 FIPS-197 C.1 一致 |
| **讲得清** | 壳在，核不在 | 步骤标签只有「第 2 轮 列混合」；AI 回答是 `tutor_service.py:49-67` 的 f-string 模板；`SBoxView.vue` 全文 4 行；密钥扩展抽屉 `WorkbenchView.vue:576` 只弹一句「未接入」 |
| **练得会** | 半达标 | 判分与三层反馈真实可用；但题库仅 3 题，8 张表里 7 张零写入，记录页只靠 `practice_attempts` 单表 |

| # | 现象 | 代码位置 | 影响 |

### 1.2 一句话定位问题

现在的工作台是「**给已经懂 AES 的人看的仪表盘**」，而目标用户是「**刚学完第一章、分不清状态和明文的学生**」。差距不在功能数量，在**解释层**。

## §2 设计目标：三条主张

改造后，用户在三个时间尺度上各得到一件事：

| 时间尺度 | 主张 | 对应功能 |
|---|---|---|
| 30 秒 | **看得见**：一进首页就知道这东西在干什么 | F02 |
| 3 分钟 | **跟得上**：能自己输入一组数据，逐步走完，每步知道为什么 | F03 / F04 / F05 |
| 30 分钟 | **讲得清**：能对着 S 盒、密钥扩展、AI 问答把原理复述出来 | F07 / F08 / F09 / F10 |

### 2.1 三条不做的判断

- **不做账号体系**：评委不会注册，记录用 `clientId` 本机保存，界面明说「本机记录」。
- **不做移动端优先**：主战场是投影和笔记本，手机只保证「能看不崩」。
- **不做算法扩展**（DES/RSA）：一个 AES 讲透，比四个算法都讲一半强。

## §3 视觉方向：从「文档」到「精密仪器」

### 3.1 为什么现在丑

不是颜色少，是**没有视觉层级**：首页 2 个元素、没有尺度对比、没有色相区分、没有图示。工作台则是**信息密度对但缺引导**：所有区域等权重，用户不知道该看哪。

### 3.2 定调

**工程图纸 + 精密仪器**：纸感底、细结构线、等宽数字、四步四色、动效只用于表达「变化」。

三条具体规则：

1. **一个页面只有一个视觉主角**。首页主角是那 4×4 矩阵；工作台主角是 C 区舞台；S 盒页主角是那张表。
2. **色彩只承担分类，不承担装饰**。四步四色是分类色，状态色（琥珀=变化、红=错误）是语义色，两者不混用。
3. **线宽恒定，只用颜色和字重做层级**。沿用既有「`border-width` 恒定，只改 `border-color`」的纪律。

### 3.3 字体决策（已拍板：标题用宋体）

> 2026-11-10 确认：**大标题走宋体系统栈**，不引 Web Font。

| 用途 | 字体 | 理由 |
|---|---|---|
| 大标题 / 数字标题 | `"Noto Serif SC", "Songti SC", "SimSun", Georgia, serif` | 宋体给「教材/论文」的权威感，和密码学题材匹配 |
| 正文 / 控件 | 现有 `--font-ui`（Archivo → 思源黑体 → 系统） | 屏幕可读性 |
| 数值 / 标签 | 现有 `--font-mono`（IBM Plex Mono → Consolas） | 对齐 |

**不引入任何 Web Font CDN**：Docker 离线跑，外链会白屏。全部走系统字体栈。

### 3.4 四步四色（新增分类色，色相与既有规范一致）

| 步骤 | 色相 | 用途 | 不用于 |
|---|---|---|---|
| 字节代换 SubBytes | 175（青） | 卡片顶条、步骤 chip、S 盒页主色 | 字节格填充 |
| 行移位 ShiftRows | 265（靛） | 同上 | 字节格填充 |
| 列混合 MixColumns | 330（玫） | 同上 | 字节格填充 |
| 轮密钥加 AddRoundKey | 258（石墨） | 同上（与密钥通道同源） | 字节格填充 |

> **红线**：这四色**永远不落到 16 个字节格上**。字节格只有七态（idle / changed / selected / error / key / done / downstream），多一个通道就毁掉「一个通道只表达一件事」的设计。

新增令牌（写入 `styles/tokens.css`）：

```css
/* 四步分类色：仅用于标签、顶条、chip、图示 */
--step-sub-tint:   oklch(0.952 0.024 175);
--step-sub-ink:    oklch(0.400 0.070 175);
--step-shift-tint: oklch(0.950 0.022 265);
--step-shift-ink:  oklch(0.395 0.070 265);
--step-mix-tint:   oklch(0.955 0.020 330);
--step-mix-ink:    oklch(0.420 0.075 330);
--step-ark-tint:   oklch(0.945 0.004 258);
--step-ark-ink:    oklch(0.360 0.012 258);

/* 首页与全站壳层 */
--nav-h: 56px;
--card-r: 3px;
--shadow-card: 0 1px 0 var(--line-hairline), 0 8px 24px oklch(0.255 0.018 258 / 0.05);
--measure-hero: 22ch;
```

对比度自检：`--step-*-ink` 对 `--step-*-tint` 均 ≥ 4.6:1；正文 `--ink-1` 对 `--paper-0` ≥ 13:1。

### 3.5 动效纪律

沿用既有 `--d-1..--d-4`（80/160/280/420ms）。新增一条：

- **首页演示动画每 1400ms 走一步，四步循环；`prefers-reduced-motion` 下停在终态（密文）不动。**
- 工作台所有动效仍然只表达「变化」，不表达「入场」。

## F01 · AppShell 与导航

### 目标
任何页面，一次点击能到任何主页面；用户永远知道自己在哪、能回哪。

### 现状（带证据）

**文案表（写死在 `data/step-copy.ts`，不散落在组件里）**

| op | 一句话 | 为什么（可展开） |
|---|---|---|
| `sub_bytes` | 16 个字节各自查一次 S 盒，一个进一个出。 | ① S 盒是非线性替换，专门用来打乱「输入和输出的关系」；② 它不是随机表，是 GF(2⁸) 求逆再做仿射变换算出来的；③ 所以同样的输入永远得到同样的输出，可以反查。 |
| `shift_rows` | 第 1 行不动，第 2/3/4 行分别左移 1/2/3 格。 | ① 移位把同一列的数据摊到不同列；② 下一轮列混合时，4 个来自不同列的数据才会混在一起；③ 这是「扩散」的来源。 |
| `mix_columns` | 每一列 4 个字节做一次 GF(2⁸) 矩阵乘法。 | ① 一个字节变了，整列 4 个都会变；② 乘的矩阵是固定的（2 3 1 1 / 1 2 3 1 / 1 1 2 3 / 3 1 1 2）；③ 最后一轮不做这步，否则无法解密。 |
| `add_round_key` | 当前状态和这一轮的密钥逐字节异或。 | ① 异或的可逆性让它既加密也解密；② 只有这一步真正引入了「密钥」；③ 第 0 轮先做一次，叫初始轮密钥加。 |
| 第 0 步 | 这是你的明文，16 个字节按列排成 4×4。 | ① 矩阵是列优先：第 1 列是前 4 个字节；② 排列顺序是 AES 规范定的，不是随便摆的；③ 按空格开始走第一步。 |
| 末步 | 这就是密文，把它按列读回来就是结果。 | ① 最后一轮没有列混合；② 所以每个密文字节只由上一状态的 1 个字节决定；③ 这也是为什么解密要从最后一轮倒着走。 |

**术语表（`data/glossary.ts`，12 条，唯一数据源）**

| 级 | 术语 | 为什么必须解释 |
|---|---|---|
| L1 | 状态矩阵 / 轮 / 字节代换 / 行移位 / 列混合 / 轮密钥加 | 不认识就读不懂任何一步 |
| L1 | S 盒 / 密钥扩展 / 轮密钥 | 现在点这两词只弹「未接入」 |
| L2 | 混淆 / 扩散 | 解释「为什么是这四步」 |
| L2 | GF(2⁸) / 异或 | 只解释到够用，不展开数学 |

> **条数口径已统一**：原方案写 10 条、学习路径文档写 14 条、术语专题列 12 条，现**定为 12 条**（取三者并集，剔除 `字节` `列` 两个日常词——它们不需要解释）。`轮常数` `逆 S 盒` `填充` 归 L3，只在用到处给一句话，不进术语表。

**每条 5 个字段**：`name` / `en` / `action`（做什么，一句具体动作）/ `analogy`（类比）/ `pitfall`（常见误解）。**`pitfall` 是核心字段**——中文译名会制造虚假熟悉感，必须逐条拆穿：

| 术语 | 字面误导 | pitfall 要写的话 |
|---|---|---|
| 字节代换 | 以为「换个值」 | 不是随便换，是**查一张 256 项固定表**，人人算出同一个结果 |
| 行移位 | 以为「随便挪」 | 第 r 行**循环左移 r 个字节**，位移量由行号决定，不是随意错位 |
| 列混合 | 以为「打乱顺序」 | **顺序完全不变，值全变了**——每列乘一个固定矩阵 |
| 轮密钥加 | 以为「算术加法」 | 是**按位异或**，叫「加」是历史遗留，没有进位 |

**呈现方式（已改，不再以 hover 为主）**：

- **首次出现就地展开**三行卡（做什么 / 类比 / 常见误解），插在 `StepNarrative` 内，不弹窗不跳页。
- 之后收回为虚线下划线，`hover` / `focus` 才弹 popover（宽 300px，`--shadow-float`，`--paper-0` 底）。
- 理由：**初学者不会 hover 一个不认识的词**，他不知道该查，直接滑过去，然后卡在后面某一步。hover 只服务回看，不承担首次教学。


- 「结论」块：`--fs-body`，`--ink-1`，左侧 3px `--accent` 竖条。
- 「为什么」：`--` 列表，每条 1 行，`--ink-2`，行高 1.6。
- 「下一步」：文字 + 一个文字按钮（下划线 + `--accent-strong`）。
- 「依据」：chip 用 `--surface-inset` 底 + `--font-mono`，点击 → 打开对应字节抽屉（复用 F04 的抽屉）。
- 流式：逐字追加，末尾 2px 竖线光标，`prefers-reduced-motion` 下不闪。
- 停止按钮：生成中显示，点击 `AbortController.abort()`。
- 来源徽标：`llm` → 「AI · 模型名」；`local` → 「本地讲解」；hover 说明「未配置模型时使用内置讲解」。

**快捷问（按当前 op 变化）**

| op | 三个快捷问 |
|---|---|
| `sub_bytes` | 「为什么这一格变成 0x63？」「S 盒为什么能反查？」「如果改成 0x00 会怎样？」 |
| `shift_rows` | 「为什么要按行移位？」「移完之后哪 4 个字节会混在一起？」「最后一轮为什么不移？」 |

**空态**：一句「问一句关于当前这一步的问题，比如：这 4 格为什么一起变？」+ 三个快捷问。

**错误态**：错误卡（代码 + 人话 + 「重试」+ 「看本地讲解」）。

**提示词（system）**


**用户消息只带当前步（±1 步），不带全量 trace**：


**流式**：`httpx.AsyncClient.stream("POST", ...)`，逐行解析 `data: {...}`，转成 F09 的 `block`/`token` 事件。首 token 前先发 `meta`。

**降级链**（必须实现，答辩现场网络不可控）：

```
无 key / enabled=false  →  本地模板（source=local）
超时(20s) / 429 / 5xx   →  重试 1 次（超时 ×1.5）→ 仍失败则本地模板 + error 事件（retryable=true）
内容为空                 →  本地模板 + 记录 warning
```

**留痕**：每次调用写 `tutor_logs`（`trace_id / step_index / question / source / model / latency_ms / tokens / created_at`）。

**健康检查**：`GET /api/health` →

```json
{ "status": "ok", "llm": { "enabled": true, "model": "deepseek-chat" }, "version": "0.1.0" }
```

前端 E 区据此显示状态点（AI / 本地）。

**安全**
- key 只从环境变量读，不进代码、不进日志、不落库。
- 日志里 `question` 截断到 80 字。
- 不加用户可控的 `base_url`（防 SSRF）。

**依赖**：`requirements.txt` 加 `httpx==0.28.x`（uvicorn/fastapi 生态已有兼容版本，需锁定）。

### 验收
1. 配置 key 后提问，`meta.source === 'llm'`，首 token < 1.5s（本地网络）。
2. 回答里出现的十六进制值，**逐个**能在当前 trace 的 `before/after` 中找到（抽查 10 次，0 次编造）。
3. 把 key 置空重启，功能仍完整，来源显示「本地讲解」。
4. 把 `LLM_BASE_URL` 指向不存在的域名，20s 后降级为本地模板并提示可重试。
5. `tutor_logs` 表有记录，`latency_ms` 合理。
6. `GET /api/health` 返回 `llm.enabled` 正确。
7. 日志中 grep 不到 key 字符串。

### 不做什么
- 不做模型选择下拉（固定一个，减少变量）。
- 不做 RAG / 向量库（当前上下文就是一步数据，用不上）。
- 不做多模型投票。

## F11 · 解密链路

### 目标
AES 从「只能加密」变成「加密 + 解密」，且解密每一步同样可见。

### 现状（带证据）
`services/aes_impl.py:176-182`：

```python
def build_trace(plaintext_hex, key_hex, key_bits, direction="encrypt"):
    if direction != "encrypt":
        raise AesInputError("unsupported_direction", "B1 only supports encrypt trace", None)
```

前端 `engine/aes.ts` **已经有** `invShiftRows`、`invMixColumns`（第 62、90 行），`sbox.ts` 有逆盒；`trace.ts:42` 的类型写死 `direction: 'encrypt'`。也就是说：**逆变换函数写好了，但没串成链路。**

### 后端改动

`services/aes_impl.py`
1. 新增 `_inv_sub_bytes`（用已有 `INV_SBOX`）、`_inv_shift_rows`、`_inv_mix_columns`（矩阵 14 11 13 9 / 9 14 11 13 / 13 9 14 11 / 11 13 9 14）。
2. `build_trace` 去掉 `direction != encrypt` 的拦截，按方向分支：
   - **加密**：现有逻辑不变。
   - **解密**：`AddRoundKey(Nr)` → for r in Nr-1..1: `InvShiftRows → InvSubBytes → AddRoundKey(r) → InvMixColumns` → 末轮 `InvShiftRows → InvSubBytes → AddRoundKey(0)`。
3. 步骤 label：`第 3 轮 逆列混合`，第 0 步解密为 `初始轮密钥加（第 10 轮密钥）`。
4. 返回体新增 `output`（加密=密文，解密=明文），**同时保留 `ciphertext` 字段**（解密时为明文），避免破坏现有前端与测试。
5. `rounds` 不变；`steps.length` 与加密相同（128 位 = 41 步）。

`models/schemas.py`：`TraceRequest.direction` 保持 `Literal["encrypt","decrypt"]`（若已是，确认；否则放宽）。

### 前端改动

`engine/aes.ts`：补齐 `invSubBytes`（用 `INV_SBOX`），已有其余三个。
`engine/trace.ts`：
- `direction: 'encrypt' | 'decrypt'`；
- `buildTrace` 按方向生成步骤；
- 步骤 label 加「逆」前缀；
- `trace_id` 的哈希输入加 direction（后端已加，前端对齐）。

`engine/vectors.ts`：增加三组向量的双向对（C.1/C.2/C.3 的密文，实施时用 NIST 附录值核对，不靠手算）。

`InputPanel.vue`（F03）：加 `[加密 | 解密]` segmented，位于「十六进制/文本」上方。
- 解密时：第一行标签变「密文」，输出提示变「明文」。
- 文本模式在解密时禁用（密文不是文本）。

`StepNarrative.vue`：解密时四步 chip 加「逆」字，色相不变（同一操作的逆操作沿用同色，避免用户重建色相记忆）。

`MatrixStage` / `Timeline`：无需改动，数据驱动。

`WorkbenchView.vue`：`checkTrace()` 的 body 带 `direction`，一致性校验比对 `data.ciphertext`（后端两向都返回该字段）。

### 验收
1. 加密 `00112233…eeff` + 全零密钥 → `69c4e0d8…c55a`。
2. 切解密，输入上述密文 + 同密钥 → 输出 `00112233…eeff`，末步矩阵与原始明文逐字节相同。
3. 192 位（FIPS C.2）、256 位（C.3）双向 round-trip 均通过。
4. 解密第 1 步 label 为「初始轮密钥加（第 10 轮密钥）」，key_indices 指向最后一组轮密钥。
5. 前后端一致性校验在解密模式下仍为 `ok`。
6. 单测：`engine/aes.spec.ts` 增加 3 组 `decrypt(encrypt(x)) === x`。
7. 时间轴轮次从 10 递减到 0（或标注「逆序」），用户能看出方向。

### 不做什么
- 不做 CBC/GCM 等模式（教学聚焦单块 ECB 语义，但**界面不写 ECB**，避免误导；只写「单个 16 字节分组」）。
- 不做 padding。
- 不做「解密失败」的错误 oracle 演示（教学不需要，且有安全含义）。

### 7.3 三态规范

每个数据区域必须有三态，且文案不能是「加载中…」这种空话：

| 态 | 规格 | 示例文案 |
|---|---|---|
| 加载 | 120ms 后才显示（避免闪烁），骨架条 2 条 | 「正在读取记录」 |
| 空 | 一句解释 + 一个动作 | 「还没有记录，去做一道题 →」 |
| 错 | 错误码 + 人话 + 一个动作 | 「后端没连上（E_NET）。检查 docker compose ps 后重试」 |

### 7.4 文案口径

- **中文优先**，首次出现的术语括号带英文：`列混合（MixColumns）`。
- **不上屏内部词**：A/B/C/D/E 区、trace、token、state_before、payload、SSE。帮助面板可保留技术词（用户主动打开，属于进阶）。
- **数字带单位**：`16 字节`、`第 2 轮`、`41 步`，不写 `16B`。
- **十六进制统一**：正文 `0x3F`（大写、两位），矩阵格内 `3F`（省略前缀）。
- **不用感叹号**，不用「轻松」「一键」「秒懂」。

### 7.5 无障碍底线

- 焦点环：2px `--accent` + 2px offset，任何可交互元素都有。
- 触控目标 ≥ 44×44（工作台工具按钮例外，但需 ≥ 24×24 且有足够间距）。
- 颜色不是唯一信息载体：变化格除琥珀色外，还有 3px 左侧竖条（已实现 `bar` 通道）。
- 所有图标按钮有 `aria-label`。
- `aria-live="polite"` 只用于步骤播报，不要每个状态都播。

| 工作台 | < 180KB | < 2s | 引擎 + 组件 |
| S 盒 | < 40KB | < 1s | 纯表格 |
| 练习/记录 | < 60KB | < 1.5s | |

## §11 红线（违反即返工）

1. **`--cell-gap` 保持 6px**（演示态 10px）。不新造间距值。
2. **七态字节通道不变**：idle / changed / selected / error / key / done / downstream。四步四色**不得**落到字节格上。
3. **变化不位移**：任何状态切换只改颜色、边框色、`inset`，不改尺寸与位置。
4. **判分只在后端**：前端不得复算密文或对错。
5. **投影对比度**：字节格边框必须用 `--rule-region-ink`（常规 0.845 / 演示 0.545），**不得**用 `--line-default`（演示态 0.760，对纸底仅 2.9:1）。
6. **不引入**：UI 框架（Element/Ant）、图标库、动画库、Web Font CDN、Markdown 全量渲染器。
7. **不改数值口径**：所有 trace 以 FIPS-197 附录为准，`compare_trace.py` 是唯一裁判。
8. **不上屏内部词**：见 §7.4。
