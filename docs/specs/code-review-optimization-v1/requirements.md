## 1. 背景与目标

### 1.1 项目现状

CipherLens 已完成 24 个功能点（F0–F24）与 3 个后端功能点（B1–B3），并留有逐项验收证据。项目硬约束已稳定：

- 前端：Vue 3.5 / Vite 5 / TypeScript / Pinia / Vue Router，HTTP 使用原生 fetch；
- 后端：FastAPI / SQLite，手写 sqlite3，不使用 ORM；
- 不引入 UI 组件库、动画库、axios 或图表库；
- 判分只在后端，前端零复算；本地 engine 只用于离线演示，不得进入判分；
- 五条视觉硬约束（边框宽度、边框取色、`--cell-gap`、格子不位移不缩放、判分在后端）继续有效；
- 当前为匿名本机数据，无登录体系；
- 后端未引入 pytest，B 系列使用手写 Python 探针。

### 1.2 审查文档指出的核心问题

审查文档认为项目骨架正确，但存在三处「承诺与实现不一致」：

1. AI 辅导没有接大模型，是本地模板拼接 + `sleep` 模拟流式；
2. 「受污染字节」的教学口径在密码学上不成立；
3. 前端渲染与 AI 回答使用两套独立 AES，只靠 `trace_id` 对齐，没有一致性校验。

此外还有错因分类失真、埋点不落库、零鉴权、数据库隐患、题库只有 1 题、SSE 客户端不规范、第 0 步语义错位等 P1/P2 问题。

### 1.3 本轮目标

把上述建议转成清晰的范围与验收口径，并完成一批**无外部依赖、可独立验收、可单独回滚**的修正。具体目标：

1. 教学口径先澄清、再决定是否改代码，避免直接推翻 B3/F19 已验证口径；
2. 让「错因分类」不再伪造结论：无法归因时显示「未归类」，而不是默认「轮密钥时机」；
3. 让练习模式具备基本可用性：题库从 1 道扩展到可形成趋势与分布的规模；
4. 消除 SSE 客户端的三处规范问题与跨组件中断风险；
5. 修正「尚未开始」与「第 0 步」的语义错位；
6. 用现有探针与 `compare_trace.py` 建立前后端引擎对账，不引入 pytest；
7. 数据库启用 WAL、必要索引与幂等迁移，为后续埋点/隔离打底；
8. 匿名隔离学习记录，保证多人演示不串数据；
9. 清理交付物中显眼的「待用户批准」占位与缺失的页面元信息；
10. 把接真实大模型、双引擎真相源选型、真登录等**高代价/需外部资源**的事项留给用户决策。

## 4. 本轮需求（EARS）

> 以下需求只描述外部可观察行为与验收口径。模块名用于定位影响面，不构成实现方案。
> EARS 关键字：WHEN / IF / THEN / WHILE / WHERE / SHALL / SHALL NOT。

### 4.1 教学口径与证据（P0-2）

#### REQ-01 · 口径澄清与证据追记（P0-2 最小子项，本轮必做）

**需求（EARS）**

- WHEN 新增或更新任何描述判分差异的材料，THE SYSTEM SHALL 使用「差异字节」或「来源字节」两个术语，并 SHALL NOT 把「首个差异之后的所有下标」称为「受污染字节」。
- WHEN 修改 B3/F19/F20 相关证据材料，THE SYSTEM SHALL 以追加「口径变更说明」的方式记录旧口径、新口径、生效日期与影响字段，并 SHALL NOT 删除或改写原证据段落。
- IF 旧字段 `propagated` 仍被保留，THEN THE SYSTEM SHALL 在接口与文档中将其标记为「兼容字段」，并 SHALL NOT 用其驱动「受污染」文案。

**验收标准**

| 编号 | 验收项 | 可测量口径 |
|---|---|---|
| A1 | 学生可见术语 | 面向学生的页面文案与新增对外说明中检索「受污染」命中数为 0；历史证据、判定表与冲突说明中的引用不计入 |
| A2 | 证据只增不改 | `evidence/acceptance/B3.md`、`F19.md`、`F20.md` 原有段落仍在；新增说明有日期与影响字段 |
| A3 | 兼容字段标记 | 接口文档与需求文档均出现 `propagated` 的「兼容/deprecated」标注 |
| A4 | 不推翻历史 | 旧证据中的实测数字（如 `propagated: [8..15]`、`.is-downstream=8`）保持可查 |

**涉及模块**：`docs/`（新增需求文档）、`evidence/acceptance/B3.md`、`F19.md`、`F20.md`；不涉及业务源码。

**风险**：证据追记若写成「旧结论作废」，会被误读为项目曾造假。缓解：明确「旧口径是当时的可观测实现，新口径是教学修正」。

**依赖**：D-02 的方向确认；若 D-02 选方案 B（保留字段名），REQ-01 的术语仍需执行。

**回归影响**：不影响运行时；影响 F19/F20 的评审叙事与 B3 契约说明。

#### REQ-02 · 差异字节与来源字节分离（P0-2 完整方案，待 D-02 确认后纳入）

**需求（EARS）**

- WHEN 后端完成一次判分且存在差异字节，THE SYSTEM SHALL 在响应中分别给出「差异字节」与「来源字节」两个概念，并 SHALL NOT 把二者合并为「受污染」。
- WHEN 前端渲染判分矩阵，THE SYSTEM SHALL 只用 `error` 样式标出首个差异字节，只用 `downstream` 样式标出来源字节，并 SHALL 在来源字节上提供可读标签，避免学生把来源字节读成「也是错的」。
- WHEN 存在多个差异字节，THE SYSTEM SHALL 用独立文案或标识说明「还有 N 个差异字节」，SHALL NOT 把其余差异字节标成 `error` 或 `downstream`。
- WHERE 存在多个差异字节，THE SYSTEM SHALL 保证「来源字节」是可由差异位置验证的唯一可能来源集合，数量不超过 4 个。
- IF 旧字段仍需保留一个版本，THEN THE SYSTEM SHALL 保留其原值但停止用于文案，并在下一个版本移除。

**验收标准**

| 编号 | 验收项 | 可测量口径 |
|---|---|---|
| B1 | 字段分离 | 响应同时包含「差异字节」与「来源字节」两个字段；任一缺失即失败 |
| B2 | 差异字节正确 | 对 C.1 第 7 字节错，差异字节集合为 `[7]`；对多字节错，集合等于实际不符下标 |
| B3 | 来源字节可验证 | 来源字节数量 1–4，且每个下标与按 AES 末轮逆置换手算结果一致 |
| B4 | error 只 1 格 | `.is-error` 数量仍为 1，等于首个差异字节 |
| B5 | downstream 只挂来源 | `.is-downstream` 数量等于来源字节数量，不等于「首个差异之后的全部下标」 |
| B6 | 其余差异不冒充 | 多字节错时，其余差异字节不被标成 `error` 或 `downstream`，由独立文案/标识说明 |
| B7 | 文案 | 学生可见页面不再出现「受污染」「受影响的下游字节」等表述 |
| B8 | 回归 | B3/F19 新旧断言同时记录；F24 E2E 判分场景通过 |

**涉及模块**：`backend/services/quiz_service.py`、`backend/services/records_service.py`、`frontend/src/stores/quiz.ts`、`frontend/src/components/region-c/MatrixStage.vue`、`frontend/src/components/region-c/QuizMatrix.vue`、`frontend/src/views/PracticeView.vue`。

**风险**：
- 推翻 B3/F19 已验证口径，评审可能质疑「之前验收是否失效」；
- `propagated` 改名会牵动前端类型、F19 断言、F24 E2E；
- 来源字节只覆盖末轮，不能解释更早轮次，文案若过度承诺会制造新的教学错误。

**依赖**：D-02 选择；REQ-01 先完成。

**回归影响**：B3（契约字段）、F19（1 格 error / N 格 downstream）、F20（记录按首错字节）、F24（Playwright 判分断言）。

### 4.2 判分归因与题库（P0-4 / P1-4）

#### REQ-03 · 不可归因时显示「未归类」（P0-4 最小子项，本轮必做）

**需求（EARS）**

- WHEN 一次错误提交无法由现有可观测数据归因到三类误解之一，THE SYSTEM SHALL 记录为「未归类」，并 SHALL NOT 默认写入「轮密钥时机」。
- WHEN 学习记录页展示错因分布，THE SYSTEM SHALL 单独展示「未归类」计数；IF 样本不足，THEN THE SYSTEM SHALL 继续遵守「少于 3 题不出结论」的既有门槛。
- WHERE 旧记录已写入三类标签，THE SYSTEM SHALL 保持可读，并 SHALL NOT 因新口径而重写历史记录。

**验收标准**

| 编号 | 验收项 | 可测量口径 |
|---|---|---|
| C1 | 不再默认 | 真实错误提交后，`misconception` 不为 `key_timing`（除非有可验证依据） |
| C2 | 未归类可见 | 记录页出现「未归类」桶，计数与数据库一致 |
| C3 | 三类桶不虚增 | 未归类错误不增加三类固定桶的任何计数 |
| C4 | 历史兼容 | 旧记录仍按原标签展示，不被清空或重算 |
| C5 | 三态不破 | 0 题 / 2 题 / 10 题三态与 F20 一致；<3 题仍不出百分比 |

**涉及模块**：`backend/services/records_service.py`、`backend/services/quiz_service.py`、`frontend/src/views/RecordsView.vue`、`frontend/src/types/api.ts`。

**风险**：记录页原有「三类分布」会变成「三类 + 未归类」，F20 证据中的 4/1/1 是探针合成数据，真实路径将不再产生该分布；需在证据中说明。

**依赖**：无（可独立于 P0-2 实施）；若 D-04 选题库标签方案，REQ-03 保留为兜底。

**回归影响**：F20（三态、分布、正确率）、F24（记录页 E2E）。

#### REQ-04 · 题库扩充到可形成趋势与分布（P1-4，本轮必做）

**需求（EARS）**

- WHEN 学生进入练习页，THE SYSTEM SHALL 提供不少于 8 道题，并 SHALL 允许学生切换题目。
- WHERE 题库覆盖密钥长度，THE SYSTEM SHALL 至少包含 AES-128、AES-192、AES-256 各 2 道。
- WHERE 题库覆盖专项，THE SYSTEM SHALL 至少包含 2 道列混合专项与 2 道轮密钥专项。
- WHEN 学生提交任意题目，THE SYSTEM SHALL 仍只通过后端判分，并 SHALL NOT 在前端保存或推导正确答案。
- WHEN 学生切换题目，THE SYSTEM SHALL 同步更新题目文案、明文、密钥与密钥长度标识，并 SHALL NOT 沿用上一题的判分叠加。

**验收标准**

| 编号 | 验收项 | 可测量口径 |
|---|---|---|
| D1 | 题量 | 题库条目数 ≥ 8 |
| D2 | 覆盖 | 128/192/256 各 ≥2；列混合专项 ≥2；轮密钥专项 ≥2 |
| D3 | 切换 | 切换后页头、明文、密钥、答案输入全部更新；无上一题 `.is-error` 残留 |
| D4 | 判分 | 任意题提交返回 200；全对/单错/输入非法三分支与 B3 一致 |
| D5 | 趋势 | 连续做 3 道不同题，记录页趋势出现 ≥3 个点 |
| D6 | 零复算 | `PracticeView` / `quiz.ts` 中 `engine` 引用为 0 |
| D7 | 无答案泄露 | 前端题库不含 `expected_ciphertext`；答案只在后端返回 |

**涉及模块**：`frontend/src/data/quizBank.ts`、`frontend/src/views/PracticeView.vue`、`frontend/src/stores/quiz.ts`、`frontend/src/types/api.ts`、`backend/services/quiz_service.py`。

**风险**：
- 当前 `PracticeView` 写死 `QUIZ_ITEMS[0]` 与「AES-128 · 16 字节」页头，补题必须改 UI；
- 192/256 位的 `key_bits` 与 key 长度、页头、判分请求需同步；
- 新增题目若使用非标准向量，需先用 `compare_trace.py` 对账。

**依赖**：D-04（标签口径）；REQ-06（对账）用于新增题验证。

**回归影响**：F19（练习页、判分叠加、跳转）、F20（趋势/错题）、F24（Playwright 判分场景）。

#### REQ-05 · 题库标签与归因边界（P0-4 增强，待 D-04 确认）

**需求（EARS）**

- WHERE 题目带有 `misconception_tag`，THE SYSTEM SHALL 在记录中保存该标签，并 SHALL 在记录页标注「题目设计意图」，SHALL NOT 把它表述为「算法诊断结论」。
- WHEN 一次错误无法由学生作答数据验证归因，THE SYSTEM SHALL 仍以「未归类」为准，并 SHALL NOT 用题目标签替代证据。
- IF 学生提交中间态（未来能力），THEN THE SYSTEM SHALL 依据中间态定位首错轮次，并 SHALL NOT 继续使用最终密文反推。

**涉及模块**：`frontend/src/data/quizBank.ts`、`backend/services/records_service.py`、`backend/services/quiz_service.py`、`frontend/src/views/RecordsView.vue`。

**风险**：题目标签是「设计意图」，不是「学生错因」；若文案混淆，会制造比当前更严重的误导。

### 4.3 前后端一致性与离线口径（P0-3）

#### REQ-06 · 三组向量引擎对账（P0-3 最小子项，本轮必做）

**需求（EARS）**

- WHEN 运行引擎对账任务，THE SYSTEM SHALL 对 3 组 FIPS-197 向量逐字段比较前后端 trace，并 SHALL 在任一差异时以非零退出码失败。
- WHEN 对账失败，THE SYSTEM SHALL 输出差异字段、下标与双方值，便于定位；SHALL NOT 只输出「失败」。
- WHERE 旧对账脚本只覆盖 1 组向量，THE SYSTEM SHALL 扩展到 3 组，并 SHALL 保留原有字段比较范围。

**验收标准**

| 编号 | 验收项 | 可测量口径 |
|---|---|---|
| F1 | 三组覆盖 | C.1 / C.2 / C.3 均运行；向量数 = 3 |
| F2 | 零差异 | 正常代码输出 `differences=0`，退出码 0 |
| F3 | 可失败 | 人为修改后端某一 step 的 `label`，脚本退出码非 0，并打印该字段差异 |
| F4 | 字段范围 | 至少覆盖 `trace_id`、`ciphertext`、`step_count`、`key_schedule`、每步 `index/round/op/state_before/state_after/changed/key_indices/key_words/label` |
| F5 | 不引 pytest | 运行方式为现有 Python 脚本 + Node dump；`requirements.txt` 不新增测试依赖 |

**涉及模块**：`backend/tools/compare_trace.py`、`backend/tools/dump_frontend_trace.mjs`、`frontend/src/engine/`。

**风险**：C.2/C.3 的 `step_count` 与轮数不同，若脚本写死 40 会误报；需按响应读取。

**依赖**：无；可在阶段 1 独立完成。

**回归影响**：B1（契约）、F3（trace 生成）；不改变运行时行为。

#### REQ-07 · 工作台运行时一致性校验（P0-3 最小子项，本轮必做）

**需求（EARS）**

- WHEN 工作台获得 `/api/aes/trace` 响应，THE SYSTEM SHALL 校验后端 `trace_id` 与 `ciphertext` 是否与本地 trace 一致。
- IF 校验不一致，THEN THE SYSTEM SHALL 展示「前后端数值不一致」的可读提示，并 SHALL 禁用提问入口。
- IF 校验一致，THEN THE SYSTEM SHALL 保持现有矩阵渲染与提问能力不变。
- WHEN 校验完成，THE SYSTEM SHALL NOT 因校验而重新生成 trace 或改变播放状态。

**验收标准**

| 编号 | 验收项 | 可测量口径 |
|---|---|---|
| G1 | 一致路径 | 正常后端：无提示，提问可用，矩阵仍为 40 步 |
| G2 | 不一致路径 | 构造 `trace_id` 或 `ciphertext` 不一致响应：出现提示，提问按钮/输入禁用 |
| G3 | 不发请求 | 不一致状态下点击发送，Network 面板无 `/api/tutor/ask` |
| G4 | 状态不扰动 | 校验不改变 `currentStep`、播放状态、URL 参数 |
| G5 | 零判分影响 | 判分请求不经过该校验，不把本地 engine 接入判分 |

**涉及模块**：`frontend/src/views/WorkbenchView.vue`、`frontend/src/components/region-e/TutorPanel.vue`、`frontend/src/stores/ui.ts`。

**风险**：校验失败可能把「后端暂时不可用」误判为「数值不一致」；需区分网络失败与内容不一致。

**依赖**：REQ-06（对账保证正常情况下两者一致）。

**回归影响**：F16（提问主链路）、F17（降级）、F23（离线标识）、F24（E2E）。

#### REQ-08 · 离线模式禁用提问（P0-3 最小子项，本轮必做）

**需求（EARS）**

- WHEN 后端不可用或一致性校验失败，THE SYSTEM SHALL 显示离线/不一致标识，并 SHALL 禁用提问入口。
- WHILE 处于离线模式，THE SYSTEM SHALL 仍允许本地 engine 渲染内置标准向量的矩阵与播放。
- WHEN 后端恢复且校验通过，THE SYSTEM SHALL 解除禁用并恢复提问。
- THE SYSTEM SHALL NOT 在离线模式下用本地 engine 计算判分结果。

**验收标准**

| 编号 | 验收项 | 可测量口径 |
|---|---|---|
| H1 | 标识 | 离线时页面出现「离线演示」或「数值不一致」可读文本 |
| H2 | 提问禁用 | 输入/发送禁用；无 ask 请求 |
| H3 | 矩阵可用 | 40 步可播放，首格与内置向量一致 |
| H4 | 恢复 | 后端恢复后重新校验并解禁 |
| H5 | 判分隔离 | `PracticeView` / `quiz.ts` 无 `engine` 引用 |

**涉及模块**：`frontend/src/views/WorkbenchView.vue`、`frontend/src/components/layout/WorkbenchLayout.vue`、`frontend/src/components/region-e/TutorPanel.vue`。

**风险**：F23 现有离线证据只验证「标识 + 矩阵可用」，未验证提问禁用；需补证据。

**依赖**：REQ-07。

**回归影响**：F23（离线降级）、F16/F17、F24。

### 4.4 SSE 与辅导交互（P1-5 / P1-6）

#### REQ-09 · SSE 帧解析符合规范（P1-5，本轮必做）

**需求（EARS）**

- WHEN SSE 帧中的 `data:` 后没有空格，THE SYSTEM SHALL 仍能解析该字段。
- WHEN 一个事件包含多行 `data:`，THE SYSTEM SHALL 以换行连接各行的值，并 SHALL NOT 直接把字符串首尾相接。
- WHEN 流结束且缓冲区仍有未以空行结尾的帧，THE SYSTEM SHALL 在结束时派发该残留帧，并 SHALL NOT 静默丢弃。
- WHERE 现有后端帧格式不变，THE SYSTEM SHALL 保持向后兼容。

**验收标准**

| 编号 | 验收项 | 可测量口径 |
|---|---|---|
| I1 | 无空格 | 构造 `data:{"t":"x"}`，`onToken` 收到 `x` |
| I2 | 多行 | 构造两行 `data:`，回调收到以 `\n` 连接的值 |
| I3 | 残留 | 流末尾无 `\n\n`，仍派发最后一帧 |
| I4 | 兼容 | 现有 `event: meta / token / done / error` 帧全部通过 |
| I5 | 单测 | 新增 vitest 用例覆盖 I1–I3；`npm test` 全绿 |

**涉及模块**：`frontend/src/utils/sse.ts`、`frontend/src/composables/useSSE.ts`。

**风险**：解析改动影响 F16/F17 的流式链路；需保留现有事件分派行为。

**依赖**：无。

**回归影响**：F16（主链路）、F17（11 态）、F24（SSE E2E）。

#### REQ-10 · SSE 作用域隔离（P1-5，本轮必做）

**需求（EARS）**

- WHEN 多个组件同时使用 SSE，THE SYSTEM SHALL 为每个调用方维护独立的取消控制器集合。
- WHEN 其中一个组件卸载，THE SYSTEM SHALL 只中止该组件发起的流，并 SHALL NOT 中止其他组件的流。
- WHEN 同一组件重复发起请求，THE SYSTEM SHALL 中止该组件上一次流，并 SHALL NOT 影响其他组件。
- WHEN 所有流结束，THE SYSTEM SHALL 保持全局活动计数准确。

**验收标准**

| 编号 | 验收项 | 可测量口径 |
|---|---|---|
| J1 | 独立集合 | 两个测试组件各自 start，卸载 A 后 B 的流仍收到 token |
| J2 | 重复请求 | 同一组件连续 start 两次，第一次被 abort，第二次正常 |
| J3 | 计数 | `window.__sse.active` 在卸载后回到正确值 |
| J4 | 现有行为 | TutorPanel 单组件场景与 F16/F17 一致 |

**涉及模块**：`frontend/src/composables/useSSE.ts`、`frontend/src/components/region-e/TutorPanel.vue`。

**风险**：改动可能影响 `onScopeDispose(abort)` 的现有语义；需明确「卸载只清自己的」。

**依赖**：REQ-09 可并行。

**回归影响**：F16/F17；未来练习页 SSE 复用。

#### REQ-11 · SSE 无 token 超时（P1-5，本轮必做）

**需求（EARS）**

- WHEN 一个 SSE 流连续 30 秒未收到任何 token，THE SYSTEM SHALL 以 `timeout` 错误结束该流，并中止请求。
- WHERE TutorPanel 已有 20 秒总降级，THE SYSTEM SHALL 让 20 秒降级优先触发，并 SHALL NOT 在降级后重复报超时。
- WHEN 用户主动中止，THE SYSTEM SHALL NOT 触发 `timeout` 错误。

**验收标准**

| 编号 | 验收项 | 可测量口径 |
|---|---|---|
| K1 | 超时触发 | 模拟 30 秒无 token，`onError('timeout')` 恰好一次 |
| K2 | 主动中止 | 点击停止/卸载，不出现 timeout 提示 |
| K3 | 降级优先 | TutorPanel 20 秒降级后，不再出现第二个错误态 |
| K4 | 正常流 | 正常 token 流不触发超时 |

**涉及模块**：`frontend/src/utils/sse.ts`、`frontend/src/composables/useSSE.ts`、`frontend/src/components/region-e/TutorPanel.vue`。

**风险**：与后端 20 秒超时、前端 20 秒降级形成三重计时；需在需求中固定优先级。

**依赖**：REQ-09、REQ-10。

**回归影响**：F17（超时降级）、F16。

#### REQ-12 · 第 0 步禁用提问（P1-6，本轮必做）

**需求（EARS）**

- WHEN 工作台当前步为 0（尚未开始），THE SYSTEM SHALL 禁用提问输入与发送，并显示「先走一步，我才能讲你看到的东西」类提示。
- WHILE 当前步为 0，THE SYSTEM SHALL NOT 发起 `/api/tutor/ask` 请求。
- WHEN 当前步 ≥ 1，THE SYSTEM SHALL 恢复提问能力，并保持原有 `step_index` 映射。

**验收标准**

| 编号 | 验收项 | 可测量口径 |
|---|---|---|
| L1 | 禁用态 | 步 0 时输入框 `disabled`，发送按钮不可用 |
| L2 | 无请求 | 步 0 点击发送，Network 无 ask 请求 |
| L3 | 提示 | 页面出现可读提示文本 |
| L4 | 恢复 | 步 1 起可正常提问，回答引用第 1 步数值 |
| L5 | 回归 | F16/F17 原有截图与断言可复现 |

**涉及模块**：`frontend/src/components/region-e/TutorPanel.vue`、`frontend/src/views/WorkbenchView.vue`。

**风险**：`Math.max(0, stepIndex - 1)` 同时用于上下文映射，禁用逻辑不能误伤步 1。

**依赖**：无。

**回归影响**：F16/F17。

### 4.5 数据持久化与匿名隔离（P1-1 / P1-2 / P1-3）

#### REQ-13 · 匿名客户端记录隔离（P1-2，本轮必做）

**需求（EARS）**

- WHEN 前端首次访问学习记录相关功能，THE SYSTEM SHALL 生成并持久化一个本机匿名客户端标识，并 SHALL 在后续记录请求中携带。

#### REQ-14 · 数据库加固与幂等迁移（P1-3，本轮必做）

### D-01 · P0-1 是否接真实大模型

| A. 本轮接真实模型 | 新增 OpenAI 兼容适配器，读 `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL`；模板保留为 fallback；`meta.source` 改为 `llm` / `fallback` | 1 天 + Key + 网络 + 成本 | F16/F17 的 11 态变成真功能；B2 证据需重录；需 D-01 通过 |

| B. 兼容优先 | `propagated` 字段名不动，只改 UI 文案为「差异字节」；新增「来源字节」作为可选教学层，不驱动 downstream 样式 | 2 小时 | 字段名仍误导；但回归面最小 |
| C. 不改代码，只改文档 | 保留现状，在文档/证据中标注「当前为可观测近似口径，不是密码学传播」 | 1 小时 | 教学错误仍在界面上；不推荐 |

**建议**：**A**，但分两步：第一步只做 REQ-01（文档/证据追记），第二步在用户确认后再改代码。理由：这是「现在教的是错知识」的问题，且改动主要在显示层，不改变统计分母；保留兼容字段可降低回归风险。

**必须先改文档/证据吗**：是。建议顺序为「追记证据 → 冻结新术语 → 改后端字段 → 改前端渲染 → 回归 F19/F24」，避免出现「代码已改、证据还是旧口径」的评审空窗。

### D-03 · P0-3 双引擎真相源

**背景**：工作台矩阵来自前端 `buildTrace()`；后端 `/api/aes/trace` 只用于取 `trace_id`；AI 用后端内存 trace；`trace_store` 为进程内 `OrderedDict`，上限 64，重启/多 worker 失效。

**方案**

| 方案 | 做法 | 代价 | 影响 |
|---|---|---|---|
| A. 后端唯一真相源 | 工作台直接使用 `/api/aes/trace` 返回的完整 trace；本地 engine 只作离线兜底并明确标注 | 1 天 | F13/F21/F23 需回归；`trace_store` 仍需解决多 worker/重启 |
| B. 前端唯一真相源 | 提问时把当前步上下文 POST 给后端；后端不查 store | 半天 | 违反 B2「不重复传 16 字节」契约；请求体变大；F16/F17 需改 |
| C. 保留双引擎 + 对账 | 扩展 `compare_trace.py` 到 3 组向量；运行时校验 `trace_id`/`ciphertext`；离线禁用提问 | 2 小时 | 不消除架构上的双份数据，但能在分叉时立刻发现 |

**建议**：本轮选 **C**，A/B 留到下一阶段。理由：C 可独立验收、不推翻 B1/B2 契约、不动 F13/F21 的播放与性能；A 虽然更彻底，但需要重做工作台数据源与离线分支，回归面大。

**补充**：无论选哪个，`trace_store` 的「进程内、上限 64、重启失效」都应在文档中明确为已知边界；若未来上多 worker，需改为持久化或让前端携带上下文。

### D-04 · P0-4 / P1-4 错因标签来源

**背景**：`first_diff.step` 恒为末步 `add_round_key`，`misconception` 恒为 `key_timing`；`source_bytes` 只能定位末轮来源，不能判断更早轮次；题库当前在前端，后端 `quiz_items` 表为空。

**方案**

| 方案 | 做法 | 代价 | 影响 |
|---|---|---|---|
| A. 只做 unattributed | 不改题库结构；无法归因即「未归类」 | 1 小时 | 记录页不再造假，但三类分布仍缺样本 |
| B. 题库标签放后端 | 后端维护 `item_id → misconception_tag` 映射（常量或 `quiz_items` 种子）；判分记录标签 | 半天 | 题目仍在前端、标签在后端，存在双处维护风险 |
| C. 题库迁到后端 | `GET /api/quiz/items` 返回题目（不含答案）；`quiz_items` 表启用；判分按 `item_id` 取标签 | 1 天 | 架构更干净，但改动 F19/F20/F24；需 D-04 通过 |
| D. 提交中间态 | 练习允许提交某轮 16 字节；后端据此定位首错轮次 | 2 天+ | 才可能产生真实三类诊断；超出本轮 |

**建议**：本轮先做 **A**，并选 **B** 作为题库标签的最小增强；**C/D** 留到后续。理由：A 立刻消除假分类；B 能让记录页有可解释的标签；C/D 改动大，且 D 需要新的交互设计。

### D-05 · P1-1 埋点落库的会话模型

**背景**：前端当前**没有任何 `/api/events` 调用**（全库检索为 0）；后端只打日志返回 204；`step_events.session_id` 是整数外键，前端 `session_id` 是字符串；`sessions` 表从未写入。

**方案**

| 方案 | 做法 | 代价 | 影响 |
|---|---|---|---|
| A. 建匿名会话 | `POST /api/sessions` 建会话，返回整数 id；events 落 `step_events`；诊断落 `diagnoses` | 1 天 | 符合现有 schema；需前端会话生命周期；F24 需回归 |

**建议**：**A**（若本轮容量允许），否则 **B**。理由：A 与审查文档建议一致，且能为诊断/记录提供统一会话；B 更快但会让 schema 出现两套会话标识。无论选哪个，都必须先做 REQ-14 迁移。

## 7. 禁止项
