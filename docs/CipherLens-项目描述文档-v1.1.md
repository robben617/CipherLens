## 4. 背景与问题定义

### 4.1 现状（怎么教的）

AES 的教学路径通常是：教材讲轮函数结构 → 静态图示意四步 → 学生背 S 盒 → 手算一两轮 → 考试。可视化工具多为"播放器"：能播动画，但播完就结束。

### 4.2 三个具体问题

1. **四步是"黑盒变换"**：字节替代、行移位、列混合、轮密钥加各自都能背，但学生说不清某一步到底改了什么、为什么这样改。
2. **现有工具只"演"不"教"**：播放器回答不了"我这一步为什么错"。
3. **卡壳无人知晓**：老师看不到全班在哪一步集体卡住，只能凭感觉重复讲。

### 4.3 本项目的改变

把"能播动画"升级为三件事：**看得见 → 讲得清 → 知道你哪不懂**。

## 6. 产品定位：三层结构

| 层 | 做什么 | 对应任务书/方向一 |
|---|---|---|
| **看得见**（可视化层） | AES 四步 + 正逆 S 盒 + 状态矩阵 + 密钥扩展，逐步播放/单步/参数调节 | 模块 4 全部条目 |
| **讲得清**（辅导层） | 选中任一步提问，AI 携带**该步真实数值**回答，只讲这一步 | 方向一"解释当前步骤的对话面板" |
| **知道你哪不懂**（诊断层） | 记录停顿、回退、重复点击，识别误解类型，主动反问 | 方向一把"当前操作"深化为"操作轨迹" |

> 定位一句话：市面上不缺"能播动画的 AES 工具"，缺的是"看得出你卡住的助教"。

## 7. 功能范围

### 7.1 功能清单与优先级

| 编号 | 功能 | 关键设计 | 优先级 |
|---|---|---|---|
| F1 | AES 可视化引擎 | 按 FIPS-197 自实现，不调 pycryptodome；状态矩阵**列优先**；四步独立渲染 | P0 |
| F2 | 步进控制 | 逐步播放 / 单步前后 / 跳过某轮 / 时间轴拖拽 / 轮数切换 | P0 |
| F3 | 步骤级 AI 辅导 | 选中任一步 → 携带矩阵快照 + 轮次 + 操作类型 → 只讲这一步 | P0 |
| F4 | 认知诊断 | 停顿 >8s、连续回退、同位置反复点击 → 判定误解 → 苏格拉底式反问 | P1 |
| F5 | 练习模式 | 加解密填空、参数调试、自动判分并定位错在第几轮第几步 | P0 |
| F6 | 用户与学习记录 | 注册登录、算法历史、错题本、学习轨迹 | P0 |
| F7 | 教师端学情热力图 | 全班卡壳分布 | P2 可砍 |
| F8 | ECB/CBC 对比实验 | 企鹅图效应 + IV 作用 | P1（见 7.3） |

### 7.2 深度清单（对抗"看着内容少"的 6 条，全部在边界内）

| # | 深度项 | 为什么值钱 |
|---|---|---|
| 1 | 三种密钥长度可切换（128/192/256，Nr=10/12/14） | 能讲清 Nk/Nr 关系，参数真实变化 |
| 2 | **加解密双流程**（逆 S 盒、逆行移位、逆列混合、密钥逆序） | 任务书原文写了"逆 S 盒"，本属必做 |
| 3 | 密钥扩展全过程（44/52/60 字逐个展开 RotWord→SubWord→Rcon→异或） | 最容易被做成黑盒的一步，做出来就是差异 |
| 4 | S 盒数学来源（GF(2⁸) 求逆 + 仿射变换，可现场生成任意一项） | 从"查表"升级到"为什么是这张表" |
| 5 | 字节级明细（点任一格看它从哪来、经过什么、变成什么） | 把"看得见"做到极致 |
| 6 | 雪崩效应（改 1 bit 密钥看多少 bit 密文变化） | 视频封面级演示，只用 AES 本身 |

> 规模测算：AES-128/192/256 加密 40/48/56 步，解密同量；每步 3 个视图 × 16 字节可展开 ≈ **1900 个字节级状态变化点**。三周刚好塞满。

### 7.3 唯一允许的横向扩展

**加"工作模式"，不加"第二个算法"。** ECB vs CBC 属于 AES 的使用方式，不构成第二个算法，符合方向一"不要贪多"。

- 收益：内容量翻倍、企鹅图经典演示、可讲清 IV 作用。
- 边界：只做 ECB、CBC 两个，不做 CTR/GCM；不做 RSA / SM4 / DES。

### 7.4 红线（明确不做）

| 不做 | 原因 |
|---|---|
| RSA / SM4 / DES / 插件化多算法 | 方向一原文"不要贪多"，做了反而减分 |
| 剧情化闯关、金陵文化关卡 | 那属方向四（面向非技术用户），与任务书人群不符 |
| 3D / Three.js 场景 | 3 周内最大风险项，投入产出比低 |
| 语音 / 移动端 / 协同白板 | 加分有限，工程量翻倍 |

## 8. 技术架构

```
┌────────────────────────── 浏览器 ──────────────────────────┐
│ Vue3 + Vite + Pinia                                        │
│ ├─ 展示层：SVG/Canvas 渲染器（矩阵 / S 盒 / 密钥扩展）      │
│ ├─ 控制层：步进控制器（播放 / 单步 / 回退 / 时间轴）        │
│ └─ 采集层：操作轨迹上报（停顿、回退、点击）                 │
└───────────────────────────┬────────────────────────────────┘
                            │ REST + SSE（流式回答）
┌───────────────────────────▼────────────────────────────────┐
│ FastAPI（Python）                                           │
│ ├─ /aes/*      加解密与分步状态快照                          │
│ ├─ /session/*  操作轨迹采集与查询                            │
│ ├─ /tutor/*    AI 辅导（上下文裁剪 + 超时降级 + 缓存）       │
│ └─ /quiz/*     题库、判分、错因定位                          │
│ SQLite：users / sessions / step_events / diagnoses / quiz   │
└───────────────────────────┬────────────────────────────────┘
                            │
                  ┌─────────▼──────────┐
                  │ LLM API（码道/华为云）│ 提示词模板 + 工具调用
                  └────────────────────┘
```

### 关键工程决策（答辩可讲点）

1. **AES 必须自实现**：调库拿不到中间状态，没有矩阵快照就没有可视化。这是架构层面的必然而非偏好。
2. **状态矩阵列优先存储**（FIPS-197 规定），是最容易写错的地方，用官方向量做单元测试兜底。
3. **列混合的 GF(2⁸) 乘法用 xtime 实现**，不查表，才能讲清"乘 02 等于左移加条件异或"。
4. **AI 调用超时降级 + 高频问题本地缓存**，现场网络抖动不至于翻车。
5. **SSE 流式回答**，首字延迟低，演示观感好。
6. **前端动画用 Canvas 局部更新 + requestAnimationFrame**，不逐帧重渲整个 4×4 矩阵。

## 9. 这个项目能展示什么（演示脚本）

### 9.0 开场 30 秒话术（答辩与视频片头共用）

> 这是我做的 **CipherLens**，一个把 AES 拆开给你看的教学平台。
> 现在市面上的可视化工具能播动画，但播完就结束了 —— 学生卡在第 3 轮列混合的时候，没人告诉他为什么。
> 所以 CipherLens 多做了一件事：它记录你在哪一步停住、反复回退、反复点同一格，然后**主动开口问你"是不是卡在列混合"**。
> 不只看见，还懂你卡在哪。

**结构说明**：第一句是什么（8 秒）→ 第二句别人怎么样 + 痛在哪（10 秒）→ 第三句我多做了什么（8 秒）→ slogan 收尾（4 秒）。共 4 句、约 30 秒，不出现任何技术名词，评委零门槛听懂。

## 12. 与选题参考四方向的对照 · 偏题自查

| 方向 | 主题 | A 的关系 |
|---|---|---|
| 方向一 | 密码学算法可视化教学与 AI 辅导平台 | **A 属此方向** |
| 方向二 | 本地优先端到端加密文件暂存工具 | 无关 |
| 方向三 | 校园场景轻量凭证签发与验证 | 无关 |
| 方向四 | 面向非技术用户的密码学闯关科普 | 无关（已列入红线，不做游戏化） |

### A 与方向一逐条对照

| 方向一原文要求 | A 的做法 | 判定 |
|---|---|---|
| 选一个或几个核心算法（建议 AES 或 RSA，**不要贪多**） | 只做 AES，做到四步 + 正逆 S 盒 + 密钥扩展全展开 | 正解 |
| 实现逐步可视化，逐步展示状态矩阵变化、轮密钥生成 | F1 + F2 + 深度项 1/3 | 对应 |
| 加入"解释当前步骤"的对话面板，学生选中任意一步提问 | F3，且携带真实状态数值 | 原话对应 |
| 码道作为"辅导层"引擎，把选中步骤上下文提供给智能体 | 架构层已体现 | 对应 |
| 工作量中等，重点在把算法拆解为可展示的步骤 | 主要工作量正砸在此 | 对应 |

**偏题判定：不偏题，属方向一正解 + 一层加强。**

三条理由：
1. A 的主体 100% 是方向一，只是把"对话面板"做深成了"诊断"。
2. 方向一原文说"针对学生**当前操作**给出解释"，A 只是把"当前操作"变成"可追踪的操作轨迹"，是同一句话的实现深化，不是换赛道。
3. 选题参考末尾明确写了"四个课题仅作参考，可按实际情况选其他课题，但要符合大方向：密码学、web 应用程序"。A 连这个自由度都没用满。

### 三个越界风险点与处置

| 风险点 | 为什么会偏 | 处置 |
|---|---|---|
| 加第二个算法（SM4/RSA/插件化） | 方向一明确"不要贪多" | 不做 |
| 往趣味闯关跑 | 变成方向四，人群不符 | 不做剧情化 |
| 教师端学情看板 | 任务书与方向一均未要求 | 降 P2，时间紧直接砍 |

> 安全边界一句话：**只做 AES + 只服务学生 + 不做游戏化。**
