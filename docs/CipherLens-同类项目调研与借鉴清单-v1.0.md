# CipherLens · 同类项目调研与借鉴清单 v1.0

调研日期：2026-11-02
调研目的：找出 GitHub 上已有的 AES 可视化 / 密码学教学项目，提取可借鉴的具体设计，确认本项目的差异化边界，并准备答辩防守口径。
调研方法：以 6 组关键词检索 + 直接读取仓库 README 原文。所有项目均可在 github.com 直接访问，技术栈与功能描述来自 README 原文，非推测。
使用原则：**只借鉴设计思路、信息架构与交互模式；不复制任何项目的代码、文案与视觉资源。** 本项目 AES 引擎与可视化组件全部自研。

## 3. 五条最值得借鉴的设计（落到我们的功能点）

### 借鉴 1：三段式 trace 数据模型（来自 P1）

P1 把追踪数据拆成三层：整体追踪 → 每轮记录 → 每步记录。这是整个可视化项目的地基，比"边算边渲染"稳得多。

**落到我们的设计**：定一个前后端共用的快照结构，作为接口契约的核心。

```python
StepSnapshot:
  index: int              # 全局步序，用于时间轴定位
  round: int              # 轮次 0..Nr
  op: str                 # sub_bytes | shift_rows | mix_columns | add_round_key
  state_before: bytes     # 16 字节（列优先存储）
  state_after: bytes      # 16 字节
  changed_bytes: list[int]# 本步变化的字节下标 ← 供前端 diff 高亮
  round_key: bytes        # 本步参与的轮密钥（16 字节）
  meta: dict              # 该步专属信息（如列混合用了哪个系数、S盒输入输出对）
```

**收益**：① 时间轴拖拽只需按下标取快照，不用重算；② 前端渲染逻辑统一，四种操作共用一套渲染器；③ AI 辅导时直接把 `StepSnapshot` 序列化进 prompt，天然满足"携带真实数值"。

### 借鉴 2：单步操作模式（来自 P4）

P4 允许学生只执行一次 SubBytes，不跑完整流程。

**落到我们的设计**：练习模式增加"单步训练"入口——选一个操作类型 + 输入一个 4×4 矩阵，只做这一次变换，立即看到结果与解释。

**收益**：① 学生卡在列混合时不必重跑 10 轮；② 实现成本极低（引擎已有该函数）；③ 直接覆盖任务书"参数调试"的要求；④ 演示时可以 5 秒讲清一个知识点。

### 借鉴 3：变化 diff 高亮（来自 P2）

P2 的做法是**高亮相邻步骤之间变化的字节**，而不是整片变色。

**落到我们的设计**：每步只对 `changed_bytes` 做动画，其余字节保持静止，配一个 200ms 的过渡。

**收益**：① 观感从"整块闪一下"变成"精准指认改了哪几个字节"，这正是教学需要的；② 减少重绘面积，动画卡顿问题一并缓解；③ 写进 F1 的验收标准，可测。

### 借鉴 4：状态导出（来自 P3）

P3 支持把每轮状态导出 CSV / JSON / PNG。

**落到我们的设计**：新增导出功能，一键导出当前加解密全过程的状态表（CSV）、完整 trace（JSON）、当前视图（PNG）。

**收益**：① 实习报告里的表格截图直接来自系统，不用手画；② 答辩 PPT 素材现成；③ 让老师能拿导出数据核对你的算法是否正确——**这是"可信"的证据**；④ 实现成本低。

### 借鉴 5：每步配解释（来自 P5，但我们升级）

P5 给每一步配一段预写的文字解释，讲"为什么"。这是好设计，但它是静态的。

**落到我们的设计**：同样在每步旁边放解释区，但内容是 **AI 按当前真实数值生成**（F3），同时把这套预写文案做成本地降级模板（第 8 节的降级要求）。

**收益**：① 别人做到"每步有解释"，我们做到"每步解释说的是你这一屏的数"；② 网络故障时退化为 P5 的水平，不至于开天窗；③ 一举两得：降级方案与对标功能是同一份资产。

## 4. 差异化确认：我们和它们的区别

这是本次调研最重要的产出。**以下三点在本次调研范围内没有找到同类实现**，且三点都直接对应任务书要求：

| # | 我们的独有做法 | 同类项目做到哪一步 | 对应的任务书条目 |
|---|---|---|---|
| D1 | **操作轨迹 → 误解判定 → 主动反问**：记录停顿 >8s、连续回退、同位置反复点击，判定为 3 类高频误解之一，页面主动开口问 | 全部无。P8 有 AI 评分与 Teach AI，但只针对"文字答案"，不与算法状态、操作行为绑定 | 模块 4"AI 辅导对话"的深化 |
| D2 | **LLM 上下文注入当前步骤的真实数值**：提问时把 `StepSnapshot` 序列化进 prompt，AI 讲的是这一屏正在发生的数 | P5 每步有解释，但是**预写文案**，不随输入变化；其余项目无 AI | 模块 3"提示词工程 + 上下文管理" |
| D3 | **练习判分定位到"第几轮第几步哪个字节"**：不只判对错，直接指出错在列混合并高亮出错字节 | P7 有测验，但是**选择题**；P4 可单步执行但不判错因 | 模块 7"练习模式 + 测试" |

**一句话总结**：现有项目解决的是"**看不看得见**"，我们解决的是"**看不看得懂**"。前者靠渲染，后者靠诊断。

## 5. 答辩防守口径（必须准备）

老师或评委搜到 P1–P7 的概率不低，被问到时不要辩解，直接承认并给出差异：

> "AES 的逐步可视化确实已经有不少开源实现，我调研了 7 个，它们的共同点是：能播动画、能单步、能给解释。我做的不一样的地方在于——**它记录你怎么操作**。你在列混合这一步停了 8 秒、退回去三次，它会判断你可能没理解列混合的扩散作用，然后主动问你一句，而不是等你想起来去点帮助。这一层，我调研的项目里没有。"

**不要说**："我的项目是首创""市面上没有类似的东西"——不成立，一问就穿。

**要说**："可视化部分是站在开源实现的设计思路上做的，差异化在诊断层。"
