## 0. 本文档的边界（先划清，避免与视觉冲突）

**我负责**：区域职责划分、元素的存在与否、交互行为与反馈、状态机、键位、焦点顺序、错误与降级处理、文案、对 PRD 逻辑的质疑。

**我不负责**：具体色值、字体、字号、间距、阴影、圆角、动画曲线与时长、图标库选型。

**我向视觉提出的硬约束（这些是交互需求，不是审美偏好）**：

| 编号 | 约束 | 为什么是硬要求 |
|---|---|---|
| UX-V1 | 每一个交互状态都必须有「颜色之外的第二个视觉通道」（边框/角标/图标/形状/文本标签） | 色盲用户与投影失真双重风险，见 5.4 |
| UX-V2 | 演示模式（投屏）需要独立一套视觉参数，不是把普通模式放大 | 投影仪对比度与 gamma 与显示器差异极大，见 5.3 |
| UX-V3 | 任何浮层不得覆盖矩阵区与时间轴 | 矩阵是唯一不能被遮的内容，PRD 只说了"不遮矩阵"，我把它扩展到时间轴 |
| UX-V4 | 动效时长必须能被 `prefers-reduced-motion` 与页内开关同时归零，且归零后信息不丢失 | 见 5.5 |
| UX-V5 | 焦点环在投影环境必须可见（视觉需给出演示模式下的焦点样式） | 教师用键盘操作时全班要看得到焦点在哪 |

## 1. 信息架构

### 1.1 导航结构（一层全局 + 一层页面内，抽屉为第三层）

```
┌─ 全局顶栏（常驻，不随滚动隐藏）───────────────────────────────────────┐
│  CipherLens   看  练  记录  [工具 ▾]      ⟨上下文胶囊⟩   [演示] [登录] │
└──────────────────────────────────────────────────────────────────────┘
                  │  │   │       └─ S 盒浏览器 PG-3
                  │  │   │          密钥扩展 PG-4（全屏态）
                  │  │   │          单步训练 PG-7
                  │  │   └─ 学习记录 PG-8 ── 错题本（tab，非独立页）
                  │  └─ 练习模式 PG-6
                  └─ 可视化工作台 PG-2  ←—— 唯一主场景
```

- 全局顶栏 5 项：**看 / 练 / 记录 / 工具▾ / 账户**。层级深度：全局(1) → 页面(2) → 抽屉或面板(3)，**最深 3 层，符合要求**。
- **「工具」下拉里的三个页面都是旁路**，它们存在的目的是"回答一个单点问题然后回到工作台"，不是并列的主场景。因此它们在导航里被收进下拉，不与"看/练/记录"平级——这是有意的信息降权。
- 「账户」菜单承载：登录/退出、关于与隐私（PG-10）、演示模式开关、数据导出。**PG-10 不占顶栏位置**，因为它是一次性阅读页，给它导航位会稀释主场景。

### 1.2 页面职责（一句话，可据此判断"这个页面该不该存在"）

| 编号 | 页面 | 一句话职责 | 定位 |
|---|---|---|---|
| PG-1 | 首页 | 让第一次来的人在 10 秒内选一条路径，并提供一条"什么都不用懂也能看到结果"的默认路径 | 入口 |
| PG-2 | 可视化工作台 | 唯一主场景：看、问、调、比，全部在这一屏闭环 | **主场景** |
| PG-3 | S 盒浏览器 | 回答"某个字节经 S 盒变成什么、被谁替换"，并带着这个答案回到工作台的某一步 | 旁路（查询工具） |
| PG-4 | 密钥扩展视图 | 回答"第 N 轮的 4 个字从哪来、怎么算出来的"，是工作台密钥轨的全屏展开态（同一组件，两种尺寸） | 旁路（工作台的延伸） |
| PG-5 | 字节明细抽屉 | 回答"这个字节从哪来、经过什么、变成什么"，是矩阵格的纵深，**不是新场景** | 工作台的纵深（抽屉，非页面） |
| PG-6 | 练习模式 | 验证"我是不是真的会算"，并把错误导回工作台做对照 | 任务流 |
| PG-7 | 单步训练 | 把某一步单独拎出来反复练，是练习的手术刀版本 | 旁路（训练工具） |
| PG-8 | 学习记录 | 把行为数据回译成"我卡在哪"，并指向下一道该做的题 | 任务流 |
| PG-9 | 登录注册 | 只为一件事存在——让记录留得住。**不阻断任何学习行为** | 附属 |
| PG-10 | 关于与隐私 | 合规与信任，一次性阅读 | 附属 |
| PG-11 | 教师端学情看板（P2） | 把全班步骤级数据变成热力图，属**独立的第二产品面** | 另一条产品线 |

### 1.4 如何让用户不迷路：7 条机制

| 编号 | 机制 | 具体做法 | 解决什么 |
|---|---|---|---|
| N-1 | **上下文胶囊**（核心） | 顶栏常驻一个胶囊，显示"FIPS-197 向量 · AES-128 · 第 2 轮 列混合 · 13/24"。在**任何页面**点它都回到工作台的该步 | 解决"我现在在哪、我刚才看到哪了"，这是全局的锚点 |
| N-2 | **回主场景按钮统一措辞** | 所有非工作台页面顶部固定一个按钮：「回到第 13 步」（不是"返回"、不是"回首页"） | 一次点击回到中断处，而不是回到起点重来 |
| N-3 | **旁路页带上下文** | 进 PG-3 / PG-4 / PG-7 时若已有会话，页面顶部显示「基于当前数据集第 13 步」，并预填查询参数 | 防止旁路页变成"空白工具"导致用户不知道从哪查起 |
| N-4 | **抽屉优先于页面** | PG-5 必须是抽屉；PG-4 默认是抽屉、可升为全屏。独立路由只服务深链接与教师投屏 | 减少一次整页跳转 = 减少一次上下文丢失 |
| N-5 | **状态全量可恢复** | 明文/密钥/长度/方向/step_index/抽屉开合全部编码进 URL query + localStorage，浏览器前进后退可用；刷新后提示「继续上次（第 13 步）」 | 刷新是教学工具的高频动作（学生截图、开新标签对比） |
| N-6 | **破坏性操作只有一次确认** | 换密钥长度 / 换明文 / 换方向会重置 trace → 二次确认，明说"当前步会回到第 0 步"，并提供「在新标签页打开」作为无损替代 | 换长度顺手就点，重置后学生以为"我刚才看的没了" |
| N-7 | **导航常驻不隐藏** | 顶栏不做随滚动收起 | 教师投屏时要随时切页面，隐藏式导航在投影里等于不存在 |

| **A 上下文条** | 告诉用户"我现在看的是哪一组数据、什么参数、朝向" | 数据集名（或"未命名"）、密钥长度、加解密方向、演示模式开关、导出▾ | 切加密/解密、切演示模式、导出、点胶囊回该步 | 不放播放控制（在 D）、不放 AI 状态（在 E） |
| **B 输入区** | 产出/更换 trace 的唯一入口 | 明文输入、密钥输入、密钥长度下拉、轮数（只读，由长度推导）、载入标准向量、生成 | 输入、粘贴、载入向量、生成、切换长度 | 不做播放控制；不显示矩阵内容 |
| **C 舞台区** | 承载"这一步到底改了什么"这个唯一的视觉主角 | 步标题（C1）、变化摘要句（C2）、4×4 矩阵（C3）、轮密钥轨（C5）、变化字节的视觉标注 | 点任一字节→抽屉、键盘在矩阵内移动、悬停看旧值→新值 | **不允许被任何浮层覆盖**；不叠放 AI 回答 |
| **D 步进与时间轴** | 控制"我在第几步"，同时承担"我的学习足迹"可视化 | 播放/暂停、上一步/下一步、跳整轮、步计数器、时间轴（按轮分段）、诊断标记、提问标记 | 播放、暂停、单步、跳转、拖拽、点标记跳转 | 不做参数修改（在 B） |
| **E AI 辅导栏** | 承接"针对当前这一步的提问"与主动诊断提示 | 上下文头、预设问题 chip、对话流、输入框、跟随开关、降级/来源标识 | 提问、点 chip、追问、停止生成、收起栏、关跟随 | 不在栏内做参数修改；不遮挡矩阵 |
| **F1 字节明细抽屉** | 单字节的因果链（从哪来→经过什么→变成什么） | 字节位置、旧值/新值、参与的操作、S 盒输入输出对、来源字节链 | 查看、跳到 S 盒、跳到该步、上一个/下一个字节 | 不做成整页（会丢上下文） |
| **F2 密钥扩展抽屉/全屏** | 轮密钥的生成过程（RotWord→SubWord→Rcon→异或） | 44/52/60 字条带、当前轮高亮、分步展开、定位输入 | 逐字查看、定位到某轮、跳到工作台该轮、升全屏 | 不重复渲染一套独立数据 |

### 2.3 信息密度：渐进披露策略（本页最容易做坏的地方）

**先说结论**：这一屏同时要放矩阵、轮密钥、步骤说明、时间轴、AI 输入框，**五者全部常显必然失败**。因此按"回答问题的紧急程度"分四层，而不是按"重要性"分层。

| 层 | 名称 | 内容 | 唤起方式 | 判断依据 |
|---|---|---|---|---|
| **L0** | 常显（永不需要点击） | 4×4 矩阵；步标题（第 N 轮 · 操作名）；时间轴；播放/单步；AI 输入框 + 上下文头 | 默认 | 缺任何一项，核心任务（看懂一步）就断了 |
| **L1** | 一处点击 | 变化摘要句展开为逐字节映射表；轮密钥轨从"本轮 4 个字"展开为"含来源箭头"；AI 预设问题 chip | 点击行内展开器 | 这些是"想知道更多细节"才需要，不是每步都看 |
| **L2** | 抽屉（覆盖 E 区） | 字节明细（PG-5）、密钥扩展（PG-4 抽屉态）、S 盒查询结果 | 点矩阵格 / 点密钥轨 / 点数值 | 属于"单个对象的深入"，可覆盖 AI 栏但**绝不可覆盖矩阵** |
| **L3** | 独立页 | 练习、单步训练、学习记录、S 盒浏览器 | 顶栏或上下文入口 | 是任务切换，不是同一任务的细节 |

**四条密度纪律（写给前端，是可验收的）**：

1. **单活动焦点原则**：一屏之内只允许一个"正在变化、正在吸引注意力"的区域。当 AI 栏处于流式输出时，时间轴与矩阵**不得**同时触发 diff 过渡动画、不得弹出诊断提示。否则两个通道争注意力，学生会漏读回答。实现上：`activeChannel = 'tutor' | 'playback' | 'idle'`，同一时刻只有一个。
2. **矩阵不可遮原则**：诊断提示、AI 回答、错误提示、导出进度、抽屉，一律不得覆盖 C 区与 D 区。诊断提示放在 E 区顶部（一行），错误提示放 B 区行内，进度放 A 区右侧。
3. **摘要先于明细**：C2 默认只给一句话（"本步 16 个字节中 4 个被替换：下标 0、5、10、15"），要逐个看映射才展开。默认展示 16 组 hex 对照会把矩阵淹掉。
4. **密集区可收起**：B 输入区在 trace 已生成后可整体折叠为一行（"明文 32 41 … · AES-128"），把宽度让给矩阵与 AI。折叠状态记入 URL。

### 2.4 时间轴规格（细节最多的控件）

**结论先行（v1.1，经产品裁决）**：标记采用**上下列轨、不合并**。理由是最初按 4px 设计时，投影 + 1m 观看距离下"圆 vs 方"基本不可辨（放大到 5px 后略好，但形状仍只做辅助），**位置通道比形状通道可靠**；且叠加时不必发明第三种符号。代价是 D 区变高，成本已核算且接受。

#### 2.4.1 轨道结构（4 条水平轨，不是 1 条）

| 轨道 | 高度 | y 起点 | 承载 |
|---|---|---|---|
| ① 轮号带 | 16px | y2 | 轮分段 + 轮号文本（`INIT` / `R1`…`R10`）+ 段间 2px 分隔线 |
| ② 刻度轨 | 10px | y18 | 每步 1px×6 竖刻度；轮边界 2px×10 |
| ③ 标记轨 | **20px** | y28 | **上沿 y30–35** = 系统推测（诊断，5px 圆）；**下沿 y41–46** = 我的提问（5px 方） |
| ④ 游标行 | 14px | y48 | 2px×46px 竖游标（贯穿①–③）+ 顶部三角 + 步号文本 |

**D 区总高**：常规 **104px**（控制行 40 + 时间轴 64）｜演示 **136px**｜`max-height: 780px` **92px**（压轮号带 16→14、控制行 40→36）。

**硬约束**：任何断点下**不得减少轨道条数**。轨道是这类控件的结构，压掉一条就丢一类信息。

**步数 / 轮数由 trace 数据驱动**，UI 不写死 24 / 40 / 58。

#### 2.4.2 标记：位置承载语义，形状只做辅助

| | 系统推测（诊断） | 我的提问 |
|---|---|---|
| 轨道位置 | 标记轨**上沿** y30–35 | 标记轨**下沿** y41–46 |
| 形状 | **5px 实心圆** | **5px 实心方** |
| 语义 | 一个**时刻**（我这一刻卡住了） | 一段**关注区间**（我关心过这一步） |
| 点击热区 | **该步整列宽 × 20px 竖条，上下两标记共用同一个热区（一个 `<button>`，不是两个）** | 同左 |

- **热区为什么必须是"一步一个"而不是"一个标记一个"（v1.3 补，视觉自查时提出）**：同一步上圆和方**可以同时存在**（这是分轨不合并的直接后果）。如果做成两个各自"整列宽 × 20px"的按钮，它们就是**两个完全重合的矩形**——只有 z 更高的那个点得到，另一个鼠标键盘都点不到；而且**键盘 Tab 两次焦点环画在同一个框上**，用户会以为"焦点没动"（违反 WCAG 2.4.7 焦点可见）。**把高度劈成上下各 10px 也不成立**：两个 10px 高的目标上下相接，按 WCAG 2.5.8 的 spacing 判定，以任一目标为心的 24px 圆必然与另一个相交，等于两个都不达标。**正解是"一步一个热区"**：用户在这一层想表达的是"这一步有标记"，不是"我要点那个圆"。详情在 E 区卡里按类型分两组列出（见 §2.4.4「标记详情的落点」），每一条自己可点。这样：只有一个热区 → 无重合；高度 20px 但垂直方向不与任何其他目标相邻（上下都是非交互的轨道带）→ 满足 2.5.8 的 spacing 例外。
- **热区宽度必须由列宽决定，绝不写死 12px（同轮自查发现的第二个坑）**：列宽是**数据驱动**的——24 步约 25px，AES-256 的 58 步约 10px。写死 12px 在 58 步时会**跨到相邻步**，出现"点第 13 步落到第 14 步"，而这正是我在标记形状上否决横条时的同一个病（动态尺寸的东西不能当固定值用）。用 `grid` 的列宽：`width: 100%` 落在该步的列容器里即可。
- 同一 x 上两者**并存不合并**。若合并，就必须回答"合并后怎么表达两个语义"，任何答案都比"两个都在"更绕。
- **位置（上/下）是第一通道，形状是第二通道**。5px 已比我最初假设的 4px 大，形状通道勉强可用；真正的兜底是图例（2.4.3）——用户只需被告知一次"上圆下方形"即可长期记住。
- **v1.2 撤回"2px 横条"方案，理由是我漏掉了一个冲突**：② 刻度轨就在标记轨正上方，一条 2px×N 的横向短条在 40+ 步（AES-256 共 58 步）时会退化成 10×2px，与刻度轨的 1px×6 竖刻度在视觉上极易混读成"又一种刻度"。**形状方案要跟相邻轨道的已有语汇共存**，这一条我先前没算进去。同时撤回的原因是：横条原本的两个优势（宽度通道、语义对齐）都被"图例 + 位置通道"覆盖了，剩下的只有成本。
- **标记轨内，标记 z 高于游标。**（此条维持，不接受视觉"被游标压住时左偏 1px"：游标 2px、标记 5px，左偏 1px 后可见 2.5px/0.5px 严重不对称；更关键的是**位置本身是语义**——偏移会让标记看起来属于相邻那一步，而这个控件全部靠位置表达。游标位置已由 ④ 游标行的 `▮` 与 `13/24` 文本冗余表达，在标记轨内不必压住标记。）

#### 2.4.3 图例（产品硬要求：不许让用户靠猜）

**位置改判（v1.2）**：接受视觉方案——放在**控制行右端**，不放标记轨右端。理由是我原先的考虑（视线不跳）站不住：标记轨右端在步数多时会被末端标记占用，且挤在 20px 带内会与轨道内容争宽；控制行是"解释这一区"的天然位置。代价是控制行右端已有 5 个按钮 + 步号 + 跟随开关，必须**共享槽位**。

| 项 | 规格 |
|---|---|
| 内容 | **图形 + 文字**：`[圆] 系统推测` ｜ `[方] 我的提问`。方括号处是**与轨道标记同一个 class 的 CSS 图形**，不是字形字符 |
| 位置 | 控制行右端固定槽位，**与键盘提示共享同一槽位** |
| 槽位优先级 | 时间轴聚焦时 → 键盘提示（`← → 单步，PgUp/PgDn 跳轮`）；否则 → 图例。两者永不同时需要，且都不新增高度 |
| 显示条件 | **会话内已有 ≥1 个标记时**，图例常显（不是 hover 才显）。无标记时降为 `?` 图标按钮，不占据整槽宽度 |
| 首次提示 | 首访可给一次短暂的下划线提示，但**不得异步循环**；`prefers-reduced-motion` 下改为静态呈现（提示只是锦上添花，`?` 按钮才是兜底） |
| `?` 兜底 | 无标记时的 `?` 按钮必须带可读标签 `aria-label="时间轴标记图例"`，点击展开与常显版相同的内容 |
| 符号实现 | 符号与轨道内标记**同源：复用同一个 class，不改尺寸**（"不是另画一个小图标，是把同一组件缩到同一尺寸再放一遍"）。**禁止用 Unicode 字形字符**（`●`/`▪` 的尺寸、字重、基线由字体决定，11px 下渲染差异大、投影易糊，且无法满足"图例与轨道像素级一致"）。图例文字 `--ink-3` 11px |
| 演示模式 | **强制常显、放大到 13px**，投屏时必须能读，不降级为 `?` |
| 可聚焦性 | **常显的图例文本不进 Tab 序列**（它没有操作，多一个空 Tab 站只会拖慢键盘用户）。改为把它挂到时间轴滑块的 `aria-describedby` 上——读屏用户一聚焦时间轴就听到「系统推测用圆点表示，我的提问用方块表示」，比单独一个 Tab 站更早、更省事。只有 `?` 按钮态可聚焦 |
| **describedby 的实现红线（v1.3 补，视觉指出的坑）** | 上面那条 `aria-describedby` 会和"槽位优先级"打架：**时间轴一聚焦，槽位内容就被键盘提示替换**。如果实现按常规写成"切换时把图例节点 `display:none` / `v-if` 掉"，那么**在需要它的那一刻它正好不存在**——`aria-describedby` 指向一个不可访问节点，读屏什么都听不到，比不加 describedby 更糟（用户以为没有说明）。**约束**：① 图例与键盘提示**两个节点都常驻 DOM**，切换只换"看得见/看不见"；② 图例收起时必须用 **`.sr-only`（`clip-path` 裁成 1×1 + absolute）**，**禁止 `display:none`、禁止 `visibility:hidden`、禁止 `hidden` 属性、禁止 `aria-hidden="true"`** —— 这四种都会把节点从无障碍树里摘掉，症状完全一样；③ 提交前用 `getComputedStyle` 断言一次：时间轴聚焦后图例节点仍然 `display !== 'none'` 且 `getBoundingClientRect().width > 0`（`.sr-only` 应得 1px，绝不是 0） |
| 读屏等价 | 帮助浮层（`?`）内含完整说明；**首个标记出现时 `aria-live="polite"` 播报一次**「时间轴上出现了一个标记，类型是"系统推测"，表示系统推测你在第 13 步遇到困惑」。**播报文案里不放字形字符**——读屏器会把 `●` 念成"黑圆"这类噪音，形状信息用文字说 |
| 不做 | 不做 hover 才显示（投影下没有 hover）；不做一次性 toast（错过就再也没有） |

#### 2.4.4 其余规格

| 项 | 规格 |
|---|---|
| 分段 | 按轮分段，段内再按操作分小格；第 0 轮 = 初始 AddRoundKey 单独一段，标 `INIT` |
| 段标签 | 不靠颜色区分轮（8 种色相色盲不可辨，见 5.4）；靠"交替底 + 2px 分隔线 + 轮号文本"三重冗余 |
| 拖拽态 | 拖拽中矩阵**实时更新**，同时游标改**空心**（预览 vs 执行的第二通道）+ 轨道顶部 1px 实线框 + 文本「浏览中」；松手后全部消失 |
| 动效归属 | **拖拽不触发 diff 过渡动画**，只有"播放/下一步"才触发。理由见 6.c |
| 边界 | 末步再按"下一步"不循环，提示"已是最后一步" + 「回到开头重看」；游标右端加 4px 短横帽 |
| 键盘等价 | `←/→` 单步（执行语义），`PageUp/PageDown` 跳轮（跳转语义），`Home/End` 首末步，**`[`/`]` 跳上一个/下一个有标记的步**。不允许存在只有鼠标能做的拖拽 |
| 可读播报 | 聚焦时播报"第 13 步，共 24 步，第 2 轮 列混合，此步有 1 条诊断提示、2 次提问" |
| 标记可达性 | **有标记的步**必须进入时间轴的 Tab 序列（不能只有热区；无标记的步不进，否则 58 步 = 58 个 Tab 站），`Enter` 打开该步的标记卡（卡内按类型分组，每条自己可聚焦） |
| 标记详情的落点 | **不弹浮层**。标记详情在 E 区展开一张卡（与诊断提示同位置）。理由：从控制行向上弹会覆盖矩阵或密钥轨（违反"矩阵不可遮"），向下弹会出视口；而 E 区本来就是"解释这一步"的地方 |
| 标记聚焦联动 | 焦点落在某个标记上时，**该步的轮号在轮号带加 1px 下划线**——只有焦点环的话，全班只知道"焦点在某个标记上"，不知道是第几轮，而教师投屏时恰恰要说"这是第 3 轮那一步" |

### 2.5 键盘快捷键清单

设计原则：**单字母键给高频操作，功能键给幂等操作，所有快捷键在输入框聚焦时失效（除 `Esc`）**。教学工具在课堂上被要求"手不离键盘"，这套键位同时是演示效率的保障。

| 键 | 动作 | 作用域 | 备注 |
|---|---|---|---|
| `Space` | 播放 / 暂停 | 工作台（非输入态） | 若焦点在按钮上，需 `preventDefault` 以统一行为 |
| `→` | 下一步（执行语义，带动画） | 工作台 | 与时间轴 `→` 语义一致 |
| `←` | 上一步（反向执行） | 工作台 | 反向动画，不是跳转 |
| `Shift + →` | 跳到下一轮第一步 | 工作台 | 教师演示常用 |
| `Shift + ←` | 跳到上一轮第一步 | 工作台 | |
| `Home` / `End` | 首步 / 末步 | 工作台 / 时间轴聚焦时 | |
| `J` | 跳到指定步（弹出小输入，接受数字或"r2m"这类简写） | 工作台 | "Jump" |
| `A` | 聚焦 AI 输入框 | 工作台 | "Ask"；再按一次回到原焦点 |
| `Enter` / `Shift+Enter` | 发送 / 换行 | AI 输入框内 | |
| `Esc` | 中断流式生成 / 关抽屉 / 取消拖拽 / 退出播放 | 全局 | 优先级：中断生成 > 关抽屉 > 退出播放 |
| `[` / `]` | 跳到上一个 / 下一个**有标记的步** | 工作台 | 一步一个停靠点（v1.3 起不再区分诊断/提问，见 §9.1）；无标记时给一句「本会话还没有标记」，不静默失败 |
| `?` | 快捷键与术语帮助浮层 | 全局 | 帮助里同时列出"字节下标从 0 开始"这类约定 |
| `D` | 切换加密 / 解密 | 工作台 | "Decrypt toggle" |
| `V` | 载入 FIPS-197 标准向量 | 工作台 | "Vector" |
| `1` `2` `3` | 密钥长度 128 / 192 / 256 | 工作台 | 会触发 N-6 的二次确认 |
| `F` | 收起 / 展开 AI 栏（给矩阵更多宽度） | 工作台 | 投屏时常用 |
| `G` | 打开密钥扩展抽屉 | 工作台 | "Key Generation" |
| `S` | 在 S 盒浏览器中查当前选中字节 | 工作台 / 字节抽屉 | 已有选中字节时可用 |
| `E` | 打开导出菜单 | 工作台 | "Export" |
| `P` | 切换演示模式 | 全局 | "Presentation" |
| `Tab` / `Shift+Tab` | 焦点前进 / 后退 | 全局 | 不接管，不设置 tabindex 陷阱（抽屉除外） |

**冲突处理规则**：输入框（明文/密钥/AI）聚焦时，除 `Esc`、`Tab`、`Enter`（AI 发送）外不响应任何单字母快捷键；`Space` 在输入框内正常输入空格。所有快捷键在帮助浮层里可查，且帮助浮层入口在 UI 上常驻一个 `?` 图标——不能只藏在键位里。

### 2.6 焦点顺序与焦点管理

1. **默认 Tab 顺序**：A 上下文条 → B 输入区 → C 矩阵（**单一 Tab 入口**，内部用方向键 roving tabindex 移动 16 格）→ C5 轮密钥轨 → D 时间轴 → E AI 栏 → 顶栏。
2. **矩阵只占一个 Tab 位**：否则用户要按 16 次 Tab 才能穿过去。进入后方向键在 4×4 内移动（到边界不跨行跳，避免方向混乱），`Enter` 打开字节抽屉，`Esc` 退出。
3. **抽屉打开时**：焦点移入抽屉首元素，焦点陷阱；关闭后焦点**还给触发元素**（那个矩阵格），不能还给 body。
4. **流式回答时**：焦点不动（不许抢焦点）；「停止生成」按钮在 Tab 顺序里排在回答内容之前，保证可键盘中断。
5. **诊断提示出现时**：**不移动焦点**（这是骚扰性最强的错误做法），只在 E 区顶部插入一个可 Tab 到达的条目，并用 `aria-live="polite"` 播报。

## 3. 关键交互流程

### 3.1 主流程：第一次进来 → 看懂一步 → 提问 → 得到解释 → 继续

| 步 | 触发条件 | 系统反馈 | 用户可做的选择 | 失败时怎么办 |
|---|---|---|---|---|
| 1 | 打开首页 | 显示三个入口卡（看/练/直接提问）+ 一行「没有数据？载入 FIPS-197 标准向量」 | 点任意 | 无网络 → 卡片仍可点，进工作台后由 B 区错误态承接 |
| 2 | 点"看"或"载入向量" | 进工作台，自动填入标准向量，**生成 trace 后停在第 0 步，不自动播放** | 按空格播放 / 直接点矩阵某一格 | trace 接口失败 → 矩阵区显示错误态 + 重试 + 「用内置离线向量试一次」 |
| 3 | 未自动播放的静止态 | C2 显示"已生成 24 步。按空格开始，或点任意字节看它现在是什么" | 播放 / 单步 / 看字节 | — |
| 4 | 按空格 | 矩阵逐步更新，只对变化字节做过场；C1 更新步标题；C2 更新摘要句 | 随时暂停 | 动画卡顿 → 降级为瞬时切换（见 5.5），不阻塞 |
| 5 | 用户暂停在某步 | E 区上下文头更新为"当前：第 N 轮 · 操作 · 变化摘要"；**不自动调模型**，只出 3 个预设 chip（本地静态） | 点 chip / 直接输入 / 收起 AI 栏 | — |
| 6 | 点 chip 或输入问题 | 输入立即上屏为用户消息；3s 内无首字 → 显示"正在组织讲解…" + 「先看本地要点」兜底 | 等待 / 点兜底 / 按 Esc 中断 | 首字超时 → 本地模板回答，标注「离线讲解」；总超时 → 错误条 + 重试 |
| 7 | 回答流式输出 | 回答中出现的数值可点击；点击后矩阵对应字节高亮并显示该字节旧值→新值 | 点数值 / 继续追问 / 拖时间轴 | 回答未含本步数值 → 标记为「通用讲解」（PRD 已有，保留） |
| 8 | 用户继续追问 | 多轮上下文保留在本步内 | 追问 / 换步 | 换步时按 6.2 的修正处理（折叠旧回答，不丢） |
| 9 | 离开再回来 | 恢复上次数据集与 step_index，提示"继续上次（第 13 步）" | 继续 / 从头开始 | localStorage 损坏 → 静默回第 0 步，不报错 |

**关键决策说明**：**不自动播放**。理由有三——① 自动播放时用户还没建立"这里有个 4×4 矩阵"的认知，动态内容会让人无从下手；② 自动播放与"我要停在这里提问"是冲突的，用户第一反应是找暂停；③ 自动播放会立刻触发 dwell 计时干扰诊断（见 6.1）。改为"已生成 24 步，按空格开始"，把控制权第一次就交给用户。

### 3.2 分支流程：被诊断发现卡点 → 主动提示 → 接受/拒绝 → 后续

```
[静默采集] 用户在同一个 step_index 上活动
   │ 采集信号（本地，不实时打接口）：该步累计可见停留时间 / 回退-前进往返次数 /
   │ 同一字节格重复点击次数 / 在 AI 输入框里输入后又删除未发送
   ▼
第 1 级：静默标记（永不打扰）
   └→ 仅两处变化：时间轴该步出现一个圆点；E 区顶栏出现一行浅色文字
      「这一步你停留较久，需要提示吗？」
   └→ 用户无动作 → 30s 后该行自动收起，圆点保留
   ▼
第 2 级：用户点击该行（或同一误解类型在会话内第 2 次命中）
   └→ E 区内推出一条反问（不遮挡矩阵、不动焦点、不清空已有对话）
      「你是不是在困惑：列混合为什么会让一个字节扩散到一整行？」
      [是，讲讲]  [不是，继续看]  [这提示不对]
   ▼
  ├─ 是 → AI 展开讲解（提示式，先不给答案）+ 底部一个「单步训练：只练列混合」入口
  │        └→ 讲完 5s 后出现一个不打扰的自评：「明白了 / 还是不太懂」
  │              └→ 还是不懂 → 换一种讲法（换类比）一次；第二次仍不懂 → 建议看字节明细抽屉
  ├─ 不是 → 记录否定：该误解类型本会话不再提示；全局 24h 冷却；无任何提示条
  └─ 这提示不对 → 进「误解反馈」：三个选项（不是这个原因 / 我已经懂了 / 你在瞎猜）
                   → 同时把该规则在本会话的置信度阈值提高
```

| 项 | 内容 |
|---|---|
| 触发条件 | 见 6.1 修正后的多信号规则（不用 PRD 原来的单阈值） |
| 系统反馈 | 两级：静默标记 → 用户主动点击才出反问。**任何情况下不弹窗、不遮挡、不抢焦点** |
| 用户可做的选择 | 接受 / 拒绝 / 否定诊断本身 / 忽略（超时自动收起） |
| 失败时怎么办 | 诊断接口失败 → **完全静默**，不做任何替代提示（PRD 已如此规定，保留并强化为"连静默标记也不出"，因为标记依赖诊断结果） |
| 打扰成本控制 | 一次会话最多 3 次主动提示，同一误解类型最多 1 次；用户连续 2 次否定后本会话彻底停止 |

### 3.3 分支流程：练习做错 → 判分 → 错因定位 → 针对性补练

| 步 | 触发条件 | 系统反馈 | 用户可做的选择 | 失败时怎么办 |
|---|---|---|---|---|
| 1 | 进入练习 | 出题（按错因标签选题）；显示题目要求的输入/输出格式 | 作答 / 跳过 / 看提示（消耗次数） | 题库接口失败 → 用内置 5 道兜底题，标注「题库离线」 |
| 2 | 点提交 | 判分中；>1s 显示进度 | 等待 / 取消（可取消，回作答） | 判分接口失败 → 存入 localStorage 待提交，明说「未提交，网络恢复后会自动提交」 |
| 3 | 判错 | **三层反馈**（见 6.4）：① 一句方向性说明；② 首次差异位置（轮/步/字节）+ 矩阵高亮；③ 「错误传播图」——把首次错误步之后被污染的字节灰化并标注"受第 1 步影响" | 看提示（1 次）/ 看差异位置（1 次）/ 看完整解析 / 再试一次 | — |
| 4 | 学生想深究 | 「在工作台对照」按钮 → 打开 PG-2，载入该题明文/密钥，**并把 step_index 定位到首次差异步**，同时在 E 区自动带上"我这一步算的是 X，正确答案是 Y" | 对照 / 提问 / 返回练习 | 打开失败 → 保留练习页状态，toast 提示可重试 |
| 5 | 同一错因累计 2 次 | 给错因标签（"疑似：轮密钥时机"），并推荐 ① 同标签的另一题 ② 「单步训练：只练轮密钥加」 | 接受推荐 / 换一题 / 结束 | 推荐接口失败 → 只给"再来一题" |
| 6 | 加入错题本 | 已登录 → 直接加入并提示；未登录 → **允许加入本机错题本**，并软提示"登录后可跨设备同步" | 加入 / 不加入 | — |

**关键设计**：**判错后不立刻给答案**。三级递进（提示 → 位置 → 完整解析）保留"再试一次"的空间，符合"防错、可逆"原则；同时把错题导回工作台做可视化对照——这是本产品相对普通判分系统的真正价值，不能只在文字解析里止步。

### 4.2 输入区（B）

| 状态 | 触发条件 | 界面表现 | 用户可执行动作 |
|---|---|---|---|
| 空 | 未填 | 两个输入框为空，占位提示给出格式示例与长度要求（"32 位十六进制，如 3243f6a8…"）；生成按钮禁用但可 Tab 到达并读出禁用原因 | 输入 / 粘贴 / 载入向量 |

| 已生成（折叠态） | trace 已生成 | B 区整体折叠成一行摘要（"3243f6a8… · AES-128 · 加密"） | 展开 / 重新生成 |
| 粘贴非 hex 文本 | 粘贴了中文/说明文字 | 归一化失败 → 行内提示"这段内容不像十六进制"，提供「把文本转成 hex」的小工具（一键） | 转换 / 手动修 / 取消 |

#### 4.9.1 由此确立：矩阵格四角分配规则（防撞车）

一个 4×4 格上最多可能同时出现 4 个语义标记，必须一次性把角分配掉，否则每加一个状态就要重新排布：

| 角 | 语义 | 形态 | 出现场景 |
|---|---|---|---|
| 左上 | **反向** | 6px `◀`（正向 `▶`） | 反向单步 |
| 右上 | **已变化** | 3px 实心琥珀角标（动效归零后转为**常驻**，不淡出） | 播放 / 单步 / 拖拽落地 |
| 右下 | **错误** | 6px 折角 + `≠` 上标 | 判错定位 |
| 左下 | **已完成 / 已确认** | 5px 缺口（**用压纸色方块压在边界上做出缺口，不是把 `border` 断开一段**——断边要改 `border`，而本项目的纪律是"只改颜色、不改宽度"，两者直接冲突；更实际的是：一旦 `border-color` 被 `downstream` 降级或判分换环色，断边会莫名消失） | 该步已完全理解 |

规则：**同一格最多同时出现 2 个角标**（"反向 + 已变化"是最常见的组合）；四角互不占用；**新增任何角标前必须先申请一个空位，不允许覆盖既有角**。中央区域留给数值本身，任何标记不得进入格心。

#### 4.9.2 否决项的替代方案：整段错怎么表达

| 元素 | 通道 | 依据 |
|---|---|---|
| 真正错的那 1 个字节 | `error`：红折角 + `≠` + 2px 边 | 唯一的错误语义承载点 |
| 其余 15 个受影响字节 | `downstream` 态：**去角标 + 边框降一级（`--line-hairline`，不是空）+ 底色 `--surface-inset` + `--ink-3` 400**；演示态边框**不降**，改由底色 ΔL 0.06 + 字重 400 承担 | 表达"被带偏"，不表达"错"。**边框不能置空**：结构线在格子上，`border:none` 就是塌洞；降一级是"仍在，只是不显眼"（§4.9.6） |
| 矩阵范围 | **四角括（corner brackets），不画完整外框** + 标签「影响范围：16 字节」 | 表达"范围"，不表达"对错"。**不用完整边框**：围起来本身就带"这块有问题"的语气，而角括在设计语言里始终是选区标记（截图框、选框、聚焦区） |
| 判分结果条 | 可用 error 样式 | 结果条说"不对"是准确的；矩阵说"全红"是不准确的 |

由此沉淀为一条设计约束（建议进 PRD / 设计系统）：

> **区域级 / 大面积的视觉通道只能表达范围或程度，不能表达对错。**

同一条约束在错题本的错题分布图、学习记录的卡壳热力区同样适用。

#### 4.9.3 二轮复核：第 5 条（整段错红框）尚未收敛，提交产品裁决

v1.2 复核时发现两方认知不一致：视觉 v1.1 记录为"产品已采纳区域级红虚线框"，而我的判定是否决。**事实依据以 PRD v0.2 F5 原文为准**，其中写明：

> 第三层 **错误传播图**：把因首个错误而受污染的下游字节"**灰化**"而非标红。理由：AES 具有雪崩性，第一步算错则后续全错，满屏红会让学生归因为"我全不会"从而放弃。

判断：**红框与该条冲突**。整块红色区域框正好是"满屏红"的一种实现，且面积更大、强度更高。因此维持否决，理由不变（详见 4.9.2）。

**裁决结论（v1.2 定稿）：只用实线四角括，不画完整外框，也不加虚线。**

| 项 | 定稿 | 为什么排除其他方案 |
|---|---|---|
| 范围表达 | **四角括（实线）+ 标签「影响范围：16 字节」** | 角括是选区语汇，只说明"范围在这里"，不说明"这里好不好" |
| ~~完整 2px 实线外框~~ | 排除 | 完整的边框仍是一个"围起来"的动作，围起来本身就带"这块有问题"的语气——比角括弱，但方向仍错 |
| ~~角括 + 中性虚线~~ | 排除 | **虚线在本系统里已有固定含义"未生效/待定/禁用"**（见 4.9.5），这里复用会让线型失去语义 |
| ~~琥珀色框~~ | 排除 | 琥珀是本产品"已变化"的色，是学生看得最多的颜色；它一旦兼职表达"有问题"，`changed` 的语义就废了 |

**与"活动区四角刻线"的共存规则（v1.2 直接定，不等讨论）**

范围角括与工作台已有的**活动区四角刻线**是同一语言家族（都是四角 L 形），但**会在同一屏共存**：学生练习判错后点「在工作台对照」，工作台矩阵自带活动区刻线，同时叠加判错的「影响范围」角括。两个含义完全不同（这块是活动区 / 这块是被污染范围），靠"28px vs 6px"的尺寸差在投影下不可分。

所以靠**位置分离**，不靠尺寸区分：

| 元素 | 落点 | 尺寸 | 是否带标签 |
|---|---|---|---|
| 活动区刻线 | 矩阵**容器外圈**（贴容器边界，向外） | 6px 小节线 | 否 |
| 范围角括 | **内缩 6px**，落在格边界内侧 | 28px 长臂 / 2px 线宽 | 是，只有它挂「影响范围：16 字节」 |

判据：**两个含义不同的同族符号，不能靠尺寸差区分，必须靠位置或标签区分。** 尺寸差是可压缩的（视口、缩放、投影都会吃掉），位置和标签不会。

**v1.3 附注：这一节原本要处理三方共存，现在是两方。** `selected` 一度也用四角刻线（单格内部、6px 臂），那样同屏会有三种 L 形；v1.3 已改判 `selected` 走 `border-color` + `inset` + `outline`（理由见 §4.9.4 第 2 条：右下那条 6px 刻线臂会与 `error` 的 6px 折角同位置叠死）。所以：**单格级别不再有任何 L 形**，四角刻线只剩容器级一个用例，`error` 折角是单格级别唯一的 L 形。三方变两方之后，本条判据不变、验收不变，但验收范围缩小了一层——只需校"容器刻线 vs 范围角括"这一对，不必再校单格。

**无论选哪个，铁律不变：错误色只能出现在真正错的那 1 个字节上。**

#### 4.9.4 ByteCell 七态叠加：不要问"谁盖谁"，要让"每个属性只有一个 owner"

前端问到七态 class 的叠加顺序。**先纠正问题的提法**：如果叠加结果依赖 class 的书写顺序，说明 CSS 设计有问题——`classList` 的 toggle 顺序不可控（单 rAF 批处理里只会 toggle 变化的那些），靠顺序赢就是靠运气。

正确做法：**按"视觉属性通道"分配 owner，每个通道同一时刻只有一个 owner，于是顺序无关。**

| 通道 | owner 优先级（左高右低） | 说明 |
|---|---|---|
| **底色 fill** | `error` > `selected` > `changed` > `downstream` > `done` > `idle` | 一格底色只能有一个 owner，按此序取第一个命中的。**`key` 不在这条链里**（v1.3 改）：轮密钥加那一步 **16 格全是 `key`**，若 `is-key` 带底色，会把这 16 格的 `changed` 黄底全部盖掉——而"本步变了哪些字节"是学生看得最多的信号。**`key` 只占两条无竞争通道：纹理（45° hatch）+ 左边缘竖条** |
| **边框 border** | **`error` > `selected` > `downstream` > 默认**（只有 4 个取值） | **只改 `border-color`，`border-width` 七态恒定 1px**（改宽度会让内容位移 1px，而矩阵里位移会被读成"数值变了"）；需要更厚用 `box-shadow: inset` 叠加（`inset` 在此只有一个用途：**加厚**，不画结构线）。`downstream` 取 hairline 档降一级（不是空），实现走 `--st-downstream-border` 这一层 token 间接，组件里不写模式分支。**字节格的线属于「区域分隔线」族（`--rule-region-ink`），不是控件边框族（`--line-default`）**——两族常规档恰好同值，所以拿错族在常规态**永远不发作**，只在演示态现形；这类"错在常规态看不见"的 token 混用，验收必须在演示态跑一遍。**`keyed` / `changed` / `done` 都不改线色**，因此本链不枚举它们。**写作教训：枚举长度不等于取值个数**——先前写成 6 段，看着更严谨，实际会让人去查根本不存在的 `keyed` 边色 |
| **角标 corner** | 四角**按位置分流**，不参与优先级：右上 `changed`／右下 `error`／左上 `reverse`／左下 `done` | 同格最多 2 个；超限按 `error > reverse > changed > done` 丢弃最低的（规则见 4.9.1） |
| **文本色** | `downstream` 是**唯一** owner（`--ink-3`）；其余一律 `--ink-1` | 弱化只允许 downstream 用；`error` 必须保持可读，不得一起弱化 |
| **纹理 / 装饰** | 同一格**只允许一种**装饰（斜纹 / 点阵 / 折角） | 演示态纹理全删，改形状 |

**互斥与冲突规则（三条，必须写进实现）**：

1. `error` ⊥ `downstream`：同一格不可能既"错"又"被污染"。同时命中时以 `error` 为准，并 `console.warn` 契约漂移（说明后端 `propagated` 与 `first_diff` 不一致）。
2. `done` ⊥ `changed`：`done` 只在复习视图出现，播放态不出现。同时命中时 `done` 让位。
3. `idle` **永不与其他共存**（它是基态，命中即清空其余全部）。
4. **判分展示期间，`changed` 整体让位**——不是单个通道让位，是 fill 与 corner 都不占。理由：判分要回答的是"哪个错、哪些被带偏"，不是"本步 diff 了哪些字节"。若 `error` 或 `downstream` 存在时还留着右上琥珀角标，一个格子上会叠出"琥珀角标 + 红折角 + `≠`"三重标记，正好是红线 1 要防的过载。

**DOM 元素数量的取值规则**：角标元素数 = **同格最多角标数（2）**，不是四角总数（4）。规则上限 2 决定了 DOM 上限 2，剩余两个角永远不会出现，不必预留节点（16 格 × 2 = 32 个，而非 64 个）。

**唯一允许的常见叠加**：`changed` + `selected`、`changed` + `keyed`（轮密钥加步骤：字节既变化又参与密钥）。**两种叠加里 `key` 都只占纹理与左竖条，不占底色与边框**——"既变化又是密钥输入"必须同时可读，而底色这一格只能归一个 owner：归 `changed`（学生看得最多），`key` 靠无竞争的竖条表达。

**禁止用 `!important` 解决叠加**——它会制造"三态同时生效"这种无法调试的结果，而上面这张表已经不需要它。

#### 4.9.5 线型语汇：虚线只表示"未生效"

裁决"虚线已被 `done` 占用、不能再用"引出了一次全表核对，结论和最初的判断不同，记在这里：

**本规格里"虚线"已经被用了 11 次，而且语义高度一致——全部是"未生效 / 待定 / 禁用"**：空格占位（1px）、计算中格边、输入区空态、禁用按钮（生成/提交/跳转/方向键）、时间轴未生成、判分中锁定框、拖拽浏览中、数据不足的统计块。**不守规矩的其实是 `done`**（已完成用虚线，与上述家族相反）。

因此把语汇钉死，而不是把 `done` 的用法当规则：

| 线型 | 唯一含义 | 允许的用法 |
|---|---|---|
| **1px / 2px 虚线** | **未生效 / 待定 / 禁用** | 空态占位、禁用控件、未生成区、锁定中、预览中 |
| **实线** | 已生效 / 确定 | 正常格边框（结构线）、正常控件、范围角括、已完成 |

**「极淡实线」这一行已从语汇表删除，但理由要说准**：它**从来不是一种线型，只是结构线的一个色阶**（hairline 档 = 结构线色往下调一档，不是另一种线型）。色阶属于颜色系统，不属于线型语汇表，所以它本来就不该在这张表里。另删 `点划线`（`done` 改实线 + 缺口后 0 落点）。

**准入规则**：新增任何线型用法前，先在上面这张表里找它属于哪一行的含义；找不到就说明这个状态需要的不是线型，而是形状、颜色色阶或文本。

两处据此修正：

1. **`done` 去掉虚线框**，改为**实线 + 左下 5px 缺口**（缺口才是它真正的身份通道，视觉已有该设计）。虚线留给"未生效"家族。**缺口的做法是"压纸色方块"，不是断边**——理由见 §4.9.1：断边必须改 `border`，与"宽度恒定、只改颜色"的纪律冲突，且会被 `border-color` 的降级/换色悄悄抹掉。
2. **`downstream` = 边框降一级（不是空）**，安静感由三处共同承担：

| | 常规态 | 演示态 |
|---|---|---|
| 边框 | `--rule-region-ink` → **hairline 档**（降一级，宽度仍 1px） | **不降**，与其他态同色同宽（演示档七态**一律 `--rule-region-ink`**，含 `downstream`） |
| 安静感来源 | 边框降级 + 底色 `--surface-inset` + **`--ink-3` 400** | 底色**加深一档**（ΔL 0.06）+ **字重 400 对 700** |

**演示态为什么"不降"而不是"降更多"**：投影会把降一级抹平成纸色，抹平后那格变成"没有框的方块"；周围都有框，在 6px 间隙里读作"没画完"，不读作"安静"。所以演示态**放弃边框这条通道**，把安静感搬到底色与字重上——不是加通道，是把通道搬到别处。

#### 4.9.6 结构线就在格子上：宽度恒定、只改颜色（本项争议的最终解法）

`downstream` 的边框前后改了四轮。中间曾有一个"把格线交给容器画"的方案，**已作废**，理由是它要治的病不存在：**矩阵是 16 个独立 chip，`--cell-gap: 6px`**，不是连续表格——相邻格的边框隔着 6px 纸，根本不接触，所以"共享边 / 两条 1px 叠成 2px"这个问题从来不存在；而容器底色会在格间填出 6px 实色条带，不是 1px 细线。

**终稿：结构线 = 每格自己的 1px `border`，留在格子上；语义只通过 `border-color` 表达。**

| 项 | 规则 | 理由 |
|---|---|---|
| 结构线归属 | 每格自己的 1px `border`，**任何状态都不得删除**（只能改颜色） | 删掉边框就是塌洞——这个判断从第一版到最后都成立 |
| `border-width` | **七态恒定 1px** | 改宽度会让格子内容位移 1px，而**矩阵里的位移会被读成"数值变了"** |
| 语义表达 | 只改 `border-color`（`--rule-region-ink` ↔ hairline 档 ↔ 状态色） | 颜色变化不改变盒模型，不会引起位移 |
| 需要更厚时 | `box-shadow: inset` 叠加，**不动盒模型** | `selected` 2px / `error` 3px 这类厚度需求走 inset，不碰 `border-width` |
| `downstream` | **降一级，不是空**（见 §4.9.5 第 2 条） | 「空」会被下一个读者实现成 `border: none`，那就是塌洞；「降一级」不会 |

**机制不锁死，结果锁死（v1.3 补充，fe v1.9 出现两种写法）**：本节写的是 `border`，因为它是参考实现、最不容易出错；但 fe 文档里另有一处把 1px 线写成 `inset box-shadow: 0 0 0 1px`。**两者都允许，只要三条不变量成立**：① 一格一个 owner；② 宽度恒定；③ 任何状态不得删除。选了 `inset box-shadow` 就必须把 `data-bd` 接到自定义属性上（`--bd-color` → `box-shadow: inset 0 0 0 1px var(--bd-color)`），否则 `data-bd` 继续消费 `border-color` 会**改不动线**——这是静默失效，最难查。**两种机制不得同时启用**（两条线叠起来就是 2px，正好破坏第 ② 条）。

**演示态的层级不靠明度（v1.3 补，视觉与 team-lead 终裁）**：演示档字节格边框**七态同色**（`--rule-region-ink`），于是"格子线与区域分隔线同色同宽"，会有人追问层级在哪。答案：**层级靠留白（区域 16px vs 格间 6/10px）+ 标签 + 位置，不靠更淡**——**"靠更淡来分层级"在投影上等于"没有层级"**，因为投影先把浅色抹平。这与 `downstream` 演示不降、`done` 演示抬到同色是**同一条道理的三次应用**，不是三个特例。

**这解掉了两条同时成立的判断**：我主张"必须保留边框"（结构靠格线承载，删了就塌洞）与视觉主张"框线会把该安静的状态抬成有标记的东西"——两条都对，解法不是争论"该多淡"，而是**把宽度锁死、只让颜色承担语义**。宽度恒定之后，"降级"是一个颜色动作，不会牵动结构。

**三条配套规则**：

1. **状态线一律 `box-shadow: inset`，不用 `border`**。理由：`border` 参与盒模型会改变格子内尺寸，4 种状态各写一套 `border` 会让 16 格出现亚像素级尺寸抖动；`inset` 不占位，且可以和结构线共存于同一条边。
2. **`error` 与 `selected` 同时命中时，两个都要表达**——这是唯一需要"组合态"的情形。做法：**`error` 占底色与右下折角，`selected` 占边框色（`--accent`）+ `inset` 1px 内环 + 外描边 `outline`**，**不允许一方静默吃掉另一方**。理由：判错后学生点开那个错字节看明细，此时"我选中的正是这个错字节"是最重要的定位信息，被吞掉会让人以为没点上。
   - **为什么 `selected` 不用四角刻线（v1.3 改，原写法是个真 bug）**：`error` 的标识是**右下 6px 折角**，而四角刻线里正好有**右下那一条 6px 臂**——两者同位置、同尺寸、不同语义，组合态下会直接叠死，看起来像一条画歪的线。这不是"稍微挤一点"，是**同一个像素位置被两个语义争用**。
   - 更深一层：**四角是角标通道**（左上 reverse / 右上 changed / 右下 error / 左下 done，见 §4.9.1），而该通道的规则是"每格最多 2 个、不得覆盖既有角"。再加一套四角刻线等于给同一通道塞进第二个 owner，直接违反 §4.9.4 的"一个通道一个 owner"。
   - 改用 `border-color` + `inset` + `outline` 后，三者全部落在**边缘通道**，与角标通道正交，组合态下互不遮挡。
   - **不能只是去掉刻线就完事：`selected` 的第二通道要有人接。** 光改 `border-color` 是纯颜色信号，违反 §4.8 的每一态都有非颜色第二通道。接它的是**外环（`outline`）**——环是**形状/厚度**通道，色盲、灰度、投影下都读得出这一格被框住了。因此对 `outline` 追加两条：① 必须是**环**（离格边 2px 的空隙），不能退化成加粗边框——加粗只是量变，环是另一种形状；② 环色允许用 accent，但**判分叠加时环色改为近黑**（`--ink-1`），因为红底 + accent 环在红色盲下会并成一团，近黑环才稳。**这条撤除不是永久禁令，但恢复要同时满足两个条件（视觉补的判据，我采纳）**：① **看得见**——有 1080p 投影 + 3m 距离的实测支撑；② **不撞角位**——`error` 的折角必须同时挪到别的角位，否则右下角还是"同位置、同尺寸、两个语义"。**只满足①就恢复，等于把 r4 那个补丁装回去**：补丁治的是"叠死"，而叠死的根因是角位冲突，不是可见性。
3. **判分叠加绑定 `step_index`，离开该步即撤**。`errorSet` / `downstreamSet` 是为某一步算出来的；学生一旦单步或跳转到别的步，这些下标就失去意义，必须整体撤场。这条同时消除了"判分叠加 + 反向单步"的不可能组合，因此 `reverse` 角标不需要单独做判分门控。

### 5.2 读屏：矩阵这种纯视觉内容的替代方案（本产品最真实的难题）

**先承认难点**：16 个十六进制字节的二维矩阵，逐步变化 24 次，还带 diff 高亮。逐格朗读 16 个数字是灾难（"0x32…0x43…" 听 24 遍没人能理解）；给一句"一个 4×4 矩阵"是无信息量的无效 alt。**这两条路都是错的**。

**方案：以"变化摘要句"为主通道，以"可导航表格"为深挖通道，两者都要有。**

| 编号 | 做法 | 说明 |
|---|---|---|
| A1 | 主通道：每一步一句摘要，放入 `aria-live="polite"` 区域 | 例："第 1 轮 字节替代。16 个字节中 4 个变化，下标 0、5、10、15。字节 0 由 0x9A 变为 0xB8。停在 13 步，共 24 步。" 读屏用户主要靠这句话理解，**这句话本身就是产品文案**，要写进文案规范 |
| A2 | 语义结构：矩阵用 `role="grid"`，4 行 4 列，格用 `role="gridcell"` | 每格 `aria-label` 只放"该格此刻最小必要信息"：`第 2 行第 2 列，字节 5，值 0xB8，十进制 184，本步已变化，原值 0x53` |
| A3 | 深挖通道：提供「表格视图」切换 | 把矩阵渲成真正的 `<table>`（行=行号、列=列号、单元格=hex + 十进制），读屏用户可以用表格导航命令逐格读。**grid + table 双形态比单一 grid 更可靠**，因为不同读屏器对 grid 的支持差异大 |
| A4 | 数值双写 | 所有字节都给 hex 与十进制两个值（教材里两种写法都有，读屏用户常需要十进制来心算） |
| A5 | 播放中的播报节流 | 自动播放时**不逐步播报**（会刷屏且听不清），只在暂停/停止时播报当前步摘要；提供开关「单步时每步播报」（默认开，自动播放时自动降频） |
| A6 | 变化的文本等价物 | C2 的摘要句里用文本列出变化字节的下标与"旧值→新值"，保证视觉高亮的全部信息都有文字版本 |
| A7 | 流式回答不逐字播报 | 流式期间 live region 设为 off，只播报一次"正在回答"；生成结束把整段放入 live region，或提供「朗读回答」按钮。**逐字播报是读屏用户最痛的点，必须避免** |
| A8 | 禁止无效 alt | 明确禁止"一个 4×4 状态矩阵""AES 加密过程图"这类无信息量描述 |
| A9 | 快捷键帮助 | `?` 打开的帮助浮层要包含"字节下标从 0 开始""列优先"这类约定——读屏用户无法从视觉上推断这些约定 |

### 5.3 对比度（投屏场景的最低要求）

| 项 | 要求 | 理由 |
|---|---|---|
| 正文与背景 | ≥ **7:1** | 投影仪对比度衰减严重、教室环境光强，WCAG AA 的 4.5:1 按显示器算，投影下经常不可读 |
| 大字号 / 图形 / 图标 | ≥ **4.5:1** | 同上 |
| 高亮的非文本区分 | 高亮必须有 ≥3:1 的**边界**对比 | 投影下浅色填充会整片消失，只剩"这块有点不一样" |
| 细线 | 结构分隔不得依赖 1px 线；用 ≥2px 或间距承载 | 投影下 1px 线直接消失 |
| 半透明 | 演示模式禁用半透明叠加 | 投影 gamma 使半透明图层糊成一片 |
| 演示模式 | 需独立一套参数（更高对比、更大字号、去纹理、去阴影） | 见 UX-V2；具体数值由视觉定，我只提需求 |
| 焦点环 | 演示模式下必须明显可见 | 教师用键盘时全班要看得到 |

### 5.4 色盲友好：高亮不能只靠颜色

| 语义 | 只能靠颜色会怎样 | 必须叠加的第二通道 |
|---|---|---|
| 变化字节（diff 高亮） | 红绿/黄蓝在投影与色盲下都不可辨 | ① 加粗边框 ② 角标（如左上小三角或 ↑ 标记）③ 文本摘要句列出下标 ④ 一次性描边动画（reduced-motion 时改为静态角标） |
| 正确 / 错误 | 红绿是经典陷阱 | 图标（✓ / ✗）+ 文案（"正确"/"第 2 步出现差异"）。**不要用线型区分**——线型在本系统里有专义（见 4.9.5），拿它兼职表达对错会和"未生效"语汇撞车 |
| 时间轴按轮分段 | 8–14 种色相完全不可辨 | 段间分隔线 + 轮号文本 + 交替明暗两值；**颜色只做辅助，不做唯一区分** |
| 诊断标记 vs 提问标记 | 两色圆点易混 | 形状区分：圆点 = 诊断，方块 = 提问；叠加时并排显示 |
| AI 回答的"引用数值" | 单靠底纹色 | 下划线 + 可点击外观 + 一个"引用本步数值"的文本标签 |
| 焦点 / 选中 / 悬停 | 三态常撞车 | 三个不同通道：焦点=外圈描边，选中=内边框+角标，悬停=背景变化（不叠加边框） |

### 5.5 动效偏好（`prefers-reduced-motion`）

| 动效 | 常规 | reduced-motion 下 |
|---|---|---|
| 矩阵逐步过渡 | 变化字节做过场 | **瞬时切换到终态**，变化字节保留一个静态标记（角标 + 描边），并保证摘要句文本完整 |
| 播放节奏 | 由动画时长决定 | **不依赖动画**：步进间隔由固定节奏驱动（动画归零不影响播放可用性） |
| 抽屉 / 浮层 | 滑出 | 直接出现 |
| 流式光标 | 闪烁 | 不闪烁（或用静态标记） |
| 无限循环动画 | 播放指示器脉冲等 | 全部禁止 |
| diff 强调 | 描边/位移 | 只保留静态颜色与角标，无位移、无缩放 |

**额外要求**：除系统偏好外，页内提供一个明显的「减少动效」开关（默认跟随系统）。理由：教室电脑是公用的、系统偏好常被锁死，学生也无法改教师机设置。

### 6.a 诊断规则：`连续回退 3 次 或 单点停留 >8s` → 判定误解

**判断：部分成立。** 方向（用行为信号推断认知状态）是本产品的核心价值，必须保留；但阈值与打扰策略会直接毁掉它。

**理由（三条，按严重程度排）**：

1. **"停留 >8s"根本不是卡住的证据。** 学生的正常行为里，8 秒的停留大量存在：在草稿纸上抄这一屏的 16 个字节、截图做笔记（截图时页面静止）、读右侧 AI 的回答（读 200 字中文需要 20 秒以上）、接个电话、看另一块屏幕上的教材。**8 秒在"读一段解释"这件事上甚至偏短**。PRD 同时又规定 AI 回答流式输出——一边流式回答一边 8 秒判你卡住，两件事直接打架。
2. **"连续回退 3 次"的定义含糊。** 回退一次是退 1 步还是退 1 轮？"连续"的时间窗是多久？学生为了对照"列混合前后"来回切 3 次是完全正常的学习动作——**对照阅读就是反复回退**，这恰恰是会学习的学生才有的行为。这条规则会优先误判最认真的那批人。
3. **误判的成本 >> 漏判的成本。** 漏判只是少了一次主动关怀；误判的代价是学生认定"这东西在瞎猜"，之后所有主动提示（包括正确的）都被无视——而 D1（诊断 + 主动反问）是 PRD 自己写的最强差异化，一旦信任崩塌，差异化归零。PRD 的 RK-5 也承认了这一点，但给出的应对（"否定后 10 分钟内不再提示"）太轻：10 分钟后同一个错误提示还会再来一次。

**修正建议（可直接写回 PRD）**：

> **F4 认知诊断规则（修订）**
>
> 1. **采用多信号加权，不用单阈值。** 四个信号，各自权重不同，需至少两个信号同时满足才输出"低置信诊断"，三个满足输出"高置信诊断"：
>    - S1 同一 step_index 的**有效停留时长**：页面可见（Page Visibility）且无滚动、无文本选择、无键盘/鼠标输入、无 AI 流式输出中。**排除条件必须写明**，否则"读 AI 回答"会被计入停留。
>    - S2 **回退-前进往返**：在同一个 1–2 步的窗口内往返 ≥3 次，且窗口内单次停留均 <3s（快进快出的反复切换才像困惑；慢速往返像对照阅读）。
>    - S3 **同一字节格重复点击** ≥4 次（且之间没有打开过其它字节）。
>    - S4 **提问未完成**：在 AI 输入框输入 ≥8 字后全部删除且未发送，重复 ≥2 次。
> 2. **停留阈值自适应，不用固定 8s。** 基线 = 该步动画时长 + 该步摘要句的阅读时间（按中文 6 字/秒估算），取下限 15s。即：`阈值 = max(15s, 动画时长 + 摘要字数/6 × 1000ms)`，且只在"用户主动停在某步"后开始计时（自动播放中完全不计时）。
> 3. **打扰分两级，第一级不算打扰。**
>    - 一级（静默）：时间轴该步出现圆点 + AI 栏顶部一行浅色文字「这一步你停留较久，需要提示吗？」，**不弹窗、不动焦点、不遮挡、不打断播放**。30s 无响应自动收起，圆点保留。
>    - 二级（反问）：仅在用户**点击**那条提示，或同一误解类型在会话内第 2 次命中时才出现。一次会话最多 3 次，同一误解类型最多 1 次。
> 4. **否定的处理加强。** 「不是」→ 该误解类型**本会话永久不再提示**；若同一类型在 7 天内被否定 ≥2 次，该规则对该用户降权（24h → 长期冷却）。提示条上常驻一个「这提示不对」入口，用于收集规则误判样本（这同时是诊断准确率指标的采集渠道）。
> 5. **提供演示与测试入口。** 教师演示与验收时不能靠"等 8 秒"，需要一个可复现触发诊断的隐藏入口（如 `?debug=diagnosis`），否则 D1 在答辩现场无法稳定演示。
> 6. **明确不计时的场景**：自动播放中、页面隐藏（切 tab）、练习页、单步训练页、抽屉打开中、AI 流式中。

### 6.b AI 栏"默认不空着，跟着当前步自动切上下文"

**判断：部分成立。** "降低提问门槛"的意图完全正确——空白的对话栏确实会让人不知道怎么开口。但"跟着当前步自动切上下文"如果实现为**每切一步就重写栏内内容**，会带来三个问题。

**理由**：

1. **视觉噪音。** 用户拖时间轴从第 3 步到第 20 步，如果每经过一步 AI 栏都改写一次，右侧会出现一条快速滚动的文字流。这比空白更糟——空白至少是安静的。
2. **误触与丢失。** 学生可能正在读第 5 步的回答，手指在时间轴上滑了一下，回答被替换，且没有明显的"回退到上一条"路径。**内容被系统主动替换，是这个界面里最不可接受的一种丢失**。
3. **成本与延迟。** 如果"自动切上下文"意味着自动发起生成请求，拖一次时间轴就是十几次模型调用；如果不自动生成而只是更新标题，那它本来也不该叫"切上下文"。PRD 第 7 节的 API 预算按 1200 次估算，这个交互一旦上线会直接击穿预算。
4. **但完全空白也不行**：用户不知道该问什么，尤其大三学生面对"我该问什么"时最容易放弃。

**修正建议（可直接写回 PRD）**：

> **F3 步骤级 AI 辅导（修订）：预取不预显**
>
> 1. **切步只更新"上下文头"，不重写正文。** 上下文头一行：「当前：第 2 轮 列混合 · 16 字节中 4 个变化」。这一行是本地渲染，零延迟、零成本。
> 2. **预设问题 chip 是本地静态文本，随 op 类型切换**（4 种 op × 3 个 chip = 12 条预写文案，不调模型）。这是"降低提问门槛"的真正承担者。
> 3. **正文永不自动生成。** 只在用户点 chip 或输入后请求。**旧回答折叠为一行**（「第 2 轮 行移位 · 你的提问」）可展开，不删除。
> 4. **跟随开关**（默认开）：开启时上下文头随步更新；关闭后栏内锁定在某步，栏头显示「已锁定：第 5 步」+「回到当前步」。
> 5. **频繁切换防抖**：时间轴拖拽 / 连续单步期间，上下文头的更新节流（如 200ms），不逐帧刷新文字。
> 6. **缓存命中不伪装流式**：本地缓存或模板返回时**整段直接呈现**并标注来源，不做假打字机效果（假流式会让用户以为在花 token，一旦发现是本地文案会觉得被欺骗）。
> 7. 若产品确实想"预生成"，只允许对 top 5 高频 chip 做**本地模板预生成**（零成本、零延迟），不做模型预生成。

### 6.c 时间轴拖拽 vs 单步执行

**判断：成立。** 这是真实的双模式冲突，PRD 目前完全没有处理。

**理由**：两种操作在用户心里是**两种不同的心智模型**：
- 单步 = 「执行」（transition）：让算法往前走一步，我想看"变的过程"。
- 拖拽 = 「跳转」（state jump）：我不关心过程，我直接要看第 18 步长什么样。

问题在两处：① 如果两者视觉与动效完全一样，学生会以为"拖到第 18 步"就是"走了 18 步"，进而在练习里误以为算法是按他拖的速度跑的；② 如果拖拽也播放 diff 动画，学生会分不清"这是我拖过去的"还是"算法刚刚变了这几个字节"。**diff 高亮的语义是"这一步改了什么"，它只能归属于"执行"，不能归属于"跳转"。**

**修正建议（可直接写回 PRD）**：

> **F2 步进控制（修订）：术语与动效双重分离**
>
> 1. **术语分离**：按钮文案为「上一步 / 下一步 / 播放」；时间轴为「跳到第 n 步」。禁用"拖动进度"这类播放器语言，**不借用视频播放器的隐喻**——这是算法执行，不是视频进度。
> 2. **动效归属分离**：只有「播放 / 下一步 / 上一步」触发 diff 过场动画与变化摘要句的更新；**拖拽跳转只静默更新矩阵，不做 diff 过场**，摘要句改为「第 18 步的快照（未执行过渡）」。
> 3. **拖拽态可见**：拖拽期间矩阵上方常驻「浏览中（未播放）」标记，松手后消失。这解决"我刚才到底播了没有"。
> 4. **边播边拖 → 自动暂停**：用户开始拖拽或点矩阵格时，自动暂停播放（不能让两个控制源争夺同一状态）。
> 5. **键盘语义对齐**：`← →` = 执行（单步），`Shift+← →` / `PageUp/PageDown` = 跳转（整轮），`J` = 精确跳转。键盘与鼠标共享同一套语义映射。
> 6. **边界不循环**：末步再"下一步"→ 提示「已是最后一步」+「回到开头重看」，不静默回绕。

### 6.d 判分"定位到第几轮第几步哪个字节"

**判断：部分成立。** 定位这件事本身是 D3 差异化的核心，不能砍；但在"整段错"的情况下，当前设计的信息量趋近于零，甚至有害。

**理由**：
1. **首步错则全错。** 如果学生在第 1 轮字节替代的第一步就错了，后面 23 步全部与标准答案不同。此时"首次差异 = 第 1 步字节 0"是完全正确的，但学生看到的是**满屏 16 个字节全红**——他会理解成"我全错了，我根本不会"，而事实是"你只错了一处，后面只是被它带偏了"。这是**归因错误**，比不给定位更伤害学习动机。
2. **定位无层次。** 现在只有一个答案："第 x 轮第 y 步第 z 字节"。但错题的教学价值分层明显：有的是抄错输入（根本不是算法错）、有的是某一类操作系统性错（值得补练）、有的是最后一步手滑（几乎会了）。三者给同一句话是浪费。
3. **有定位没对照。** 学生看到"第 2 轮列混合第 3 字节错"，然后呢？他还得自己去可视化里找那一幕——而工作台明明就在旁边。

**修正建议（可直接写回 PRD）**：

> **F5 练习判分（修订）：三层反馈 + 错误传播图**
>
> 1. **第一层（默认显示）：一句方向，不给位置。** 「结果不对。差异出现在第 2 轮的操作里。」难度越高的题给的方向越模糊（简单题可直接给层 2）。
> 2. **第二层（点「看差异位置」后显示）：首次差异点。** 「第一次不一样：第 2 轮 列混合，字节 3。你的值 0x7C，正确值 0x63。」矩阵上只高亮这一个字节。
> 3. **第三层（点「看完整解析」后显示）：错误传播图。** 把首次错误步之后的字节按"是否受首错影响"分两类：受影响的下游字节**灰化并标注"受第 3 字节影响"**，只有真正独立的错误才另起标红。文案强调「你只错了 1 处，其余 15 个字节是被它带偏的」。
> 4. **单独一类：输入不一致。** 若学生录入的明文/密钥与题目期望不同，**不计为算法错误**，单独提示并允许改输入重判。这道题在统计里要从"错误"里剔出去（否则学习记录的正确率会被抄错污染）。
> 5. **必须给「在工作台对照」出口**：一键带该题数据集 + 首次差异步打开 PG-2，并在 AI 栏自动带上"我这一步算的是 0x7C，答案是 0x63，为什么"。**这是本产品相对普通判分系统的唯一真正优势，不做这一步等于放弃 D3 的价值。**
> 6. **判错不立刻给答案**：三级递进保留"再试一次"的空间；「再试一次」后重新提交，记录为同题第 2 次尝试，错因分析只用首次尝试。
> 7. **错因标签需样本门槛**：同一错因类型累计 ≥2 次才给结论标签，1 次时只说「疑似」，0 次不给。

### 6.e 首页三种模式入口（看 / 练 / 问）

**判断：成立（"问"不该作为并列模式），但需要给一个入口，只是入口指向要改。**

**理由**：
1. **"问"脱离上下文即失去意义。** 本产品对通用 AI 的唯一优势是"我知道你在第几轮第几步、屏幕上是什么数"（PRD 的 D2，也是最强的护城河）。一个独立的"问"入口意味着**用户在这里提问时没有快照**，回答与 ChatGPT 无差别——我们自己把护城河填了。
2. **认知上也不成立。** "看"和"练"是任务（我要做什么），"问"是手段（我遇到问题时怎么做）。把手段与任务并列放在同一行，用户会困惑"我是来问问题的吗？我感觉我是来看懂 AES 的"。
3. **但完全不给入口会赶走一部分人。** 有一类用户的起点确实是"我有个问题"（考前复习时带着具体疑问来的）。不给他们入口，他们会在首页愣住。

**修正建议（可直接写回 PRD）**：

> **PG-1 首页（修订）：两个主模式 + 一个带上下文的提问入口**
>
> 1. 首页主视觉给**两个**大入口卡：「看：一步步看懂 AES 怎么算」/「练：算一遍，看错在哪」。
> 2. 第三个入口**降级并改写**（不是"问"，而是"我有具体问题"）：
>    文案「我有具体问题 →」副标题「先载入一组数据，AI 会带着你屏幕上的数值回答」。
>    **点击行为**：进入 PG-2（若已有数据集则恢复上次步），并**把焦点直接放进 AI 输入框**（`A` 键的等效动作），AI 栏顶部展开一组"概念型问题"示例 chip（如"列混合为什么能扩散""为什么第一轮不加列混合"）。
> 3. 即：**"问"不再是模式，而是工作台里的一个能力，首页只负责把用户带到这个能力的入口前，且必须带着上下文。**
> 4. 首页下方常驻一行「什么都不想选？载入 FIPS-197 标准向量，看一眼再说」——这是给最没有方向感的用户的安全网。

### 6.f PG-4 密钥扩展 44 个字：独立页还是工作台内展开

**判断：部分成立。** 独立页面确实割裂；但整体塞进工作台会把已经极度密集的一屏彻底压垮。正确答案是"同一个组件的两种尺寸"，而不是"两个页面"或"一个页面"。

**理由**：
1. **密钥扩展的因果链天然依附于"当前轮"。** 学生真正的问题不是"44 个字分别是什么"，而是"**这一轮用的这 4 个字是怎么算出来的**"。脱离第 N 轮的 44 字长列表，是一张需要自己找位置的图——这正是 PRD 自己批评的"静态图"。
2. **但 L8 验收要求演示 44 字全量。** 教师投屏时也需要一张"完整图"。所以不能只做抽屉。
3. 关键判断：**这两个需求是同一个数据、同一个组件、两种视口尺寸**，不是两个页面。做成两个页面就要维护两套交互、两套状态同步，还会产生"我在抽屉里点了第 20 字，工作台没跟着跳"的 bug。

**修正建议（可直接写回 PRD）**：

> **PG-4 密钥扩展（修订）：单组件双层**
>
> 1. **工作台内常显「密钥轨」**：横向条带，只显示当前轮用到的 4 个字（w[4r..4r+3]），带"← 来自"箭头指向上一轮对应字。这是 L0 层，因为它与当前步强相关。
> 2. **点密钥轨 → 抽屉展开为 44/52/60 字条带**（覆盖 AI 栏，不覆盖矩阵），当前轮高亮，点任一字可展开 RotWord→SubWord→Rcon→异或的分步。这是 L2 层。
> 3. **抽屉内提供「全屏查看」**，全屏态即 PG-4 的独立路由（`/workspace/key-expansion?key=...&round=2`），供教师投屏与深链接使用。**全屏态与抽屉态是同一个组件的不同容器，共享同一份状态**。
> 4. **双向联动**：抽屉/全屏里点某个字 → 工作台 step_index 跳到对应轮的轮密钥加步；工作台换轮 → 抽屉内高亮跟随（若抽屉开着）。
> 5. **URL 可表达**：`panel=keyexp` 记入 query，刷新与分享不丢。
> 6. 判据写进设计原则：**「我在看这一步」→ 工作台；「我在研究密钥扩展机制」→ 抽屉全屏。同一组件的两种用法，不是两个功能。**

### 6.g 投屏模式：教师看学生的轨迹还有意义吗？PG-11 与投屏是不是一回事

**判断：部分成立——PRD 把三件不同的事混成了两件。**

**理由**：现在 PRD 里并存两个概念：① "教师投屏演示"（Q2 里教师的核心目标）；② "教师端学情看板 PG-11"（全班热力图）。这两件事的数据来源、使用者、时序完全不同：
- **投屏演示**是**课堂上的实时行为**，操作者是教师一人，目的是"让全班看清楚"，不需要任何学生数据。
- **学情看板**是**课后的分析行为**，操作者是教师，数据来自全班学生，与投屏无关。
- 还有第三件被忽略的：**演示时教师自己的操作轨迹该不该记录？** PRD 没有规定，而这是一个会直接毁掉 PG-11 的数据质量问题。

**具体风险**：教师课堂投屏演示时，会在"列混合"那一步反复回退 20 次（因为有学生说没看清），并且长时间停留在那一步（讲解 3 分钟）。如果这段轨迹被当作学生的学习轨迹上报，PG-11 的热力图会显示"全班在列混合集体卡壳"——**这是一个由一个人制造的集体假象**，而这恰恰是 PG-11 唯一要回答的问题。

**修正建议（可直接写回 PRD）**：

> **拆成三件事，分别定义**
>
> 1. **演示模式（Presentation Mode）= 视图状态，不是权限，不是页面。** 任何登录或匿名用户都能进；内容是：加大字号、提高对比、隐藏输入区的次要控件、隐藏诊断提示、顶栏收起、提供一个「演示脚本」下拉（"走到第 2 轮列混合并停住""走到最后一轮"等预设跳转）。快捷键 `P` 切换。**它没有独立 URL 页面，是工作台的一个 state**（`?present=1`）。
> 2. **教师端学情 PG-11 = 独立页面 + 独立数据模型**（班级关系、学生账号、聚合统计），P2，可砍。它的数据只能来自学生账号的普通会话。
> 3. **埋点模式独立于视图**：`session.mode ∈ {study, demo, quiz, single_step}`。
>    - `demo` 模式的会话**一律不写入学情统计**（可写入个人历史，但排除出班级聚合）。
>    - 判断依据不能用"是否教师账号"（教师也可能自己学，学生也会投屏做汇报），而是**由用户显式开启演示模式时设置**。
>    - 若无法可靠区分，退化为：**PG-11 的聚合只统计 `quiz` 与 `study` 模式的会话，且要求该会话至少有 1 次练习提交**——用"做过题"作为"这是学生本人"的低成本代理指标。
> 4. **投屏时学生的轨迹**：不存在"投屏时产生学生轨迹"这回事——投屏是单向展示。真正的问题是"**投屏结束后**，学生回到自己电脑上是否需要重新走一遍"。答案是不需要：工作台状态全在 URL 里，教师可以把带参数的链接发到班级群，学生点开就是同一屏同一步。**这是投屏模式真正该有的产出物：一个可分享的深链接，而不是"学生的轨迹"。**

### 6.h 匿名会话 + 登录后合并学习记录

**判断：成立，而且 PRD 的处理时点太晚，是最容易导致流失的一处。**

**理由**：
1. **PRD 现在的触发时点是"用户点加入错题本时才提示登录"（第 5.3 节异常表）。** 这意味着用户已经投入了 20 分钟做题、判错、看解析，最后一步才被告知"你得登录"——这是最经典的"价值已交付、门槛后置"式流失：用户会想"那我刚才白练了"，然后关页面。
2. **"白练"的恐惧即使不成立也会发生。** 即便技术上合并成功，只要用户**在登录前无法预期"我的记录会不会丢"**，他就会在登录页放弃（多一个账号成本 > 已有沉没成本）。
3. **PRD 说"允许先练，登录后合并本地记录"，但没有定义合并规则。** 冲突怎么办？重复的题算几次？跨设备怎么办？这些不定义，前端就无法实现，最后往往变成"登录后记录清空"——最坏结果。

**修正建议（可直接写回 PRD）**：

> **F6 用户与学习记录（修订）：匿名不降级 + 提前告知 + 可预期合并**
>
> 1. **匿名态提供"本机记录"**：错题本、练习历史、学习记录页在未登录时**全部可用**，数据存 localStorage + 服务端 `sessions.user_id = NULL`。**"白练"在功能上永远不成立**，因为匿名也有记录，只是不同步。
> 2. **提示提前，且用常驻轻声而非弹窗**：进入练习或工作台时，界面角落常驻一行「游客模式 · 记录保存在本机」，**在第一次产生记录后立即出现**（不是等到要存错题时）。这是一句状态说明，不是营销。
> 3. **合并规则显式定义**：
>    - 登录时自动扫描本机 `session_id` 列表，调用合并接口把 `sessions.user_id` 回填；
>    - 练习题按 `item_id` 去重，保留**首次尝试**为错因分析依据，其余作为"重做记录"追加（`attempts` 表已有 `item_id`，天然可去重）；
>    - 合并后必须给出可核实的结果：「已合并本机 3 次练习、12 条学习轨迹、4 道错题」，而不是只说"已同步"；
>    - 合并**只增不删**，任何情况下不覆盖服务端已有数据；
>    - 跨设备不合并本机数据（另一台机器的 localStorage 拿不到），但服务端匿名会话若带同一 `device_id` 可合并，需在隐私说明里写清。
> 4. **给用户一次"先看价值再登录"的机会**：学习记录页在未登录时正常展示本机数据，顶部一条「本机数据（未同步）+ 登录后可跨设备」。
> 5. **退出登录不删本机数据**，只停止同步。

### 6.i（新发现）「8 秒内流式返回」与「超时 8s 降级」互相打架

**判断：成立。** PRD 的 US-1 验收标准写"8 秒内流式返回"，第 6.4 节写"8s 超时 → 本地预写模板"。这两个 8s 会在同一个时间点上冲突：模型在 7.9 秒吐出第一个字，界面刚渲染出半个词，超时判定同时触发 → 回答被模板替换。用户看到的是"字出来了又消失"，比直接降级更糟。

**修正建议（可直接写回 PRD）**：

> **F3 超时策略（修订）：双阈值**
>
> - **首字超时 3s**：3s 未收到首字 → 显示「正在组织讲解…」+「先看本地要点」兜底按钮（不强制替换，用户可继续等）。
> - **总超时 20s**：超过则替换为本地模板并标注「离线讲解」。
> - **判定以"已收到首字"为界**：一旦收到首字，不再触发超时降级，只提供用户主动「停止生成」。
> - US-1 的验收标准改写为"首字 ≤3s，完整回答 ≤20s"。

### 6.j（新发现）诊断的"不给答案只给提示"与 AI 辅导同用一栏，会产生敷衍感

**判断：成立。** PRD 第 6.4 节提示词约束写"不给答案只给提示（诊断场景）"。但诊断提示与 AI 辅导共用右侧同一栏、同一个输入框。学生从诊断提示点「是，讲讲」进入后，如果 AI 继续"只给提示"，他会遇到 AI 产品最招恨的行为——追问两三次都被"你想想看"打回。

**修正建议（可直接写回 PRD）**：

> **F3/F4 意图区分（修订）**
>
> - 请求携带显式 `intent ∈ {explain, hint, diagnose_followup}`。
> - `intent=hint`（仅从练习的"看提示"进入）：只给提示，不给答案，且回答末尾必须有「给我完整解释」按钮。
> - `intent=explain`（从工作台提问、或诊断提示点「是，讲讲」进入）：**必须讲清楚**，允许给结论。
> - 任何 `hint` 回答被用户点"给我完整解释"后，升级为 `explain`，且本次不计入提示次数消耗。

### 6.k（新发现）全量 trace 一次返回 —— 设计合理，但 UI 语义要说清

**判断：不成立（PRD 的设计是对的），但需要补 UI 措辞。** 一次性返回全量快照是正确决策（可任意跳转、无需重算、AI 上下文天然可序列化）。风险在措辞：如果界面上的"播放"看起来像"正在计算加密"，学生可能形成"拖时间轴也是在算"的错误模型，反而理解不了"算法其实已经算完了"这件事。

**修正建议**：

> 文案与提示上明确"算完再回放"：生成成功后 C2 显示「已算完全部 24 步。可以播放，也可以直接跳到任意一步」。这句话本身就是一次教学——**加密是一次性算完的，播放只是回看**。

### 6.l（新发现）匿名可无限调用 AI 接口

**判断：成立。** 成本与滥用风险（PRD 预算按 1200 次估，一个脚本就能打穿）。

**修正建议**：见 4.6.1，匿名配额（每会话 10 问 / 每日 20 问），配额用尽时明确告知并给"登录可提升"的正向动机，而不是单纯的拦截。

## 7. UX 文案规范

### 7.1 语气定义

**像助教，不像客服；像同事指着你的屏幕说，不像老师在考你。**

四条可执行规则：
1. **先说我看到什么，再说建议。** 每条反馈都要引用真实数值或真实状态，不说"你错了"，说"第 2 轮列混合，字节 3 你算的是 0x7C，正确是 0x63"。
2. **不用感叹号和语气词。** 不用"太棒了""亲""哦~""呢"，也不堆 emoji。技术工具的热情体现在"答得准"，不体现在"说得甜"。
3. **错误不指责，只描述差异。** "你的输入与题目不一致"而不是"你输入错了"；"这一步还需要再看一下"而不是"又错了"。
4. **不确定就说不确定。** "这一步我不能确定"是允许的文案；编一个看似合理的解释是最严重的文案事故。

### 7.2 空状态

| 位置 | 文案 | 说明 |
|---|---|---|
| 首页副标题 | 「AES 的每一步都能停下来提问。它知道你屏幕上是什么数。」 | 一句话说清两个差异：可停 + 带数值 |
| 首页安全网 | 「什么都不想选？载入 FIPS-197 标准向量，看一眼再说。」 | 给最没有方向感的用户一条零决策路径 |
| 首页第三入口 | 「我有具体问题 →」/「先载入一组数据，AI 会带着你屏幕上的数值回答」 | 把"问"导回上下文，见 6.e |
| 工作台·未生成 | 「还没算。填入明文和密钥，或载入标准向量。」 | 不写"暂无数据"这种系统语言 |
| 工作台·已生成未播放 | 「已算完全部 24 步。按空格播放，或点任意一个字节看它现在是什么。」 | 顺便教一次"算完才回放"的概念（6.k） |
| 输入区·空 | 占位符：「32 位十六进制，例如 3243f6a8885a308d313198a2e0370734」 | 给真实可用的示例，不是"请输入明文" |
| AI 栏·空闲 | 上下文头 + chip：「这一步为什么这么做」「换了哪几个字节」「S 盒怎么查」 | 用问题代替"有任何问题可以问我" |
| 字节抽屉·无前序 | 「这是初始轮密钥加的结果。它的来源是轮密钥 w[5]。」+「看这 4 个字怎么来的」 | 空态也要给下一步 |
| 学习记录·空 | 「还没有记录。做一道练习题就会开始记。」+「去做第一题」 | 不说"暂无数据" |
| 错题本·空 | 「错题本是空的。这不是坏事。」+「去练习」 | 允许一句轻幽默，但只有一句 |
| 密钥扩展·无上下文 | 「先在工作台生成一组数据，这里会跟着当前轮走。」 | 说明联动关系 |
| S 盒·空查询 | 「输入一个字节，比如 0x53（十进制 83），看它正查和逆查分别是什么。」 | 给具体值 |

### 7.3 错误与异常提示

| 场景 | 文案 | 说明 |
|---|---|---|
| 长度非法 | 「现在是 28 位，AES-128 的明文需要 32 位（16 字节）。差 4 位。」 | 说清"差多少"，不只说"不合法" |
| 非十六进制 | 「第 9 个字符 'k' 不是十六进制。十六进制只有 0–9 和 a–f。」 | 定位到字符，并解释规则 |
| 含空格/换行 | 「已忽略其中的空格和换行。实际使用 32 位。」 | 自动修正后告知，不报错 |
| 超长 | 「当前版本只演示一个分组（16 字节），已用前 16 字节。后面 8 个字节还留在输入框里，没删。」 | 明确"没删"，消除数据丢失焦虑 |
| 换长度会重置 | 「换成 AES-192 会重新计算。当前停在第 13 步，换成后会回到第 0 步。」+「在新标签页打开」 | 给无损替代方案 |
| trace 失败 | 「计算没成功。可以重试，或者先用内置的标准向量看一遍流程。」 | 给两条出路，不让人卡死 |
| AI 首字慢 | 「还在生成。你可以等，也可以先看本地要点。」 | 给控制权，不做假进度 |
| AI 超时降级 | 「这次没连上模型，下面是离线的固定讲解。网络恢复后可以重问一遍。」 | 明确"这是降级"，不假装正常 |
| AI 通用讲解 | 「通用讲解（没有引用当前这一步的数值）」+「带上这一步的数据重问」 | 保持 PRD 的标注，并给升级路径 |
| 判分网络失败 | 「判分没提交成功。答案已保存在本机，网络恢复后会自动提交，不用重做。」 | 最关键的安抚：不用重做 |
| 题库失败 | 「题库暂时取不到，这是一道内置题。」 | 降级要说出来 |
| 导出失败 | 「导出没成功。数据还在，可以重试。」 | 不跳页 |
| 离线 | 「当前离线。内置向量仍可完整演示。」 | 说清"什么还能用" |
| 未登录要保存 | 「这条记录已经存在本机了。登录后可以跨设备看到。」 | **不说"请先登录"**，先说已经存下了（6.h） |

### 7.4 诊断反问（3 类误解各一条，示例可直接用）

| 误解类型 | 反问文案 | 设计说明 |
|---|---|---|
| 轮密钥时机 | 「你是不是在想：为什么第 1 轮开始之前也要先做一次轮密钥加？」 | 用"你是不是在想"而不是"你错了"，把判断权留给用户 |
| 列混合系数 | 「你是不是在困惑：列混合为什么会让一个字节扩散到一整行？你刚才来回看了几次这一步。」 | 引用他的行为（"来回看了几次"）来证明"我确实在看你的操作"，这是 D1 的说服力所在 |
| 密钥扩展方向 | 「你是不是在想：第 2 轮的轮密钥，是从上一轮的密钥算出来的，还是从主密钥重新算的？」 | 把误解写成"二选一"，比陈述句更容易被认领 |

反问的通用规则：
- 一次只问一个问题，不叠加。
- 结尾不加"要不要我讲讲？"（两个问句会稀释）。按钮承载这个意图。
- 三个按钮固定为「是，讲讲」「不是，继续看」「这提示不对」。

### 7.5 判分结果文案

| 状态 | 文案 | 说明 |
|---|---|---|
| 判对 | 「正确。你的列混合系数和异或都没出错。」 | 说清"对在哪"，才算真反馈 |
| 判对但不熟练 | 「正确。不过你在这一步停了 48 秒，可以再练一次把它变成肌肉记忆。」 | 用行为数据给建设性反馈 |
| 判错·第一层 | 「结果不对。差异出现在第 2 轮的操作里。」 | 不给位置，保留再试空间 |
| 判错·第二层 | 「第一次不一样：第 2 轮 列混合，字节 3。你的值是 0x7C，正确值是 0x63。」 | 给出可比对的两个值 |
| 判错·整段错 | 「从第 1 步的字节替代就出现差异了。后面 15 个字节都被这一处带偏，不是 16 个地方都错。」 | 归因修正，见 6.d |

| 错因标签 | 「同类错误出现 2 次了。可能是：列混合的系数用错了行。」+「练这一类」 | 有样本门槛（6.d 第 7 条） |
| 样本不足 | 「再做一道同类题，就能给你错因分析了。」 | 宁可不出结论 |

### 8.4 跨文档一致性口径表（唯一权威写法）

> 这份表是为"同一件事在四份文档里各写一遍"而建的。**凡与下表冲突的表述，一律以本表为准并回改。**
> 建立理由：本轮出现同一参数漂移多次（标记形状 4 次、`downstream` 边框 4 次），根因不是判断力，是**变更传播**——每方手上的"最新版"靠对话记忆维持。**四条使用约束**：
> ① 转述定稿级参数时必须**带着完整约束一起引**，不能只引结论（丢约束就必然改错）；
> ② 改判后**同一条消息通知全部下游**并写明"这覆盖了我 X 时说的 Y"；
> ③ **"见文档"不算交代**——跨文档依赖必须写清"哪个文件的哪一节、依赖的是哪个结论"，否则对方只能猜；
> ④ **同一参数出现在两处时必须写明"权威处"**：色值与视觉参数以《视觉设计规范》为准，行为与阈值以本文档为准；引用方标注"以 XX 为准"，不复制数值。
> ⑤ **本文档只引 token 名与关系，不引色值字面量**（v1.3 补）：写 `--ink-3`、`--line-hairline`、"降一级"、"加深一档"、"ΔL 0.06"，**不写 `oklch(...)` 字面量**。理由不是洁癖：色值一旦在两处各存一份，视觉改一档我这边就成第二个漂移源，而这轮所有事故都出在"同一参数两处各存一份"。演示档的字面量统一指向《视觉设计规范》§2.3.2。

| # | 事项 | 唯一正确写法 |
|---|---|---|
| 1 | 标记形状 | 诊断 **5px 圆** / 提问 **5px 方**，CSS 几何体；图例**复用同一 class**，禁止字形字符（`●`/`▪`） |
| 2 | 标记位置 | 标记轨上沿 y30–35 / 下沿 y41–46，分轨**不合并** |
| 3 | 图例 | 控制行右端共享槽位（约 188px）；时间轴聚焦时显示键盘提示；**常显态不进 Tab**，挂时间轴的 `aria-describedby`；`?` 按钮须 `aria-label` |
| 4 | z 序 | 标记轨内 标记 z3 > 游标 z2，**不做位移**（左偏会让标记看起来属于相邻步） |
| 5 | D 区高度 | 104 / 演示 136 / `max-height:780px` → 92；**任何断点不减少轨道条数** |
| 6 | 结构线 | **每格自己的 1px `border`，任何状态不得删除**。矩阵是 `--cell-gap: 6px` 的 16 个独立 chip，相邻格不接触，"共享边/双线"问题不存在；**"容器画线"方案已作废**（会在格间填出 6px 实色条带） |
| 7 | 边框通道 | **`border-width` 七态恒定 1px，只改 `border-color`**（改宽度会让内容位移 1px，而矩阵里位移会被读成"数值变了"）；需要厚度用 `box-shadow: inset`；owner 链 `error > selected > keyed > changed > downstream > idle` |
| 8 | `downstream` | 边框**降一级**（常规取 `--rule-region-ink` → hairline 档，宽度仍 1px；**实现走 `--st-downstream-border` 一层 token 间接**，这样演示档由 token 承担、组件里不写模式分支）+ 底色 `--surface-inset` + `--ink-3` 400 + **无角标**；演示态**边框不降**，安静感由底色**加深一档**（ΔL 0.06）+ **字重 400 对 700** 承担（投影会把"降一级"抹平成纸色，抹平后读作"没画完"） |
| 9 | `done` | **实线 + 左下 5px 缺口（压纸色方块实现，不是断边）**；无点阵、无虚线 |
| 10 | 线型语汇 | 虚线 = 未生效/待定/禁用；实线 = 已生效/确定；**点划线本版删除（0 用例）**。色阶（`--line-hairline`）不属于线型语汇，属颜色系统 |
| 11 | 整段错 | 1 格 `error` + 15 格 `downstream` + **只有四角括**（无完整外框、无虚线、无琥珀），标签「影响范围：16 字节」 |
| 12 | 四角分配 | 左上 reverse / 右上 changed / 右下 error / 左下 done；同格**最多 2 个**；截断顺序 `br > tl > tr > bl`（= 错误 > 反向 > 变化 > 完成）；任何角标不得进格心 |
| 13 | 判分期叠加 | `changed` **整体让位**（fill + corner 都不占）；`is-key` **保留**（`changed` 是 diff 信息可静音，`key` 是输入条件不可静音）；`error + selected` 必须**两者都表达**，机制是 **`error` 占底色 + 右下折角，`selected` 占 `border-color` + `inset` 内环 + `outline` 外环（**非颜色第二通道由外环承担**，环须离格边 2px、判分叠加时环色转近黑）**——**`selected` 一律不用四角刻线**（右下刻线臂会与 `error` 的 6px 折角同位置叠死，且四角是角标通道、不能再进第二个 owner）；判分叠加**绑定 `step_index`，离开该步即撤** |
| 14 | 容量与降级 | **DOM 元素数 = 规则上限**（角标 2 元素 / 16 格 = 32 节点，不是 4×16）；W2 末尾降级**只降动效，不降状态** |
| 15 | 角括与活动区刻线共存 | 全站**只有两种四角 L 形**：① 活动区刻线 = **矩阵容器外圈**、6px 臂、1px、**永不带标签**；② 范围角括 = **内缩 6px**、28px 臂、2px、**必带标签**「影响范围：16 字节」。刻线只有容器级这一个用例（单格不用刻线，见第 13 条），因此"两者同屏"只剩这一对，靠位置 / 长度 / 有无文字三通道区分。**验收**：「在工作台对照」页手动截图一次，确认不被读成同一个东西 |
| 16 | 标记热区 | **一步一个**：宽度 = 该步列宽（`width:100%` 落在列容器里，**不写死 12px**）、高度 20px、**上下两标记共用同一个 `<button>`**。**不得拆成两个**（"整列宽 × 20px × 2"是重合矩形，只有 z 高的点得到；劈成上下 10px 则两个都不满足 2.5.8 的 spacing）。Tab 序列只放**有标记的步**。**验收**：58 步下点第 13 步与第 14 步必须各自命中；同一步圆方并存时点一次能同时看到两类 |
| 17 | 图例 `aria-describedby` | 图例与键盘提示**两节点常驻 DOM**，槽位切换只换可见性；图例收起时用 **`.sr-only`**，**禁止 `display:none` / `visibility:hidden` / `hidden` 属性 / `aria-hidden`**（四者都会把节点摘出无障碍树，describedby 静默失效）。**验收**：聚焦时间轴后断言图例节点 `display !== 'none'` 且 `getBoundingClientRect().width > 0` |
| 18 | 判分期验收的测法 | **逐态实测"该态的身份通道是否还在"，不能只测被让位的那个态。** 典型漏测：验证 `changed` 让位时只确认"黄底没了"，却没人确认 `key` 的左边缘竖条还在——而"首次差异发生在轮密钥加"是必然场景，那里 `key` 是唯一还站着的通道。**三个必测点**：① 判分期 `key` 字节的左竖条存在（`is-key` 必须真的挂上 DOM，不是文档里写了）；② `error` 格的右下折角存在且不与任何外环重叠；③ `downstream` 格**没有**折角、没有 `≠`。测法：七态各截一张判分期截图 + DevTools 逐个断言 class / 属性，**不靠肉眼扫全屏**。**本条的由来**：本轮四条真错里有三条属于“文档说了、代码没做”（`is-key` 没挂上）或“单态对、组合态错”（刻线撞折角），只有一条是纯参数错——**前两类更值得留档，因为读需求的人会以为已经做了** |
| 19 | L 形符号的使用范围 | **字节格内禁止任何 L 形 / 四角刻线**（角标通道已被四个角占满，且 `error` 的右下折角与刻线右下臂同位置）。L 形只允许出现在**容器级**两处：矩阵活动区刻线（外圈、向外、6px）、B 区输入框 focus。`selected` 只用 `border-color` + `inset` + 外环。**验收**：DevTools 查 `.c-byte` 的 `::before` / `::after` 与 SVG `corners` 层，选中格与错误格都不应出现 L 形路径。**同条附则**：`selected` 的 `outline` **任何规则不得吃掉**（含 `outline: none` / `outline: 0` / `outline-color: transparent`）——它现在是选中态**唯一的形状通道**，一旦被吃掉就退化成纯颜色信号，而且不报错、控制台干净 | **逐态实测"该态的身份通道是否还在"，不能只测被让位的那个态。** 典型漏测：验证 `changed` 让位时只确认"黄底没了"，却没人确认 `key` 的左边缘竖条还在——而"首次差异发生在轮密钥加"是必然场景，那里 `key` 是唯一还站着的通道。**给定三个必测点**：① 判分期 `key` 字节的左竖条存在（`is-key` 必须真的挂上 DOM，不是文档里写了）；② `error` 格的右下折角存在且不与任何外环重叠；③ `downstream` 格**没有**折角、没有 `≠`。测法：对七态各截一张判分期截图 + 在 DevTools 里逐个断言 class / 属性，**不靠肉眼扫全屏** |

## 9. 附录：与视觉跨角色对齐结论（对齐后修订，v1.2）

> 视觉侧已按 UX-V1~V6 出 v1.1，逐条承接。以下是经评审后的**最终结论**，与第 4、5 节不一致处以此为准。

### 9.1 结论一：时间轴标记改为「上下列轨」，且形状承载语义

采纳视觉的"分轨不合并"方案，但**形状要承载真实语义差异**，不是随便挑两个形状。

> **本节形状与图例位置已在 v1.2 改判，以下 §2.4.2（5px 圆 / 5px 方）与 §2.4.3（控制行右端、共享槽位）为准**；本段保留 v1.1 的裁决记录与推理过程，便于回溯。

**产品裁决（v1.1 定稿）**：采纳上下分轨；transport 84→104（演示 136）；并追加一条硬要求——**分轨必须有一次图例说明，不许让用户靠猜**。图例的位置、显示条件、符号实现与读屏等价见 **§2.4.3**。

| | 诊断标记 | 提问标记 |
|---|---|---|
| 轨道位置 | 标记轨**上沿** | 标记轨**下沿** |
| 形状（v1.2 定稿） | **5px 实心圆** | **5px 实心方** |
| 语义映射 | 一个**时刻**（我在这一刻卡住了） | 一段**关注区间**（我关心过这一步） |
| 叠加 | 同一 x 上圆在上、方在下，**互不合并** | |

**理由**：4px 尺寸下"圆 vs 方"在 1m 观看距离 + 投影缩放下基本不可辨（视觉的判断正确）；挪到位置通道后形状只做辅助。**v1.2 撤回我当时提的"点 vs 横条"改法**：横条在 40+ 步时退化为 10×2px，会与正上方的 ② 刻度轨（1px×6 竖刻度）混读成"又一种刻度"；且横条的两个优势（宽度通道、语义对齐）已被"位置通道 + 图例"覆盖，只剩成本。故形状定稿 5px 圆 / 5px 方。**不合并的理由要记下**：合并后必须发明第三种符号来表达"两者都有"，任何答案都比"两个都在"更绕。

**成本核算（接受）**：标记轨 20px → D 区 104px，1280×720 下占视口 14.4%，可接受（C 区仍能容纳 4×72px 矩阵 + 标题 + 摘要句 + 密钥轨）。**附加约束**：`max-height: 780px` 时压缩到 92px（压轮号带与控制行），**任何断点下不得减少轨道条数**——轨道是这类控件的结构，压掉一条就丢一类信息。

**游标与标记的层级修正**：视觉原方案"被游标压住时标记左移 1px"，但 2px 游标 + 5px 标记左移 1px 后可见宽度是 2.5px/0.5px，严重不对称，等于一半贴着游标、一半悬空。改为：**标记轨内标记 z 高于游标**。游标位置已由游标行 + 步号文本表达，在标记轨内不需要再压住标记。

**键盘路径（我这边补的缺口）**：标记的可点击热区（该步整列宽 × 20px，一步一个）只服务鼠标。新增：

| 键 | 动作 |
|---|---|
| `[` | 跳到**上一个有标记的步**（同一步不重复停留） |
| `]` | 跳到**下一个有标记的步** |
| 聚焦标记时 | 播报"第 3 轮列混合，1 条系统推测、2 次提问，按回车打开标记详情"；`Enter` 打开 E 区标记详情卡 |

**v1.3 修：`[` / `]` 不再"诊断优先于提问"。** 那条规则是"一标记一热区"模型的产物——模型废掉之后，"优先"没有对象：一步只有一个停靠点，同一步里两类标记由卡的 `aria-label` 一起播报。**旧模型遗留的规则要跟着模型一起删，不能留着当"兼容"**，否则实现会去猜"同一步有 2 个诊断时谁优先"这种没有答案的问题。

**Tab 序列只放"有标记的步"**：58 步全部可聚焦会变成 58 个 Tab 站，等于把键盘用户堵在时间轴上。规则：热区只挂在**含 ≥1 个标记的步**上，无标记的步不进 Tab 序列（它们的可达性由滑块的 `←/→` 提供，步进本来就不需要单独的热区）。这样 Tab 站数量 = 有标记的步数，通常 <10。

**WCAG 2.5.8（目标尺寸 24×24）怎么交代**：58 步时列宽只有约 10px，热区宽度不可能达到 24px，这是**由数据密度决定的物理限制**，不是疏忽。走 **Equivalent 例外**：同一页面上存在达成同一功能的等价操作——① `[` / `]` 逐标记跳转（纯键盘、无尺寸限制）；② 时间轴滑块本身可 `←/→` 到任意步；③ E 区详情卡内的每一条标记自己可点可聚焦（尺寸 28px 高，达标）。**这三条任一都成立，因此不把按列热区判定为不合格**；但**三条都必须真的实现**，删掉任一条这个例外就失效——所以这条既是解释也是验收项。

### 9.2 结论二：三处新增非颜色通道——两处确认，第三处必须改

| 项 | 结论 | 说明 |
|---|---|---|
| 4.1 离线改 A 区 badge | ✅ 确认 | 但**必须带文字"离线"**，不能只有 `◌` 图标（图标会被当装饰）；且后面要跟一句"内置向量仍可完整演示"——离线是信任问题（我的数据存上了吗），不是状态装饰 |
| 4.5 输入不一致用 `⇄` 图标 | ✅ 确认 | 必须同时给文字标签「输入与题目不一致」。这正是 6.d 第 4 条要求的"从错误统计里剔除"在视觉上的落点 |
| 4.5 整段错用区域级红虚线框 | ❌ **改为四角括，且不保留任何完整外框** | 见下。**这一条比 v1.1 又进了一步**：v1.1 写的是"改为中性框"，产品裁决更进一步——连中性外框也不画，因为"围起来"这个动作本身带"这块有问题"的语气，中性色只解决了颜色，没解决动作 |

**为什么"整段错的红色区域框"必须改**：6.d 花了一整条去修一个归因错误——学生首步错导致 16 字节全变，他看到满屏红会认定"我全错了"，而事实是"你只错了 1 处"。给整个矩阵套一个**红色**框，等于用最强的大面积信号把"全错"这个错误认知重新装回去，把文案层的修正抵消掉。

**改为**：

| 元素 | 通道 | 说明 |
|---|---|---|
| 真正错的那 1 个字节 | 错误通道（红折角 + `≠` + 2px 边） | 唯一的错误语义承载点 |
| 其余 15 个受影响字节 | `downstream` 态：**去角标 + 边框降一级（`--line-hairline`，宽度仍 1px）+ 底色 `--surface-inset` + `--ink-3` 400**；演示态边框不降、改由底色 ΔL 0.06 + 字重 400 承担 | 表达"被带偏"，不表达"错"。**边框只降级不删除**：删掉就是塌洞（§4.9.6） |
| 矩阵范围 | **四角括（实线，不画完整外框）** + 标签「影响范围：16 字节」 | 表达"范围"，不表达"错误"。角括只说明"范围在这里"，不说明"这里好不好" |
| 判分结果条 | 可用错误样式 | 结果条说"不对"是准确的；矩阵说"全红"是不准确的 |

**原则沉淀**：「区域级通道只能表达范围/程度，不能表达对错。」这是本项目里容易反复犯的一类错。

### 9.3 结论三：不需要第三套间距，但密度归属要修正

| 页面 | 页面密度 | 例外 |
|---|---|---|
| 工作台 PG-2 | compact | — |
| 练习 PG-6 | roomy | 错因定位区块内嵌的小矩阵用 compact 的 `--cell-size` 桶（44/52/62/72） |
| 学习记录 PG-8 / 首页 PG-1 | roomy | 记录页的分布图区若含矩阵同练习 |
| **S 盒浏览器 PG-3** | **外壳 roomy，表格 compact** | 16×16 = 256 格必须紧凑；把整个 S 盒页判为 roomy 会导致表格放不下 |
| 单步训练 PG-7 | roomy | 其矩阵可用 compact 桶 |

**规则升级**（可写进设计系统）：**density 由页面容器定；嵌入的密集组件可单独覆盖 `--cell-size` 桶与 spacing，不新增全局 density 档。** 这样既避免第三套间距，又允许"宽松页面里嵌一个密集矩阵"这种真实场景。

### 9.4 由我这边拍板的三处小改（已通知视觉与前端）

| 编号 | 改动 | 理由 |
|---|---|---|
| X-1 | `--step-interval` 的 2× 档（400ms）下，C2 变化摘要句**不得有更新动效** | 每秒变 2.5 次文字，任何过渡都会糊成噪点。0.5× 档必须保留（读摘要句需要时间） |
| X-2 | 演示态矩阵格径需加"窄视口降档"（视觉原方案只有放大档 88px） | 1280 宽下若输入区展开 + AI 栏 360px，stage 约 700px，352px 矩阵够用；但教师把窗口缩到 1024 时需降到 72px 档，否则矩阵溢出 |
| X-3 | 动效归零不能只把时长设 0 | `stroke-dashoffset` 类动画在 `transition-duration: 0` 下可能停在中间值（描边留半截），必须同时 `animation: none` + `el.getAnimations().forEach(a => a.cancel())`。此条写入 8.2 给前端的接口清单 |

### 9.5 与视觉一致、无需再议的三条

1. **诊断行 40px 常驻占位**（无提示时留白 + 一行 11px `DIAGNOSTIC —`）。理由成立：禁止"出现时才插入"，否则会推动对话流产生位移——在阅读 AI 回答时发生位移是最破坏阅读的行为。
2. **AI 栏收起用"淡出换档"而非宽度过渡**。认可：`grid-template-columns` 过渡会导致 280ms 内每帧重排 16 个格，这正是性能红线；"淡出 120ms → 换栅格一帧 → 淡入 120ms"在 240ms 内完成，观感更快。
3. **取消"批注竖线 1.8s 循环生长"**。认可并升级为规则：**教室公用电脑上不允许任何无限循环动画**（持续占合成层 + 违反"批注必须静止"）。此规则已并入 5.5。
